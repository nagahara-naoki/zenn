## はじめに

JavaScript / TypeScript でクラスを使うと、次のようなコードをよく書きます。

```ts
class User {
  name: string

  constructor(name: string) {
    this.name = name
  }
}

const user = new User("Taro")
```

この `new User("Taro")` の `new` が、今回のテーマです。

`new` は一言でいうと、**関数やクラスから新しいオブジェクトを作るための演算子**です。

ただし、実際にはただオブジェクトを作っているだけではありません。

内部では、次のような処理をまとめて行っています。

```txt
1. 新しいオブジェクトを作る
2. そのオブジェクトと prototype をつなぐ
3. constructor を実行する
4. constructor 内の this に新しいオブジェクトを入れる
5. 完成したオブジェクトを返す
```

この記事では、`new` 演算子が何をしているのかを、できるだけ噛み砕いて説明します。

---

## `new` 演算子とは

`new` 演算子は、**コンストラクタ関数を使って新しいインスタンスを作るための構文**です。

```ts
const user = new User("Taro")
```

このコードでは、`User` というクラスから `user` というインスタンスを作っています。

```txt
User クラス
↓ new
user インスタンス
```

もう少し具体的に言うと、`new` は次のような役割を持っています。

```txt
クラスや関数をもとに、
新しいオブジェクトを作り、
初期化処理を実行して、
使える状態にして返す
```

---

## constructor との関係

`new` と `constructor` はセットで理解するとわかりやすいです。

```ts
class User {
  constructor(name: string) {
    this.name = name
  }
}

const user = new User("Taro")
```

このとき、`new User("Taro")` を実行すると、内部で `constructor("Taro")` が呼ばれます。

流れはこうです。

```txt
new User("Taro")
↓
新しいオブジェクトを作る
↓
constructor("Taro") を実行する
↓
this.name = "Taro" が実行される
↓
初期化済みの user が返る
```

つまり、`new` は **constructor を呼び出すための入口**とも言えます。

---

## `new` の内部処理

次のコードを見てみます。

```ts
class User {
  constructor(name: string) {
    this.name = name
  }
}

const user = new User("Taro")
```

この1行の裏側では、ざっくり次のような処理が行われています。

```txt
const user = new User("Taro")
```

```txt
1. 空のオブジェクトを作る
2. 作ったオブジェクトの [[Prototype]] を User.prototype にする
3. constructor を呼び出す
4. constructor 内の this に、作ったオブジェクトを入れる
5. this.name = "Taro" を実行する
6. 完成したオブジェクトを user に代入する
```

イメージとしては、次のようなことを自動でやってくれています。

```ts
const obj = {}

obj の prototype を User.prototype につなぐ

User の constructor を obj を this として実行する

obj.name = "Taro"

const user = obj
```

実際の JavaScript エンジン内部はもっと複雑ですが、まずはこのイメージで十分です。

---

## `this` は何を指すのか

`new` を理解するうえで重要なのが `this` です。

```ts
class User {
  constructor(name: string) {
    this.name = name
  }
}
```

この `this` は、**new によって作られた新しいオブジェクト**を指します。

```ts
const user = new User("Taro")
```

この場合、constructor の中の `this` は、最終的に `user` になるオブジェクトです。

つまり、

```ts
this.name = name
```

は、イメージとしては次の処理に近いです。

```ts
user.name = "Taro"
```

もちろん、実際には `user` という変数に代入される前に constructor が実行されます。

正確には、

```txt
まだ user という名前は付いていない
↓
new が新しいオブジェクトを作る
↓
そのオブジェクトを this として constructor を実行する
↓
処理が終わったあと user に代入される
```

という流れです。

---

## prototype との関係

`new` は、オブジェクトを作るだけではありません。

作ったオブジェクトを、コンストラクタの `prototype` とつなぎます。

```ts
class User {
  constructor(name: string) {
    this.name = name
  }

  greet() {
    console.log(`Hello, ${this.name}`)
  }
}

const user = new User("Taro")

user.greet()
```

このとき、`greet` メソッドは `user` 自身に直接入っているわけではありません。

内部イメージはこうです。

```txt
user
├─ name: "Taro"
└─ [[Prototype]] ──> User.prototype
                     ├─ constructor
                     └─ greet()
```

`new` によって、`user` の `[[Prototype]]` が `User.prototype` につながります。

そのため、`user.greet()` と書くと、JavaScript は次のように探します。

```txt
user に greet はある？
↓
ない
↓
User.prototype に greet はある？
↓
ある
↓
実行する
```

これが prototype チェーンです。

## 関数でも `new` は使える

JavaScript では、class だけでなく通常の関数にも `new` を使えます。

```js
function User(name) {
  this.name = name
}

const user = new User("Taro")

console.log(user.name) // Taro
```

この場合も流れは同じです。

```txt
1. 新しいオブジェクトを作る
2. User.prototype につなぐ
3. User を this 付きで実行する
4. this.name = "Taro" を実行する
5. オブジェクトを返す
```

もともと JavaScript のクラスは、関数と prototype を使った仕組みを、より書きやすくしたものです。

そのため、次の2つはかなり近い考え方です。

```js
function User(name) {
  this.name = name
}
```

```ts
class User {
  constructor(name) {
    this.name = name
  }
}
```

ただし、完全に同じではありません。

---

## class は `new` なしで呼べない

通常の関数は、`new` なしでも呼べます。

```js
function User(name) {
  this.name = name
}

User("Taro")
```

ただし、これは危険です。

`new` なしで呼ぶと、新しいオブジェクトが作られません。

そのため、`this` が意図しないものを指す可能性があります。

一方、class は `new` なしでは呼べません。

```ts
class User {
  constructor(name) {
    this.name = name
  }
}

User("Taro") // TypeError
```

class は、必ず `new` と一緒に使う必要があります。

これは、誤って普通の関数のように呼び出してしまうミスを防ぐためです。

---

## `new` されたときに返る値

基本的には、`new` で作られたオブジェクトが返ります。

```ts
class User {
  constructor(name) {
    this.name = name
  }
}

const user = new User("Taro")

console.log(user)
// User { name: "Taro" }
```

ただし、constructor の中で明示的にオブジェクトを `return` した場合は、そのオブジェクトが返ります。

```ts
class User {
  constructor(name) {
    this.name = name

    return {
      name: "Hanako"
    }
  }
}

const user = new User("Taro")

console.log(user.name) // Hanako
```

この場合、`this.name = "Taro"` で作られたオブジェクトではなく、`return` した別のオブジェクトが返ります。

ただし、constructor でプリミティブ値を返した場合は無視されます。

```ts
class User {
  constructor(name) {
    this.name = name

    return 100
  }
}

const user = new User("Taro")

console.log(user.name) // Taro
```

`100` はオブジェクトではないため、`new` で作られた元のオブジェクトがそのまま返ります。

ただし、constructor で明示的に別オブジェクトを返す書き方は、通常は避けたほうがよいです。

読み手が混乱しやすくなります。

---

## `new` できる関数とできない関数

すべての関数に `new` を使えるわけではありません。

たとえば、通常の関数は `new` できます。

```js
function User(name) {
  this.name = name
}

const user = new User("Taro")
```

一方、アロー関数は `new` できません。

```js
const User = (name) => {
  this.name = name
}

const user = new User("Taro") // TypeError
```

アロー関数は constructor として使うことを想定していないためです。

また、アロー関数は自分自身の `this` を持ちません。

そのため、`new` と相性が悪いです。

---

## `new` と配列・日付・Map

JavaScript では、組み込みオブジェクトを作るときにも `new` を使うことがあります。

```js
const date = new Date()
const map = new Map()
const set = new Set()
```

これらも考え方としては同じです。

```txt
Date という constructor から date オブジェクトを作る
Map という constructor から map オブジェクトを作る
Set という constructor から set オブジェクトを作る
```

ただし、組み込みオブジェクトは内部実装が特殊なものもあります。

そのため、自分で書く class と完全に同じ挙動だとは考えないほうがよいです。

---

## `new` と TypeScript

TypeScript でも `new` の考え方は同じです。

```ts
class User {
  constructor(public name: string) {}
}

const user = new User("Taro")
```

TypeScript では、constructor の引数に型を付けられます。

```ts
class User {
  name: string

  constructor(name: string) {
    this.name = name
  }
}
```

ただし、TypeScript の型情報は JavaScript に変換されると消えます。

```ts
constructor(name: string)
```

は、JavaScript では次のようになります。

```js
constructor(name)
```

つまり、`new` の実行時の仕組み自体は JavaScript のものです。

TypeScript は、開発時に型チェックをしてくれるだけです。

---

## `new` を使うメリット

`new` を使うメリットは、**同じ形のオブジェクトを簡単に作れること**です。

```ts
class User {
  constructor(name: string, age: number) {
    this.name = name
    this.age = age
  }
}

const user1 = new User("Taro", 20)
const user2 = new User("Hanako", 25)
const user3 = new User("Jiro", 30)
```

このように、同じ設計図から複数のオブジェクトを作れます。

```txt
User クラス
├─ user1
├─ user2
└─ user3
```

また、メソッドを `prototype` で共有できるため、各インスタンスごとに同じメソッドを持つ必要がありません。

```ts
class User {
  constructor(name: string) {
    this.name = name
  }

  greet() {
    console.log(`Hello, ${this.name}`)
  }
}
```

`greet` は各 user にコピーされるのではなく、`User.prototype` に置かれます。

## `new` の注意点

### 1. `new` を付け忘れない

関数constructorを使う場合、`new` を付け忘れると意図しない挙動になります。

```js
function User(name) {
  this.name = name
}

const user = User("Taro")
```

この場合、`user` には `undefined` が入ります。

```js
console.log(user) // undefined
```

なぜなら、`User` 関数は明示的に return していないからです。

class を使えば、`new` なしで呼んだ時点でエラーになるため、このミスを防ぎやすいです。

---

### 2. constructor に処理を書きすぎない

constructor は初期化処理を書く場所です。

しかし、重い処理を書きすぎると、インスタンスを作るだけで時間がかかります。

```ts
class User {
  constructor(name: string) {
    this.name = name

    // 重いAPI通信や複雑な処理などは避けたい
  }
}
```

constructor では、基本的に次のような処理に留めると扱いやすいです。

```txt
- プロパティの初期化
- 引数の受け取り
- 必要最低限の状態設定
```

API通信や重い処理は、別メソッドに分けたほうが読みやすくなります。

---

### 3. constructor の戻り値に頼らない

constructor で別のオブジェクトを return することはできます。

```ts
class User {
  constructor() {
    return { name: "Taro" }
  }
}
```

しかし、これは基本的には避けたほうがよいです。

理由は、`new User()` したのに `User` のインスタンスではない別オブジェクトが返る可能性があるからです。

```ts
const user = new User()

console.log(user instanceof User) // false になる可能性がある
```

constructor は「初期化する場所」として使い、戻り値で挙動を変えないほうが安全です。

---

## `new` を使わない作り方もある

JavaScript では、必ず `new` を使わなければいけないわけではありません。

オブジェクトリテラルで作ることもできます。

```ts
const user = {
  name: "Taro",
  age: 20
}
```

また、factory 関数で作ることもできます。

```ts
function createUser(name: string, age: number) {
  return {
    name,
    age
  }
}

const user = createUser("Taro", 20)
```

`new` を使うかどうかは、設計次第です。

ざっくり分けると、次のようになります。

| 作り方 | 向いているケース |
|---|---|
| オブジェクトリテラル | その場だけの単純なオブジェクト |
| factory 関数 | 柔軟にオブジェクトを作りたい場合 |
| class + new | 同じ型・振る舞いを持つインスタンスを複数作りたい場合 |

## `new` を自作してみる

理解を深めるために、`new` の動きを簡単に再現してみます。

```js
function myNew(Constructor, ...args) {
  const obj = {}

  Object.setPrototypeOf(obj, Constructor.prototype)

  const result = Constructor.apply(obj, args)

  if (result !== null && typeof result === "object") {
    return result
  }

  return obj
}
```

使い方はこうです。

```js
function User(name) {
  this.name = name
}

const user = myNew(User, "Taro")

console.log(user.name) // Taro
console.log(user instanceof User) // true
```

この `myNew` は、`new` の本質をかなり単純化したものです。

```txt
1. 空のオブジェクトを作る
2. prototype をつなぐ
3. constructor を this 付きで実行する
4. オブジェクトを返す
```

ただし、実際の `new` はもっと多くの仕様を扱います。

class、継承、組み込みオブジェクト、`new.target` なども関係するため、この実装は学習用のイメージです。

---

## `new.target` とは

constructor の中では、`new.target` という特殊な値を使えます。

```ts
class User {
  constructor() {
    console.log(new.target)
  }
}

new User()
```

この場合、`new.target` は `User` を指します。

`new.target` は、**どの constructor が new されたのか**を表します。

通常の関数でも使えます。

```js
function User(name) {
  if (!new.target) {
    throw new Error("new を付けて呼び出してください")
  }

  this.name = name
}

const user = new User("Taro")
```

`new.target` を使うと、`new` なしで呼ばれた場合にエラーにできます。

---

## `extends` と `new`

継承を使う場合、`new` の流れは少し複雑になります。

```ts
class Animal {
  constructor(name: string) {
    this.name = name
  }
}

class Dog extends Animal {
  constructor(name: string, breed: string) {
    super(name)
    this.breed = breed
  }
}

const dog = new Dog("Pochi", "Shiba")
```

この場合、流れはこうです。

```txt
new Dog("Pochi", "Shiba")
↓
Dog の constructor が呼ばれる
↓
super("Pochi") が呼ばれる
↓
Animal の constructor が実行される
↓
this.name = "Pochi"
↓
Dog 側で this.breed = "Shiba"
↓
dog が完成する
```

子クラスでは、`super()` を呼ぶ前に `this` を使えません。

```ts
class Dog extends Animal {
  constructor(name: string, breed: string) {
    this.breed = breed // エラー
    super(name)
  }
}
```

これは、親クラスの constructor が実行される前は、`this` がまだ使える状態になっていないためです。

## よくある誤解

### 誤解1: `new` はただ関数を呼んでいるだけ

実際には、ただの関数呼び出しではありません。

```js
User("Taro")
```

と

```js
new User("Taro")
```

は別物です。

`new` を付けると、新しいオブジェクトの作成、prototype の接続、this の設定が行われます。

---

### 誤解2: メソッドはインスタンスごとにコピーされる

class のメソッドは、基本的にインスタンスごとにコピーされません。

```ts
class User {
  greet() {
    console.log("hello")
  }
}
```

`greet` は `User.prototype` に置かれます。

```txt
user
└─ [[Prototype]] ──> User.prototype
                     └─ greet()
```

そのため、複数のインスタンスで同じメソッドを共有できます。

---

### 誤解3: constructor プロパティはインスタンス自身にある

次のように書けます。

```ts
user.constructor
```

しかし、多くの場合、`constructor` は `user` 自身にあるわけではありません。

`User.prototype.constructor` を prototype チェーン経由で見つけています。

```txt
user
↓
User.prototype
↓
constructor
```

## まとめ

`new` 演算子は、**クラスや関数から新しいオブジェクトを作るための演算子**です。

内部では、主に次の処理を行っています。

```txt
1. 新しいオブジェクトを作る
2. prototype をつなぐ
3. constructor を this 付きで実行する
4. 初期化されたオブジェクトを返す
```

つまり、

```ts
const user = new User("Taro")
```

は、単に `User` を呼び出しているだけではありません。

裏側では、

```txt
オブジェクト生成
↓
prototype 接続
↓
constructor 実行
↓
this に値をセット
↓
完成したインスタンスを返す
```

という流れが動いています。

`new` を理解すると、次のテーマもかなり見えやすくなります。

```txt
- constructor
- this
- prototype
- class
- extends / super
- インスタンス
```

JavaScript の class をしっかり理解するには、`new` の仕組みを知ることがとても大切です。
