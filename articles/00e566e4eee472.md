## `console.log` だけで終わらない、便利なデバッグパターン集

JavaScriptで開発をしていると、ほぼ必ず使うのが `console.log()` です。

```js
console.log("確認");
```

値の確認、処理の通過確認、APIレスポンスの確認など、デバッグではとても便利です。

ただし、`console` には `log` 以外にも便利なメソッドがたくさんあります。

たとえば、警告として表示する `console.warn()`、エラーとして表示する `console.error()`、表形式で表示できる `console.table()`、処理時間を測れる `console.time()` などがあります。

この記事では、JavaScriptの `console` の代表的な使い方を、実務で使いやすいパターンごとにまとめます。

---

# `console` とは

`console` とは、JavaScriptからブラウザの開発者ツールやNode.jsのターミナルに情報を出力するためのオブジェクトです。

ブラウザであれば、Chrome DevToolsなどの「Console」タブに出力されます。

```js
console.log("Hello Console");
```

実行すると、開発者ツール上に次のように表示されます。

```txt
Hello Console
```

主な用途は次の通りです。

* 変数の中身を確認する
* 関数が実行されているか確認する
* APIレスポンスを確認する
* 条件分岐の流れを確認する
* エラー原因を調査する
* 処理時間を測定する

`console` は、開発中の状態確認に非常に便利な道具です。

---

# 1. 基本の `console.log()`

もっともよく使うのが `console.log()` です。

```js
const name = "Taro";

console.log(name);
```

出力結果は次のようになります。

```txt
Taro
```

## 複数の値を出力する

`console.log()` には複数の値を渡せます。

```js
const name = "Taro";
const age = 25;

console.log(name, age);
```

```txt
Taro 25
```

実務では、値だけを出すよりも、ラベルを付けると見やすくなります。

```js
console.log("name:", name);
console.log("age:", age);
```

```txt
name: Taro
age: 25
```

値だけを出すと、あとで見たときに「これは何の値だっけ？」となりやすいです。

そのため、基本的にはラベル付きで出力するのがおすすめです。

---

# 2. オブジェクトを確認する

JavaScriptでは、オブジェクトの中身を確認したい場面が多くあります。

```js
const user = {
  id: 1,
  name: "Taro",
  age: 25,
};

console.log(user);
```

出力結果は次のようになります。

```txt
{ id: 1, name: "Taro", age: 25 }
```

オブジェクトの確認では、ラベルを付けて出すとわかりやすいです。

```js
console.log("user:", user);
```

---

# 3. 配列を確認する

配列の中身も `console.log()` で確認できます。

```js
const users = [
  { id: 1, name: "Taro" },
  { id: 2, name: "Hanako" },
  { id: 3, name: "Jiro" },
];

console.log(users);
```

ただし、配列の中身がオブジェクトの場合、少し見づらいことがあります。

そのような場合は、後で紹介する `console.table()` が便利です。

---

# 4. `console.warn()` で警告を出す

`console.warn()` は警告を表示するためのメソッドです。

```js
const stock = 0;

if (stock === 0) {
  console.warn("在庫がありません");
}
```

`console.log()` との違いは、開発者ツール上で警告として目立つ表示になることです。

通常のログよりも目立たせたいが、エラーではない場合に使います。

たとえば、次のような場面で便利です。

* 非推奨の処理を使っている
* 想定外に近い状態だが、処理は継続できる
* 注意して確認したい値がある

```js
if (!user.email) {
  console.warn("メールアドレスが未設定です", user);
}
```

---

# 5. `console.error()` でエラーを出す

`console.error()` はエラーを表示するためのメソッドです。

```js
try {
  throw new Error("APIエラーが発生しました");
} catch (error) {
  console.error(error);
}
```

`console.error()` を使うと、開発者ツール上でエラーとして表示されます。

```js
console.error("ユーザー情報の取得に失敗しました");
```

エラー時には、メッセージだけでなく関連する情報も一緒に出すと原因を追いやすくなります。

```js
console.error("ユーザー情報の取得に失敗しました", {
  userId: 1,
  endpoint: "/api/users/1",
});
```

エラー調査では「何が起きたか」だけではなく、「どの条件で起きたか」が重要です。

---

# 6. `console.info()` で情報を出す

`console.info()` は情報ログを出すためのメソッドです。

```js
console.info("アプリケーションを起動しました");
```

使い方は `console.log()` とほとんど同じです。

```js
console.info("ログイン成功", {
  userId: 1,
});
```

ただし、実務では `console.log()` と見た目が大きく変わらない環境も多いため、必須というよりはログの意味を分けたいときに使うイメージです。

---

# 7. `console.table()` で表形式にする

配列やオブジェクトの一覧を確認するときに便利なのが `console.table()` です。

```js
const users = [
  { id: 1, name: "Taro", age: 25 },
  { id: 2, name: "Hanako", age: 30 },
  { id: 3, name: "Jiro", age: 28 },
];

console.table(users);
```

通常の `console.log()` よりも、表形式で見やすく表示されます。

特に、APIから取得した一覧データを確認するときに便利です。

```js
fetch("/api/users")
  .then((response) => response.json())
  .then((users) => {
    console.table(users);
  });
```

## 特定のカラムだけ表示する

`console.table()` では、表示するカラムを指定できます。

```js
console.table(users, ["id", "name"]);
```

これにより、必要な項目だけを見やすく確認できます。

大量のデータを確認するときには、すべての項目を表示するよりも、必要なカラムだけに絞った方が見やすくなります。

---

# 8. `console.group()` でログをグループ化する

ログが増えてくると、どのログがどの処理のものなのか分かりにくくなります。

そのようなときは `console.group()` が便利です。

```js
console.group("ユーザー情報");

console.log("id:", 1);
console.log("name:", "Taro");
console.log("age:", 25);

console.groupEnd();
```

これにより、ログをグループとしてまとめられます。

## ネストもできる

`console.group()` は入れ子にできます。

```js
console.group("API処理");

console.log("リクエスト開始");

console.group("レスポンス");
console.log("status:", 200);
console.log("data:", { id: 1, name: "Taro" });
console.groupEnd();

console.log("リクエスト終了");

console.groupEnd();
```

処理の流れを整理して確認したいときに便利です。

---

# 9. `console.groupCollapsed()` で折りたたみ表示にする

`console.group()` は最初から開いた状態で表示されます。

一方で、`console.groupCollapsed()` は最初から折りたたまれた状態で表示されます。

```js
console.groupCollapsed("詳細ログ");

console.log("step1");
console.log("step2");
console.log("step3");

console.groupEnd();
```

大量のログを出したいけれど、普段は閉じておきたい場合に便利です。

たとえば、APIレスポンスの詳細やデバッグ用の補助情報などに向いています。

---

# 10. `console.time()` / `console.timeEnd()` で処理時間を測る

処理にどれくらい時間がかかっているか確認したい場合は、`console.time()` と `console.timeEnd()` を使います。

```js
console.time("loop");

for (let i = 0; i < 1000000; i++) {
  // 重い処理
}

console.timeEnd("loop");
```

出力例は次のようになります。

```txt
loop: 3.5ms
```

`console.time()` と `console.timeEnd()` には、同じラベルを指定します。

```js
console.time("API取得");

await fetch("/api/users");

console.timeEnd("API取得");
```

API取得、重いループ処理、描画処理の確認などに使えます。

---

# 11. `console.count()` で呼び出し回数を数える

`console.count()` は、特定の処理が何回実行されたかを数えるために使います。

```js
function greet() {
  console.count("greet called");
  console.log("Hello");
}

greet();
greet();
greet();
```

出力結果は次のようになります。

```txt
greet called: 1
Hello
greet called: 2
Hello
greet called: 3
Hello
```

関数が想定より多く呼ばれているかどうかを確認したいときに便利です。

たとえば、ReactやAngularなどで「なぜこの処理が何回も走るのか」を調べるときにも使えます。

---

# 12. `console.countReset()` でカウントをリセットする

`console.count()` のカウントは、`console.countReset()` でリセットできます。

```js
console.count("click");
console.count("click");
console.countReset("click");
console.count("click");
```

出力結果は次のようになります。

```txt
click: 1
click: 2
click: 1
```

特定のタイミングでカウントをリセットしたい場合に使えます。

---

# 13. `console.trace()` で呼び出し元を確認する

`console.trace()` は、どこからその処理が呼ばれたのかを確認するために使います。

```js
function first() {
  second();
}

function second() {
  third();
}

function third() {
  console.trace("呼び出し経路");
}

first();
```

`console.trace()` を使うと、関数がどの順番で呼ばれたかを確認できます。

これは、次のような場面で便利です。

* なぜこの関数が呼ばれているのか分からない
* どこから状態が変更されているのか調べたい
* 意図しないタイミングで処理が走っている

通常の `console.log()` では値しか確認できませんが、`console.trace()` を使うと呼び出し経路まで確認できます。

---

# 14. `console.assert()` で条件付きログを出す

`console.assert()` は、条件が false の場合だけログを出します。

```js
const age = 15;

console.assert(age >= 18, "18歳未満です");
```

この場合、`age >= 18` が false なのでログが出ます。

```txt
Assertion failed: 18歳未満です
```

条件が true の場合は何も出力されません。

```js
const age = 20;

console.assert(age >= 18, "18歳未満です");
```

これは、特定の条件を満たしているはず、という確認に使えます。

```js
console.assert(user.id !== undefined, "user.id が存在しません", user);
```

ただし、実務では `if` 文と `console.error()` を使った方が読みやすい場合も多いです。

---

# 15. `console.clear()` でコンソールをクリアする

`console.clear()` は、コンソールの表示をクリアします。

```js
console.clear();
```

ログが多くなりすぎたときに便利です。

ただし、開発中の調査ログまで消えてしまうため、使いすぎには注意が必要です。

---

# 16. `console.dir()` でオブジェクト構造を確認する

`console.dir()` は、オブジェクトのプロパティ構造を確認するときに使います。

```js
const user = {
  id: 1,
  name: "Taro",
};

console.dir(user);
```

DOM要素を確認するときにも便利です。

```js
const button = document.querySelector("button");

console.dir(button);
```

`console.log(button)` ではHTML要素として表示されることがありますが、`console.dir(button)` を使うとJavaScriptオブジェクトとしてのプロパティを確認しやすくなります。

---

# 17. `console.debug()` でデバッグ用ログを出す

`console.debug()` は、デバッグ用のログを出すためのメソッドです。

```js
console.debug("debug:", data);
```

使い方は `console.log()` とほぼ同じです。

ただし、ブラウザの設定によっては表示されない場合があります。

そのため、確実に表示したい場合は `console.log()` を使う方が分かりやすいです。

---

# 18. 実務でよく使うログの書き方

ここからは、実務で使いやすい `console` の書き方を紹介します。

## パターン1：ラベル付きで出す

```js
console.log("user:", user);
console.log("response:", response);
console.log("error:", error);
```

単に値だけを出すよりも、何の値かが分かりやすくなります。

悪い例です。

```js
console.log(user);
console.log(response);
console.log(error);
```

これだと、ログが増えたときに何の値か分かりにくくなります。

良い例です。

```js
console.log("ログインユーザー:", user);
console.log("APIレスポンス:", response);
console.log("エラー内容:", error);
```

---

## パターン2：処理の通過確認をする

処理が通っているか確認したい場合があります。

```js
console.log("ここまで来た");
```

ただし、実務ではもう少し具体的に書いた方がよいです。

```js
console.log("login処理開始");
console.log("APIリクエスト送信前");
console.log("APIレスポンス受信後");
console.log("login処理終了");
```

このように書くと、どこまで処理が進んでいるか分かりやすくなります。

---

## パターン3：条件分岐の確認をする

条件分岐が想定通りに動いているか確認したい場合です。

```js
if (user.isAdmin) {
  console.log("管理者ユーザーです");
} else {
  console.log("一般ユーザーです");
}
```

条件に使っている値も一緒に出すと、さらに分かりやすくなります。

```js
console.log("isAdmin:", user.isAdmin);

if (user.isAdmin) {
  console.log("管理者ユーザーです");
} else {
  console.log("一般ユーザーです");
}
```

---

## パターン4：APIレスポンスを確認する

API通信の確認では、リクエスト内容とレスポンス内容を分けて出すと見やすいです。

```js
console.group("ユーザー取得API");

console.log("request:", {
  endpoint: "/api/users/1",
  method: "GET",
});

const response = await fetch("/api/users/1");
const data = await response.json();

console.log("response:", data);

console.groupEnd();
```

APIの調査では、次の情報を出すと原因を追いやすくなります。

* endpoint
* method
* request body
* response
* status code
* error message

---

## パターン5：配列データは `console.table()` で見る

一覧データは `console.table()` が便利です。

```js
const products = [
  { id: 1, name: "Book", price: 1000 },
  { id: 2, name: "Pen", price: 200 },
  { id: 3, name: "Note", price: 500 },
];

console.table(products);
```

一覧データを `console.log()` だけで確認すると、データ量が多いと見づらくなります。

```js
console.log(products);
```

表形式にした方が、各項目を比較しやすくなります。

---

## パターン6：処理時間を測る

重そうな処理がある場合は、処理時間を測ります。

```js
console.time("filter処理");

const result = users.filter((user) => user.age >= 20);

console.timeEnd("filter処理");
```

パフォーマンス改善では、感覚ではなく数値で確認することが大切です。

---

## パターン7：何回呼ばれているか確認する

関数が何回呼ばれているか確認したい場合です。

```js
function render() {
  console.count("render");
}
```

想定より多く呼ばれている場合、不要な再描画や無駄な処理の原因を見つけるきっかけになります。

---

# 19. `console.log()` を使うときの注意点

`console.log()` は便利ですが、注意点もあります。

## 本番環境に残さない

開発中のログを本番環境に残すと、不要な情報がユーザーのブラウザに出てしまいます。

```js
console.log("debug:", user);
```

特に、次のような情報を出すのは危険です。

* 個人情報
* 認証情報
* トークン
* パスワード
* APIレスポンスの詳細
* 内部仕様が分かる情報

開発中は便利でも、本番環境では削除するか、ログ出力の仕組みを分けるべきです。

---

## ログを出しすぎない

ログが多すぎると、逆に重要な情報を見逃しやすくなります。

悪い例です。

```js
console.log("start");
console.log("data1", data1);
console.log("data2", data2);
console.log("data3", data3);
console.log("end");
```

ログが増えてきた場合は、`console.group()` でまとめたり、不要なログを削除したりすると見やすくなります。

```js
console.group("データ確認");

console.log("data1:", data1);
console.log("data2:", data2);
console.log("data3:", data3);

console.groupEnd();
```

---

## ログだけで解決しようとしない

`console.log()` は便利ですが、すべてをログだけで解決しようとすると大変です。

複雑な不具合では、ブラウザのDevToolsの機能も使うべきです。

たとえば、次のような機能があります。

* breakpoint
* step execution
* Networkタブ
* Performanceタブ
* Applicationタブ
* React Developer Tools
* Angular DevTools

`console` は便利な道具ですが、デバッグ手段のひとつとして使うのが大切です。

# まとめ

JavaScriptのデバッグでは `console.log()` を使うことが多いですが、`console` には他にも便利なメソッドがたくさんあります。

特に、実務で使いやすいのは次のあたりです。

* 基本確認には `console.log()`
* 警告には `console.warn()`
* エラーには `console.error()`
* 一覧データには `console.table()`
* 処理時間の確認には `console.time()` / `console.timeEnd()`
* 呼び出し回数の確認には `console.count()`
* 呼び出し元の確認には `console.trace()`
* ログ整理には `console.group()`

`console.log()` だけでもデバッグはできます。

しかし、用途に応じてメソッドを使い分けると、ログが見やすくなり、原因調査もしやすくなります。

開発中は、ただ値を出すだけではなく、「何を確認したいのか」に合わせて `console` を使い分けることが大切です。
