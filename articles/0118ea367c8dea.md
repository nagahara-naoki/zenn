## 「関数が外側の変数を覚えている」仕組みを理解する

JavaScriptを学んでいると、**クロージャ** という言葉が出てきます。

クロージャは、JavaScriptの中でも少し難しく感じやすいテーマです。

ただ、考え方自体はそこまで複雑ではありません。

まずは、次のように理解するとわかりやすいです。

> クロージャとは、関数が「自分が作られた場所の変数」を覚えている仕組み

もう少し実務寄りに言うと、クロージャを使うことで、**関数の外側にある変数を、関数の実行後も保持できる** ようになります。

この記事では、クロージャとは何か、なぜ値が残るのか、どのような場面で使うのかを順番に解説します。

---

# クロージャを理解する前に必要なこと

クロージャを理解するには、まずJavaScriptのスコープを軽く押さえる必要があります。

スコープとは、変数を参照できる範囲のことです。

```js
function greet() {
  const message = "こんにちは";

  console.log(message);
}

greet();
```

この場合、`message` は `greet` 関数の中で定義されています。

そのため、関数の外側からは参照できません。

```js
function greet() {
  const message = "こんにちは";
}

console.log(message);
```

これはエラーになります。

```txt
ReferenceError: message is not defined
```

`message` は `greet` 関数の中だけで有効な変数だからです。

---

# 関数の中から外側の変数は参照できる

JavaScriptでは、内側の関数から外側の変数を参照できます。

```js
function outer() {
  const message = "こんにちは";

  function inner() {
    console.log(message);
  }

  inner();
}

outer();
```

出力結果です。

```txt
こんにちは
```

`inner` 関数の中には `message` が定義されていません。

それでも `message` を使えています。

なぜなら、JavaScriptは内側のスコープに変数がなければ、外側のスコープを探しに行くからです。

この仕組みを **スコープチェーン** と呼びます。

---

# クロージャの基本形

では、クロージャの基本的な例を見てみます。

```js
function outer() {
  const message = "こんにちは";

  function inner() {
    console.log(message);
  }

  return inner;
}

const fn = outer();

fn();
```

出力結果です。

```txt
こんにちは
```

ここで重要なのは、`outer()` の実行はすでに終わっているという点です。

```js
const fn = outer();
```

この時点で `outer` 関数は実行され、`inner` 関数を返しています。

普通に考えると、`outer` の中で作られた `message` はもう消えていそうに見えます。

しかし、その後に `fn()` を実行すると、`message` を表示できます。

```js
fn();
```

つまり、`inner` 関数は、`outer` 関数の中にあった `message` を覚えているのです。

これがクロージャです。

---

# クロージャとは何か

クロージャとは、次のような状態のことです。

```js
function outer() {
  const count = 0;

  return function inner() {
    console.log(count);
  };
}
```

`inner` 関数は、外側の `outer` 関数の変数 `count` を参照しています。

そして、`outer` の実行が終わったあとも、`inner` は `count` を使い続けることができます。

つまり、クロージャとは、

> 関数と、その関数が作られたときの外側の変数環境がセットになったもの

です。

もっと簡単に言うと、

> 関数が外側の変数を覚えている状態

です。

---

# カウンターで理解するクロージャ

クロージャの代表例として、カウンターがあります。

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;

    return count;
  };
}

const counter = createCounter();

console.log(counter());
console.log(counter());
console.log(counter());
```

出力結果です。

```txt
1
2
3
```

`createCounter()` は最初に1回だけ実行されています。

```js
const counter = createCounter();
```

その後は、`counter()` を呼び出しています。

```js
counter();
counter();
counter();
```

ここで不思議なのは、`count` の値が毎回リセットされないことです。

```js
let count = 0;
```

もし毎回 `count` が作り直されるなら、出力はこうなるはずです。

```txt
1
1
1
```

しかし、実際には次のようになります。

```txt
1
2
3
```

これは、返された関数が `count` を覚えているからです。

この「覚えている」という性質がクロージャです。

---

# なぜ count は消えないのか

通常、関数の中で作られた変数は、関数の実行が終わると不要になります。

```js
function sample() {
  const value = 10;
}

sample();
```

この場合、`value` は `sample` 関数の中でしか使われません。

そのため、関数の実行が終われば、外から使うことはできません。

しかし、次の場合は違います。

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;

    return count;
  };
}

const counter = createCounter();
```

返された関数の中で `count` が使われています。

```js
return function () {
  count++;

  return count;
};
```

この関数が外側で使われ続ける限り、`count` も必要です。

そのため、JavaScriptは `count` を消さずに保持します。

つまり、クロージャでは、

> 外側の関数の実行が終わっても、内側の関数から参照されている変数は残る

ということです。

---

# クロージャは変数の「値」ではなく「変数そのもの」を覚える

ここは重要です。

クロージャは、変数の値をコピーして覚えているわけではありません。

変数そのものを参照しています。

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;

    console.log(count);
  };
}

const counter = createCounter();

counter();
counter();
counter();
```

出力結果です。

```txt
1
2
3
```

もし値だけをコピーしていたなら、毎回 `0` から始まるはずです。

しかし実際には、同じ `count` が更新され続けています。

つまり、クロージャは「作られた時点の値を固定して保存している」のではなく、**外側の変数への参照を保持している** と考えるとわかりやすいです。

---

# 複数のカウンターを作る

クロージャを使うと、それぞれ独立した状態を持つ関数を作れます。

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;

    return count;
  };
}

const counterA = createCounter();
const counterB = createCounter();

console.log(counterA());
console.log(counterA());
console.log(counterB());
console.log(counterB());
```

出力結果です。

```txt
1
2
1
2
```

`counterA` と `counterB` は、それぞれ別々の `count` を持っています。

```js
const counterA = createCounter();
const counterB = createCounter();
```

`createCounter()` を呼ぶたびに、新しい `count` が作られます。

そのため、`counterA` の `count` と `counterB` の `count` は別物です。

これは、クロージャを使った状態管理の基本的な考え方です。

---

# クロージャの使いどころ

クロージャは、実務でもさまざまな場面で使われます。

代表的な使いどころは次の通りです。

* 状態を保持したいとき
* 外から直接変更されたくない値を持ちたいとき
* 関数を作る関数を作りたいとき
* コールバック関数で外側の値を使いたいとき
* 一部の設定だけを固定した関数を作りたいとき

順番に見ていきます。

---

# 使いどころ1：状態を保持する

先ほどのカウンターのように、クロージャを使うと関数の中に状態を持たせられます。

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;

    return count;
  };
}

const counter = createCounter();

console.log(counter());
console.log(counter());
```

この `count` は外側から直接触れません。

```js
console.log(count);
```

これはエラーになります。

つまり、クロージャを使うと、関数の中だけで使う状態を安全に保持できます。

---

# 使いどころ2：プライベート変数のように使う

JavaScriptでは、クロージャを使ってプライベート変数のようなものを作れます。

```js
function createUser(name) {
  let loginCount = 0;

  return {
    getName() {
      return name;
    },
    login() {
      loginCount++;

      console.log(`${name}さんがログインしました`);
    },
    getLoginCount() {
      return loginCount;
    },
  };
}

const user = createUser("田中");

user.login();
user.login();

console.log(user.getName());
console.log(user.getLoginCount());
```

出力結果です。

```txt
田中さんがログインしました
田中さんがログインしました
田中
2
```

`loginCount` は `createUser` の中にあります。

そのため、外側から直接変更できません。

```js
user.loginCount = 100;
```

このように書いても、クロージャの中にある `loginCount` とは別物です。

外から直接書き換えられない値を持ちたい場合に、クロージャは便利です。

---

# 使いどころ3：設定を固定した関数を作る

クロージャを使うと、ある設定を固定した関数を作れます。

```js
function createMultiplier(multiplier) {
  return function (number) {
    return number * multiplier;
  };
}

const double = createMultiplier(2);
const triple = createMultiplier(3);

console.log(double(10));
console.log(triple(10));
```

出力結果です。

```txt
20
30
```

`double` は `multiplier` に `2` を覚えています。

`triple` は `multiplier` に `3` を覚えています。

このように、最初に渡した設定を覚えた関数を作ることができます。

---

# 使いどころ4：コールバックで外側の変数を使う

クロージャは、イベント処理や非同期処理でもよく使われます。

```js
function setupButton(button, message) {
  button.addEventListener("click", () => {
    console.log(message);
  });
}
```

このアロー関数は、外側の `message` を使っています。

```js
() => {
  console.log(message);
}
```

`setupButton` の実行が終わったあとでも、ボタンがクリックされれば `message` を表示できます。

これもクロージャです。

イベント処理では、クロージャを意識しなくても自然に使っていることが多いです。

---

# 使いどころ5：一度だけ実行する処理を作る

クロージャを使うと、「一度だけ実行できる関数」を作れます。

```js
function once(callback) {
  let called = false;

  return function () {
    if (called) {
      return;
    }

    called = true;
    callback();
  };
}

const initialize = once(() => {
  console.log("初期化しました");
});

initialize();
initialize();
initialize();
```

出力結果です。

```txt
初期化しました
```

`called` はクロージャによって保持されています。

一度 `true` になると、次回以降は `callback()` が実行されません。

このような制御にもクロージャは使えます。

---

# よくあるつまずき：ループとクロージャ

クロージャでよくあるつまずきが、ループ内で関数を作るケースです。

```js
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);
  }, 1000);
}
```

出力結果は、次のようになります。

```txt
3
3
3
```

`0, 1, 2` になりそうですが、実際には `3, 3, 3` です。

理由は、`var` が関数スコープを持つためです。

3つの関数が、同じ `i` を参照しています。

そして、`setTimeout` が実行される頃には、ループは終わって `i` は `3` になっています。

---

# `let` を使うと解決できる

現在のJavaScriptでは、`let` を使うことでこの問題を避けられます。

```js
for (let i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);
  }, 1000);
}
```

出力結果です。

```txt
0
1
2
```

`let` はブロックスコープを持ちます。

そのため、ループごとに別々の `i` が作られます。

結果として、それぞれの関数が別々の `i` を覚えます。

---

# 昔は即時関数で解決していた

`let` がなかった時代は、即時関数を使って値を閉じ込めていました。

```js
for (var i = 0; i < 3; i++) {
  (function (currentIndex) {
    setTimeout(function () {
      console.log(currentIndex);
    }, 1000);
  })(i);
}
```

出力結果です。

```txt
0
1
2
```

即時関数に `i` を渡して、`currentIndex` として保持しています。

この `currentIndex` がクロージャによって残るため、正しい値が表示されます。

現在は `let` を使えばよい場面が多いですが、古いコードを読むときにはこのパターンを見かけることがあります。

---

# クロージャとメモリ

クロージャでは、外側の変数が保持されます。

これは便利ですが、不要になった変数まで保持し続けると、メモリを使い続ける可能性があります。

```js
function createLargeDataHandler() {
  const largeData = new Array(1000000).fill("data");

  return function () {
    console.log(largeData.length);
  };
}

const handler = createLargeDataHandler();
```

`handler` が存在している限り、`largeData` も参照され続けます。

そのため、JavaScriptは `largeData` を不要なものとして片付けられません。

小さなデータではほとんど問題になりませんが、大きなデータや長く残るイベントリスナーでは注意が必要です。

---

# クロージャが嫌われることがある理由

クロージャは便利ですが、嫌われることもあります。

理由は、主に次の3つです。

## 1. どこで値が保持されているのか分かりにくい

クロージャでは、関数の実行が終わったあとも変数が残ります。

これは便利な反面、慣れていないと「なぜこの値が残っているのか」が分かりにくくなります。

```js
const counter = createCounter();

counter();
counter();
```

この `counter` の中に `count` が隠れているため、コードを読む側は内部状態を意識する必要があります。

## 2. 状態が見えづらい

クロージャで保持される値は、外から直接見えません。

これは安全でもありますが、デバッグしにくい場合があります。

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}
```

`count` がどこで増えているのか、どの関数が持っているのかを追う必要があります。

## 3. メモリを保持し続ける可能性がある

クロージャは外側の変数を保持します。

そのため、不要になったデータを参照し続けると、メモリが解放されにくくなる可能性があります。

特に、イベントリスナーや長く生きるオブジェクトで大きなデータを閉じ込める場合は注意が必要です。

---

# クロージャを使うときの注意点

クロージャを使うときは、次の点を意識すると安全です。

## 状態を持たせすぎない

クロージャに大量の状態を持たせると、コードの見通しが悪くなります。

```js
function createSomething() {
  let a = 1;
  let b = 2;
  let c = 3;
  let d = 4;

  return function () {
    // 多くの状態を使う
  };
}
```

状態が増える場合は、オブジェクトやクラス、状態管理の仕組みに分けた方が読みやすいことがあります。

## 何を覚えている関数なのか名前で表す

クロージャを使う関数は、名前が重要です。

```js
const double = createMultiplier(2);
const triple = createMultiplier(3);
```

このように、何を固定している関数なのかが名前からわかると読みやすくなります。

## 不要になった参照を残さない

イベントリスナーなどでクロージャを使う場合、不要になったら解除することも大切です。

```js
function handleClick() {
  console.log("clicked");
}

button.addEventListener("click", handleClick);

// 不要になったら解除
button.removeEventListener("click", handleClick);
```

長く残るイベントリスナーは、外側の変数も保持し続ける可能性があります。

---

# ReactやAngularでもクロージャは使われている

クロージャは、ReactやAngularなどのフレームワークでも自然に使われています。

たとえば、Reactのイベントハンドラでは、外側の変数を参照することがよくあります。

```js
function UserButton({ user }) {
  const handleClick = () => {
    console.log(user.name);
  };

  return <button onClick={handleClick}>表示</button>;
}
```

`handleClick` は、外側にある `user` を参照しています。

これもクロージャです。

Angularでも、コンポーネント内で定義した関数やコールバックが外側の変数を参照する場面があります。

```js
const userId = 1;

this.userService.getUser(userId).subscribe((user) => {
  console.log(userId);
  console.log(user);
});
```

`subscribe` に渡した関数は、外側の `userId` を参照しています。

これもクロージャの一例です。

---

# クロージャを一言で説明すると

クロージャを一言で説明すると、次のようになります。

> クロージャとは、関数が作られたときの外側の変数を覚えていて、あとから使える仕組み

ポイントは、次の3つです。

* 関数の中で外側の変数を使える
* 外側の関数の実行が終わっても、その変数が残ることがある
* 関数がその変数への参照を保持している

特に重要なのは、クロージャが「値のコピー」ではなく、「変数への参照」を保持しているという点です。

---

# まとめ

クロージャは、JavaScriptの重要な仕組みのひとつです。

最初は難しく感じるかもしれませんが、基本はシンプルです。

> 関数が外側の変数を覚えている

これがクロージャの中心です。

クロージャを使うと、次のようなことができます。

* 関数の中に状態を保持できる
* 外から直接変更できない値を作れる
* 設定を固定した関数を作れる
* コールバック関数で外側の値を使える
* 一度だけ実行する関数を作れる

一方で、クロージャには注意点もあります。

* 状態が見えづらくなる
* 値がどこで保持されているか分かりにくい
* 不要な参照が残るとメモリを使い続ける可能性がある

クロージャは、特別な構文ではありません。

JavaScriptの関数とスコープの仕組みから自然に生まれるものです。

そのため、クロージャを理解すると、関数、スコープ、コールバック、非同期処理、ReactやAngularのコードも読みやすくなります。

まずは、次のカウンターの例をしっかり理解するところから始めるとよいです。

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;

    return count;
  };
}

const counter = createCounter();

console.log(counter());
console.log(counter());
console.log(counter());
```

この `count` がなぜ残り続けるのかを説明できるようになれば、クロージャの基本はかなり理解できています。
