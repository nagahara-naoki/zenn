クロージャとは、関数と、その関数が定義されたレキシカル環境の組み合わせです。

よく「関数が外側の変数を覚えている」と説明されます。入口としては分かりやすい一方、覚えているのは値のコピーではなく、変数を解決するための環境だと理解することが重要です。

## 最小例

```js
function createCounter() {
  let count = 0;

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();

console.log(counter()); // 1
console.log(counter()); // 2
```

`createCounter()` の実行は終わっています。それでも返された `increment` が `count` を参照しているため、その環境は必要な間保持されます。

```text
counter
  └─ increment関数
       └─ 外側の環境
            └─ count: 2
```

## 値ではなく変数への参照

```js
function createReader() {
  let message = "before";

  const read = () => message;
  message = "after";

  return read;
}

const read = createReader();
console.log(read()); // after
```

`read` を作った時点の文字列 `"before"` がコピーされたわけではありません。`message` という束縛を参照しているため、後から更新された値が返ります。

## 呼び出しごとに別の環境ができる

```js
const counterA = createCounter();
const counterB = createCounter();

console.log(counterA()); // 1
console.log(counterA()); // 2
console.log(counterB()); // 1
```

`createCounter` を呼ぶたびに、新しい `count` の束縛が作られます。2つのcounterは状態を共有しません。

## 実務での使いどころ

### 設定済みの関数を作る

```js
function createTaxCalculator(rate) {
  return (price) => Math.round(price * (1 + rate));
}

const calculateWithTax = createTaxCalculator(0.1);

console.log(calculateWithTax(1_000)); // 1100
```

`rate` を毎回渡す必要がなく、どの税率で計算する関数かを生成時に決められます。

### 内部状態を隠す

```js
function createTodoStore() {
  const todos = [];

  return {
    add(title) {
      todos.push({ title, completed: false });
    },
    list() {
      return todos.map((todo) => ({ ...todo }));
    },
  };
}
```

`todos` は外から直接変更できず、公開した操作を通して扱えます。

ただし、閉じ込めれば常に良い設計になるわけではありません。状態の更新経路が多い場合は、classや明示的なstoreの方が追いやすいことがあります。

### コールバックで周辺情報を使う

```js
function registerButton(button, userId) {
  button.addEventListener("click", () => {
    sendAnalytics({ event: "button_click", userId });
  });
}
```

event listenerは、登録時の `userId` をクロージャ経由で参照します。

## ループとクロージャ

`var` はblock scopeではなくfunction scopeなので、ループ後に同じ `i` を参照する問題が起きます。

```js
const callbacks = [];

for (var i = 0; i < 3; i += 1) {
  callbacks.push(() => i);
}

console.log(callbacks.map((callback) => callback())); // [3, 3, 3]
```

`let` を使うforループでは、反復ごとに新しいbindingが作られます。

```js
const callbacks = [];

for (let i = 0; i < 3; i += 1) {
  callbacks.push(() => i);
}

console.log(callbacks.map((callback) => callback())); // [0, 1, 2]
```

現代のコードで、ループ変数を閉じ込めるためだけにIIFEを使う必要はほとんどありません。

## 非同期処理と「古い値」

クロージャが参照するbindingと、処理開始時に明示的にコピーした値は区別します。

```js
let query = "javascript";

async function search() {
  const requestedQuery = query;
  const result = await fetchResults(requestedQuery);

  if (query !== requestedQuery) {
    return; // 入力が変わったため古い結果を採用しない
  }

  render(result);
}
```

`requestedQuery` は各 `search()` 呼び出しに固有です。一方、外側の `query` は後から変わる可能性があります。

UIフレームワークで「stale closure」と呼ばれる問題も、コールバックがどのレンダー・どのbindingを閉じ込めたかを追うと理解しやすくなります。フレームワーク固有の更新規則もあるため、単に「クロージャは古い値を覚える」と一般化しないようにします。

## メモリとの関係

クロージャがあるだけでメモリリークになるわけではありません。関数が到達可能で、その関数から外側の値へ参照が続く間は、必要な値も回収されません。

```js
function registerPreview(button, largeData) {
  const handleClick = () => {
    showPreview(largeData);
  };

  button.addEventListener("click", handleClick);

  return () => {
    button.removeEventListener("click", handleClick);
  };
}
```

長寿命のevent listenerやtimerが大きなデータを参照するときは、解除方法を用意します。

確認するポイントは次の通りです。

- listenerやsubscriptionを解除できるか
- timerを停止できるか
- cacheへ無制限に関数を残していないか
- 必要以上に大きなオブジェクトを参照していないか

## クロージャが読みにくくなる兆候

- 1つの関数が多数の外部変数を暗黙に参照する
- 状態の変更箇所が複数のネスト関数へ散らばる
- 関数名から保持している状態が分からない
- 生成と破棄のタイミングが不明

必要な値を引数へ変える、状態と操作をオブジェクトへまとめる、関数を小さく分ける、といった方法を検討します。

## まとめ

- クロージャは関数とレキシカル環境の組み合わせ
- 外側の値のコピーではなく、bindingを解決する環境を参照する
- 外側の関数を呼ぶたびに別の環境を作れる
- 設定済み関数、状態のカプセル化、コールバックで役立つ
- 長寿命のlistenerやtimerでは、参照の寿命と解除を意識する

「何を覚えたか」よりも、「この関数はどのスコープのどのbindingを参照しているか」を追うと、クロージャを正確に読めます。
