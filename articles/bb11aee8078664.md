JavaScriptのオブジェクトは、別のオブジェクトを参照する内部リンク `[[Prototype]]` を持てます。

自分自身にプロパティがなければ、そのリンクをたどって探します。この仕組みがprototype chainです。

## 最小例

```js
const animal = {
  eat() {
    return "食べる";
  },
};

const dog = Object.create(animal);
dog.name = "Pochi";

console.log(dog.name);  // Pochi
console.log(dog.eat()); // 食べる
```

`dog` 自身には `eat` がありません。それでも呼び出せるのは、`dog` の `[[Prototype]]` が `animal` を参照しているからです。

```text
dog
├─ name: "Pochi"
└─ [[Prototype]] ──> animal
                     └─ eat()
```

確認には `Object.getPrototypeOf` を使います。

```js
console.log(Object.getPrototypeOf(dog) === animal); // true
```

## prototypeと[[Prototype]]は別物

名前が似ていますが、役割が異なります。

- `User.prototype`：コンストラクター関数が持つ通常のプロパティ
- `user` の `[[Prototype]]`：オブジェクト内部の参照

```js
function User(name) {
  this.name = name;
}

User.prototype.greet = function () {
  return `Hello, ${this.name}`;
};

const user = new User("Taro");

console.log(Object.getPrototypeOf(user) === User.prototype); // true
```

`new User()` は、新しいオブジェクトの `[[Prototype]]` を基本的に `User.prototype` へ接続します。

`__proto__` は歴史的なアクセサーです。学習用に見かけることはありますが、操作には `Object.getPrototypeOf`、`Object.setPrototypeOf`、`Object.create` を使います。

## classとの関係

`class` 構文を使っても、メソッド共有にはprototypeが使われます。

```js
class User {
  constructor(name) {
    this.name = name;
  }

  greet() {
    return `Hello, ${this.name}`;
  }
}

const a = new User("Taro");
const b = new User("Hanako");

console.log(a.greet === b.greet); // true
console.log(a.greet === User.prototype.greet); // true
```

`name` は各インスタンスが持ち、`greet` は `User.prototype` に1つだけあります。

```text
a                         b
├─ name: "Taro"           ├─ name: "Hanako"
└─ [[Prototype]] ─┐       └─ [[Prototype]] ─┐
                  └─> User.prototype <──────┘
                      └─ greet()
```

クラスフィールドへアロー関数を代入すると、通常はインスタンスごとに関数が作られます。

```js
class User {
  greet = () => "Hello";
}

const a = new User();
const b = new User();

console.log(a.greet === b.greet); // false
```

この書き方は `this` を保ったままコールバックへ渡しやすい一方、prototypeメソッドとは配置と生成コストが異なります。

## プロパティ探索の流れ

```js
console.log(user.greet);
```

概念的には、次の順に探します。

1. `user` 自身に `greet` があるか
2. `User.prototype` にあるか
3. `Object.prototype` にあるか
4. `null` へ到達したら見つからない

手前に同名プロパティがあれば、奥のプロパティを隠します。

```js
const base = { role: "base" };
const child = Object.create(base);

child.role = "child";

console.log(child.role); // child
delete child.role;
console.log(child.role); // base
```

## 自身のプロパティか確認する

`in` はprototype chain全体を確認します。

```js
console.log("greet" in user); // true
```

`Object.hasOwn` は、そのオブジェクト自身だけを確認します。

```js
console.log(Object.hasOwn(user, "name"));  // true
console.log(Object.hasOwn(user, "greet")); // false
```

外部入力から作ったオブジェクトを扱う場合、継承プロパティまで含めるべきかを意識して選びます。

## 継承

`extends` は、インスタンス側とクラス側の両方へprototype chainを作ります。

```js
class Animal {
  eat() {
    return "eat";
  }
}

class Dog extends Animal {
  bark() {
    return "bow";
  }
}

const dog = new Dog();

console.log(dog.bark());
console.log(dog.eat());
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype); // true
```

`Dog.prototype` から `Animal.prototype` をたどれるため、`dog.eat()` を呼べます。

## constructorプロパティ

通常、関数の `prototype` には `constructor` プロパティがあります。

```js
console.log(User.prototype.constructor === User); // true
console.log(user.constructor === User); // true
```

`user.constructor` は多くの場合prototype chain経由で見つかります。ただし書き換え可能であり、型判定の絶対的な根拠にはできません。

```js
console.log(user instanceof User);
```

`instanceof` も、右辺の `prototype` が左辺のprototype chainに存在するかを基本として判定します。別realmのオブジェクトなどでは期待と異なることがあるため、用途に応じて判定方法を選びます。

## prototypeを後から変えるときの注意

既存オブジェクトのprototypeを動的に変更すると、コードを追いにくくし、JavaScriptエンジンの最適化にも不利になり得ます。

組み込みオブジェクトのprototypeへ独自メソッドを追加することも避けます。将来の標準機能との衝突や、他ライブラリへの影響があるためです。

通常は、生成時に `class` や `Object.create` で関係を決めます。

## まとめ

- オブジェクトは `[[Prototype]]` で別オブジェクトを参照できる
- 見つからないプロパティはprototype chainをたどって探す
- `User.prototype` とインスタンスの `[[Prototype]]` は別の概念
- classの通常メソッドもprototypeに置かれる
- 自身のプロパティ確認には `Object.hasOwn` を使える
- 実行中のprototype変更や組み込みprototypeの拡張は避ける

prototypeを「継承の古い書き方」ではなく、JavaScriptのプロパティ探索そのものとして理解すると、classや `new` の挙動も説明しやすくなります。
