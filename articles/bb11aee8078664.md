JavaScriptの`prototype`は、`constructor`や`new`を理解するときに必ず出てくる重要な仕組みです。

ただ、最初は次のような用語が一気に出てくるため、かなり混乱しやすいです。

```js
User.prototype
user.__proto__
Object.getPrototypeOf(user)
prototype chain
constructor property
```

しかし、`prototype`の本質はシンプルです。

一言でいうと、`prototype`とは **オブジェクトがプロパティやメソッドを探しに行く参照先** です。

もう少し実務的に言うと、**複数のインスタンスでメソッドを共有するための仕組み** です。

この記事では、`constructor`、`new`、`class`との関係から、`prototype`をわかりやすく整理します。

---

## この記事でわかること

この記事では、次の内容を説明します。

- `prototype`とは何か
- `User.prototype`とは何か
- インスタンスと`prototype`の関係
- `constructor`プロパティの正体
- `prototype chain`とは何か
- `class`と`prototype`の関係
- `__proto__`と`Object.getPrototypeOf`の違い
- `prototype`を理解すると何が嬉しいのか

## まずprototypeとは何か

`prototype`とは、オブジェクトがプロパティやメソッドを探しに行くための参照先です。

次のコードを見てください。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
const user = new User('Taro')
user.greet()
```

このコードでは、`user.greet()`を呼び出しています。

では、`greet`は`user`自身の中に入っているのでしょうか？

確認してみます。

```js
console.log(user.hasOwnProperty('name'))
// true
console.log(user.hasOwnProperty('greet'))
// false
```

`name`は`user`自身が持っています。

しかし、`greet`は`user`自身のプロパティではありません。

では、どこにあるのか。

答えは、`User.prototype`です。

```js
console.log(User.prototype.hasOwnProperty('greet'))
// true
```

つまり、関係は次のようになります。

```txt
user
├─ name: "Taro"
└─ [[Prototype]] ──> User.prototype
                    ├─ constructor
                    └─ greet
```

`user.greet()`を実行したとき、JavaScriptは次のように探します。

```txt
user自身にgreetはある？
↓
ない
↓
userの参照先であるUser.prototypeを見る
↓
User.prototypeにgreetがある
↓
それを実行する
```

これが`prototype`の基本です。

---

## prototypeはメソッドの共有場所

`prototype`は、インスタンス同士で共有したいメソッドを置く場所です。

たとえば、次のように複数のインスタンスを作ります。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
const user1 = new User('Taro')
const user2 = new User('Hanako')
```

`user1`と`user2`は別々のオブジェクトです。

```txt
user1
└─ name: "Taro"
user2
└─ name: "Hanako"
```

しかし、`greet`メソッドはそれぞれのインスタンスにコピーされているわけではありません。

```txt
user1 ─┐
       ├─> User.prototype.greet
user2 ─┘
```

`greet`は`User.prototype`に1つだけ存在し、複数のインスタンスから共有されます。

これが`prototype`の大きな役割です。

---

## なぜprototypeが必要なのか

もし、インスタンスごとに同じメソッドを持たせるとどうなるでしょうか。

```js
function createUser(name) {
  return {
    name,
    greet() {
      console.log(`こんにちは、${this.name}です`)
    }
  }
}
const user1 = createUser('Taro')
const user2 = createUser('Hanako')
```

この場合、`user1`と`user2`はそれぞれ別の`greet`関数を持ちます。

```txt
user1
├─ name: "Taro"
└─ greet: function
user2
├─ name: "Hanako"
└─ greet: function
```

小さなコードなら問題ありません。

しかし、大量のオブジェクトを作る場合、同じ処理の関数を何度も作ることになります。

そこで、共通メソッドを`prototype`に置いて共有します。

```txt
user1
└─ name: "Taro"
   ↓
   User.prototype.greet
user2
└─ name: "Hanako"
   ↓
   User.prototype.greet
```

これにより、無駄な関数の複製を避けられます。

## constructorとprototypeの関係

次のクラスを見てください。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
```

この`User`には、内部的に次のような関係があります。

```txt
User
└─ prototype ──> User.prototype
                 ├─ constructor ──> User
                 └─ greet
```

`User.prototype`の中には、`constructor`というプロパティがあります。

確認してみます。

```js
console.log(User.prototype.constructor === User)
// true
```

`User.prototype.constructor`は、元の`User`を指しています。

そのため、インスタンスからも次のように見えます。

```js
const user = new User('Taro')
console.log(user.constructor === User)
// true
```

ただし、重要なのはここです。

`user`自身が`constructor`を持っているわけではありません。

```js
console.log(user.hasOwnProperty('constructor'))
// false
```

`user.constructor`は、prototypeをたどって見つかっています。

```txt
user.constructorを探す
↓
user自身にはない
↓
User.prototypeを見る
↓
User.prototype.constructorがある
↓
Userを返す
```

つまり、`constructor`プロパティは、多くの場合インスタンス自身ではなく`prototype`側にあります。

---

## newされたときにprototypeがつながる

`prototype`は、`new`演算子と深く関係しています。

```js
const user = new User('Taro')
```

このとき内部では、ざっくり次のような処理が行われます。

```txt
1. 新しい空のオブジェクトを作る
2. そのオブジェクトの参照先をUser.prototypeにする
3. constructorを実行する
4. this.name = 'Taro'で値を入れる
5. 完成したオブジェクトを返す
```

つまり、`new User()`で作られたインスタンスは、`User.prototype`につながります。

```txt
user
├─ name: "Taro"
└─ [[Prototype]] ──> User.prototype
```

このつながりを確認するには、`Object.getPrototypeOf`を使います。

```js
console.log(Object.getPrototypeOf(user) === User.prototype)
// true
```

`new`は、単にconstructorを呼ぶだけではありません。

作成したオブジェクトと`constructor.prototype`をつなぐ役割も持っています。

---

## prototypeと[[Prototype]]は違う

ここはかなり混乱しやすいポイントです。

`prototype`と`[[Prototype]]`は似ていますが、意味が違います。

| 名前 | 意味 |
|---|---|
| `User.prototype` | constructor関数が持つプロパティ |
| `user`の`[[Prototype]]` | オブジェクトが参照する先 |

たとえば、次のコードがあります。

```js
class User {}
const user = new User()
```

このとき、関係は次のようになります。

```txt
User.prototype
↑
│
userの[[Prototype]]
```

つまり、`new User()`によって作られた`user`の`[[Prototype]]`は、`User.prototype`になります。

確認するとこうです。

```js
console.log(Object.getPrototypeOf(user) === User.prototype)
// true
```

`User.prototype`は、JavaScriptのコードからアクセスできる通常のプロパティです。

一方、`[[Prototype]]`は仕様上の内部的な参照です。

実際のコードでは、`Object.getPrototypeOf(user)`で確認します。

---

## __proto__とは何か

JavaScriptでは、次のように書くこともできます。

```js
console.log(user.__proto__ === User.prototype)
// true
```

`__proto__`は、オブジェクトの`[[Prototype]]`にアクセスするための歴史的な仕組みです。

ただし、普段のコードでは`__proto__`を直接使うより、次のAPIを使う方が安全です。

```js
Object.getPrototypeOf(user)
```

prototypeを変更する場合も、基本的には次のAPIを使います。

```js
Object.setPrototypeOf(user, anotherPrototype)
```

ただし、既存オブジェクトのprototypeを後から変更することは、実務ではあまりおすすめされません。

パフォーマンスに悪影響が出ることがあるためです。

---

## prototype chainとは何か

`prototype chain`とは、プロパティを探すためにprototypeを順番にたどる仕組みです。

次のコードを見てください。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log('hello')
  }
}
const user = new User('Taro')
```

このとき、`user.toString()`も呼べます。

```js
console.log(user.toString())
```

しかし、`toString`は`user`にも`User.prototype`にも定義していません。

では、どこから来ているのでしょうか。

prototype chainは次のようになっています。

```txt
user
↓
User.prototype
↓
Object.prototype
↓
null
```

`toString`は、多くの場合`Object.prototype`にあります。

JavaScriptは次のように探します。

```txt
userにtoStringはある？
↓
ない
↓
User.prototypeにtoStringはある？
↓
ない
↓
Object.prototypeにtoStringはある？
↓
ある
↓
それを使う
```

この探索のつながりが`prototype chain`です。

---

## プロパティ探索の流れ

`user.greet()`を実行すると、JavaScriptは次の順番で探します。

```txt
1. user自身にgreetがあるか確認する
2. なければUser.prototypeを見る
3. User.prototypeにgreetがあれば使う
4. なければObject.prototypeを見る
5. それでもなければundefinedになる
```

つまり、JavaScriptのプロパティアクセスは、そのオブジェクト自身だけを見ているわけではありません。

prototype chainをたどって探します。

---

## classのメソッドはprototypeに置かれる

次のコードを見てください。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
```

この`greet`は、各インスタンスに直接作られるのではありません。

```js
const user = new User('Taro')
console.log(user.hasOwnProperty('greet'))
// false
console.log(User.prototype.hasOwnProperty('greet'))
// true
```

つまり、`class`構文で定義した通常メソッドは`prototype`に置かれます。

```txt
user
└─ name
   ↓
User.prototype
└─ greet
```

これにより、複数のインスタンスで同じメソッドを共有できます。

---

## インスタンスプロパティとprototypeメソッド

クラスでは、インスタンスごとに違う値と、共通で使うメソッドを分けて考えると理解しやすいです。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
```

この場合、`name`はインスタンスごとに違います。

```txt
user1.name = "Taro"
user2.name = "Hanako"
```

一方、`greet`は共通処理です。

```txt
User.prototype.greetをuser1とuser2が共有する
```

整理するとこうです。

| 種類 | 置き場所 | 例 |
|---|---|---|
| インスタンスごとの値 | インスタンス自身 | `this.name` |
| 共通メソッド | `ClassName.prototype` | `greet()` |

---

## class以前のprototypeの書き方

`class`が登場する前は、constructor関数と`prototype`を直接使っていました。

```js
function User(name) {
  this.name = name
}
User.prototype.greet = function () {
  console.log(`こんにちは、${this.name}です`)
}
const user = new User('Taro')
user.greet()
```

これは、classで書くと次のコードに近いです。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
```

つまり、`class`はprototypeの仕組みを隠して、書きやすくした構文と考えると理解しやすいです。

---

## prototypeを後から追加できる

`prototype`には、後からメソッドを追加できます。

```js
function User(name) {
  this.name = name
}
const user = new User('Taro')
User.prototype.greet = function () {
  console.log(`こんにちは、${this.name}です`)
}
user.greet()
// こんにちは、Taroです
```

`user`を作った後に`User.prototype.greet`を追加しても、`user.greet()`は使えます。

なぜなら、`user`は`User.prototype`への参照を持っているからです。

```txt
user
↓
User.prototype
```

後から`User.prototype`にメソッドが追加されると、既存のインスタンスからも見えるようになります。

---

## prototypeの差し替えには注意

次のように、`prototype`自体を丸ごと差し替えることもできます。

```js
function User(name) {
  this.name = name
}
const user1 = new User('Taro')
User.prototype = {
  greet() {
    console.log('hello')
  }
}
const user2 = new User('Hanako')
```

この場合、`user1`と`user2`は異なるprototypeを参照します。

```txt
user1 ──> 古いUser.prototype
user2 ──> 新しいUser.prototype
```

つまり、`prototype`を丸ごと差し替えると、既存のインスタンスには影響しません。

一方、既存の`User.prototype`にメソッドを追加する場合は、既存インスタンスにも見えます。

```js
User.prototype.greet = function () {}
```

この違いは重要です。

---

## constructorプロパティが消えるケース

`prototype`を丸ごと差し替えると、`constructor`プロパティが消えることがあります。

```js
function User(name) {
  this.name = name
}
User.prototype = {
  greet() {
    console.log('hello')
  }
}
const user = new User('Taro')
console.log(user.constructor === User)
// falseになることがある
```

なぜなら、新しく代入したオブジェクトには、明示的に`constructor`を入れていないからです。

必要であれば、次のように書きます。

```js
User.prototype = {
  constructor: User,
  greet() {
    console.log('hello')
  }
}
```

ただし、現代のJavaScriptでは、通常は`class`を使う方が安全で読みやすいです。

---

## staticメソッドはprototypeに置かれない

`class`には`static`メソッドもあります。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
  static createGuest() {
    return new User('Guest')
  }
}
```

このとき、`greet`は`User.prototype`に置かれます。

```js
console.log(User.prototype.greet)
// function
```

一方、`createGuest`は`User`自身に置かれます。

```js
console.log(User.createGuest)
// function
```

置き場所はこうです。

```txt
User
├─ createGuest
└─ prototype ──> User.prototype
                 ├─ constructor
                 └─ greet
```

整理すると、次のようになります。

| 定義 | 置き場所 | 呼び出し方 |
|---|---|---|
| 通常メソッド | `User.prototype` | `user.greet()` |
| staticメソッド | `User`自身 | `User.createGuest()` |

---

## arrow functionのクラスフィールドとの違い

最近のJavaScriptやTypeScriptでは、次のような書き方もあります。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet = () => {
    console.log(`こんにちは、${this.name}です`)
  }
}
```

この`greet`は、通常メソッドとは違います。

通常メソッドの場合は、`User.prototype`に置かれます。

```js
class User {
  greet() {}
}
```

```txt
User.prototype.greet
```

一方、クラスフィールドのarrow functionは、インスタンスごとに作られます。

```js
class User {
  greet = () => {}
}
```

```txt
user1.greet
user2.greet
```

整理するとこうです。

| 書き方 | 置き場所 | 特徴 |
|---|---|---|
| `greet() {}` | `prototype` | メソッドを共有できる |
| `greet = () => {}` | インスタンス自身 | `this`が固定されやすいが、毎回関数が作られる |

Reactなどではarrow functionを使う場面もあります。

ただし、通常のクラス設計では、prototypeメソッドの方が自然なことも多いです。

## prototypeの確認方法

prototypeの関係を確認するには、次のメソッドが使えます。

### Object.getPrototypeOf

```js
Object.getPrototypeOf(user)
```

オブジェクトの`[[Prototype]]`を取得します。

```js
console.log(Object.getPrototypeOf(user) === User.prototype)
// true
```

### hasOwnProperty

```js
user.hasOwnProperty('name')
// true
user.hasOwnProperty('greet')
// false
```

そのプロパティが、オブジェクト自身のものかどうかを確認します。

### in演算子

```js
'name' in user
// true
'greet' in user
// true
```

`in`は、オブジェクト自身だけでなくprototype chain上も含めて確認します。

そのため、`greet`は`user`自身にはありませんが、`in`では`true`になります。

---

## hasOwnPropertyとinの違い

次のコードを見てください。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {}
}
const user = new User('Taro')
```

確認します。

```js
console.log(user.hasOwnProperty('name'))
// true
console.log(user.hasOwnProperty('greet'))
// false
console.log('name' in user)
// true
console.log('greet' in user)
// true
```

`hasOwnProperty`は、自分自身のプロパティだけを見ます。

`in`は、prototype chainまで見ます。

| 確認方法 | 自分自身 | prototype chain |
|---|---:|---:|
| `hasOwnProperty` | 見る | 見ない |
| `in` | 見る | 見る |

prototypeを理解すると、この違いも自然にわかります。

## prototypeを使った継承

prototypeは継承にも使われます。

```js
class Animal {
  constructor(name) {
    this.name = name
  }
  eat() {
    console.log(`${this.name}が食べます`)
  }
}
class Dog extends Animal {
  bark() {
    console.log('ワン')
  }
}
const dog = new Dog('Pochi')
dog.eat()
dog.bark()
```

このとき、prototype chainは次のようになります。

```txt
dog
↓
Dog.prototype
↓
Animal.prototype
↓
Object.prototype
↓
null
```

`dog.bark()`は`Dog.prototype`で見つかります。

`dog.eat()`は`Dog.prototype`にはありませんが、次の`Animal.prototype`で見つかります。

これがprototypeによる継承です。

---

## prototypeは親クラスそのものではない

prototypeは、クラスベース言語の「親クラス」と完全に同じではありません。

JavaScriptでは、オブジェクトが別のオブジェクトを参照します。

```txt
オブジェクト → オブジェクト → オブジェクト
```

つまり、JavaScriptの継承は、クラスそのものよりも **オブジェクト同士のつながり** が中心です。

`class`を使っていても、内部ではprototype chainが使われています。

---

## よくある誤解

### 誤解1: インスタンスがprototypeを持っている

正確には、インスタンスが`prototype`というプロパティを持っているわけではありません。

```js
const user = new User()
console.log(user.prototype)
// undefined
```

インスタンスが持つのは、内部的な`[[Prototype]]`です。

`prototype`プロパティを持つのは、主にconstructor関数側です。

```js
console.log(User.prototype)
// User.prototype object
```

### 誤解2: constructorはインスタンス自身のプロパティ

多くの場合、違います。

```js
const user = new User()
console.log(user.hasOwnProperty('constructor'))
// false
```

`user.constructor`は、prototype chainをたどって`User.prototype.constructor`を見つけています。

### 誤解3: classを使えばprototypeは関係ない

これも違います。

`class`は見た目をわかりやすくしているだけで、通常メソッドは`prototype`に置かれます。

```js
class User {
  greet() {}
}
console.log(User.prototype.greet)
// function
```

classを使っていても、prototypeの仕組みは裏側で動いています。

---

## 実務ではどこまで意識すべきか

普段の開発では、毎回`prototype`を直接操作する必要はありません。

多くの場合、次のように`class`を書けば十分です。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
```

ただし、次のような場面ではprototypeの理解が役立ちます。

- JavaScriptの`class`の仕組みを理解したいとき
- `this`の挙動を理解したいとき
- 継承の仕組みを理解したいとき
- メソッドがどこにあるのか調べたいとき
- `hasOwnProperty`や`in`の違いを理解したいとき
- ライブラリのコードを読むとき

prototypeは毎日直接書くものではありません。

しかし、JavaScriptの理解を深めるうえではかなり重要です。

---

## まとめ

`prototype`は、JavaScriptのオブジェクトがプロパティやメソッドを探しに行く参照先です。

重要なポイントは次の通りです。

```txt
constructor関数はprototypeを持つ
newされたインスタンスは、そのprototypeにつながる
メソッドはprototypeに置かれて共有される
プロパティ探索ではprototype chainをたどる
classの通常メソッドもprototypeに置かれる
```

次のコードをもう一度見てください。

```js
class User {
  constructor(name) {
    this.name = name
  }
  greet() {
    console.log(`こんにちは、${this.name}です`)
  }
}
const user = new User('Taro')
user.greet()
```

このコードの裏側では、次のような関係ができています。

```txt
user
├─ name: "Taro"
└─ [[Prototype]] ──> User.prototype
                    ├─ constructor ──> User
                    └─ greet
```

つまり、`prototype`は **インスタンスに共通の機能を共有させるための仕組み** です。

`constructor`、`new`、`this`、`class`を深く理解するには、`prototype`は避けて通れない重要なテーマです。
