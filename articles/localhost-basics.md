開発サーバーを起動すると、ターミナルにこんなURLが表示されます。

```text
http://localhost:3000
```

ブラウザで開けば、作っている画面が出てくる。普段はそれで困りません。

でも、よく考えると不思議です。`localhost`はWebサイトの名前なのでしょうか。インターネット上のどこかへ接続しているのでしょうか。後ろに付いた`3000`は何を表しているのでしょう。

結論から書きます。

**localhostは、いま使っているコンピューター自身を指す名前です。**

`http://localhost:3000`を開いても、ブラウザは外部のWebサイトへ向かいません。行き先は、同じコンピューターの中で動いているプログラムです。この記事では、その通信をブラウザ側から順番に追います。

## localhostは自分のコンピューターを指している

`zenn.dev`を開くと、ブラウザはインターネットを経由して、Zennのサーバーへ接続します。

一方、`localhost`が指すのは自分のコンピューターです。

```text
zenn.dev   → インターネット上のコンピューター
localhost  → いま使っているコンピューター
```

`localhost`は、コンピューター自身へ接続するために用意された特別なホスト名です。ホスト名とは、ネットワーク上の接続先を表す名前のことです。

ただし、localhost自身がWebページを持っているわけではありません。自分のコンピューター内で、リクエストを待っているプログラムが必要です。そのプログラムが開発サーバーです。

## サーバーは同じコンピューターの中でも動かせる

サーバーと聞くと、大きな専用コンピューターを思い浮かべるかもしれません。けれども、サーバーという言葉は「リクエストを受け取り、結果を返す役割」も表します。

普段使っているPCでも、その役割を持つプログラムを動かせます。

たとえば、Viteで`npm run dev`を実行すると、開発サーバーが起動します。ブラウザが「ページをください」とリクエストを送り、開発サーバーがHTMLやJavaScriptを返します。

```mermaid
flowchart LR
    A["ブラウザ（クライアント）"] -->|"ページをください"| B["開発サーバー"]
    B -->|"HTMLなどを返す"| A
```

このとき、ブラウザと開発サーバーは同じPC上で動いています。それでも役割は別です。リクエストを送るブラウザがクライアント、受け取って返事をするプログラムがサーバーです。

## `localhost:3000`の3000は受付を分ける番号

自分のコンピューターでは、複数のプログラムが同時に動いています。接続先がlocalhostだけでは、どのプログラムにリクエストを渡せばよいか決まりません。

そこで使うのが**ポート番号**です。

```text
localhost:3000 → ポート3000で待つプログラム
localhost:8000 → ポート8000で待つプログラム
```

ポートは、同じコンピューター内の受付を分ける番号だと考えると分かりやすいでしょう。開発サーバーがポート3000で待っているなら、ブラウザもポート3000へ接続します。

番号が違えば、届きません。

## URLを4つに分けると役割が見える

ここで、URL全体を分解してみます。

```text
http://localhost:3000/users
```

| 部分 | 名前 | 役割 |
| --- | --- | --- |
| `http` | 通信方式 | HTTPでやり取りする |
| `localhost` | ホスト名 | 自分のコンピューターへ接続する |
| `3000` | ポート番号 | ポート3000で待つプログラムへ接続する |
| `/users` | パス | サーバーへ`/users`を要求する |

これを一文にすると、次の意味になります。

> 自分のコンピューターのポート3000で待っているプログラムへ、HTTPで`/users`を要求する。

URLでポート番号を省略した場合は、通信方式ごとの標準ポートが使われます。HTTPなら80、HTTPSなら443です。`http://localhost`は、ポートを明記していなくても80番ポートへ接続します。

## ブラウザからサーバーへ届くまで

`http://localhost:3000`を開いたときの流れを、もう少し詳しく見てみます。

```mermaid
flowchart LR
    A["ブラウザ"] -->|"1. localhostへ接続"| B["OSのネットワーク機能"]
    B -->|"2. ポート3000へ渡す"| C["開発サーバー"]
    C -->|"3. レスポンスを返す"| B
    B -->|"4. ブラウザへ戻す"| A
```

まず、ブラウザは`localhost`に対応するIPアドレスを調べます。通常は`127.0.0.1`という、自分自身を表す特別なIPアドレスが使われます。

次に、ブラウザはそのアドレスのポート3000へ接続します。OSはポート3000で待っているプログラムを確認し、見つかればリクエストを渡します。開発サーバーがレスポンスを返すと、同じ経路を通ってブラウザへ戻り、画面が表示されます。

この通信でも、OSのネットワーク機能は使います。ただし、Wi-FiやLANケーブルから外へは出ません。自分自身へ戻ってくる経路だから、名前は**ループバック**です。

### localhostと127.0.0.1は同じもの？

接続先はほぼ同じですが、役割が違います。

- `localhost`は人が読める名前
- `127.0.0.1`はIPv4のIPアドレス

`http://localhost:3000`と`http://127.0.0.1:3000`は、通常、同じコンピューターの同じポートへ接続します。

:::message
環境によっては、localhostがIPv6の`::1`を指すこともあります。`::1`も自分自身へ戻るためのアドレスです。最初は「localhostには、自分自身を表すIPアドレスが対応している」と分かれば十分です。
:::

## サーバーを止めると接続できない理由

localhostは、入力するだけでページを表示してくれるWebサイトではありません。指定したポートで、サーバーがリクエストを待っている必要があります。

```text
サーバーが動いている
ブラウザ → localhost:3000 → 開発サーバーが応答する

サーバーが止まっている
ブラウザ → localhost:3000 → 応答するプログラムがいない
```

応答するプログラムがいないと、ブラウザには「接続を拒否されました」などのエラーが表示されます。ターミナルでは`Connection refused`と出ることもあります。

このエラーが出たら、最初に次の2点を確認します。

1. 開発サーバーが起動しているか
2. ブラウザと開発サーバーのポート番号が一致しているか

localhostを使った開発で起きる接続エラーの多くは、このどちらかで見つかります。

## 小さなサーバーを動かして確かめる

Node.jsが入っていれば、短いコードで確認できます。次の内容を`server.mjs`として保存してください。

```js:server.mjs
import { createServer } from "node:http";

const server = createServer((_request, response) => {
  response.writeHead(200, {
    "Content-Type": "text/plain; charset=utf-8",
  });
  response.end("localhostからこんにちは");
});

server.listen(3000, "localhost", () => {
  console.log("http://localhost:3000 で待っています");
});
```

準備はこれだけです。

ターミナルで起動します。

```sh
node server.mjs
```

ブラウザで`http://localhost:3000`を開くと、「localhostからこんにちは」と表示されます。

コードの中では、`server.listen()`がlocalhostのポート3000でリクエストを待ち始めています。ブラウザが同じポートへ接続したので、`createServer()`へ渡した処理が呼ばれ、文字列が返ってきました。

次に、ターミナルで`Ctrl+C`を押してサーバーを止め、ブラウザを再読み込みしてみてください。今度は接続できません。理由は単純です。ポート3000で待つプログラムが、もういません。

`http://localhost:3001`へ変えても接続できません。こちらも同じです。サーバーは3000番で待っているので、3001番には何もいません。

## localhostについてよくある疑問

### インターネットにつながっていなくても使える？

使えます。localhostへの通信はPCの中で完結します。ただし、表示したアプリが外部のAPIや画像を読み込む場合、その部分にはインターネット接続が必要です。

### 別のPCでlocalhostを開けば、開発中のPCにつながる？

つながりません。別のPCで入力したlocalhostは、その別のPC自身を指します。localhostの「自分」は、通信を始めた側です。

### 同じポートを複数のサーバーで使える？

通常、同じアドレスとポートの組み合わせを、複数のサーバーが同時には使えません。すでに3000番ポートが使われている状態で別のサーバーを起動すると、`Address already in use`などのエラーになります。

## localhostは自分のPCへ戻るための名前

最後に、`http://localhost:3000`の意味をもう一度まとめます。

```text
http       → HTTPで通信する
localhost  → 自分のコンピューターへ接続する
3000       → ポート3000で待つプログラムを選ぶ
```

localhostがページを返しているわけではありません。ページを返すのは、指定したポートで待っている開発サーバーです。localhostは、ブラウザがそのサーバーへ向かうときに使う「自分自身への行き先」を表しています。

つまり、`localhost:3000`を開くとは、**自分のコンピューターのポート3000で待っているプログラムへ接続すること**です。
