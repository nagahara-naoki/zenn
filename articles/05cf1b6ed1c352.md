Decoratorは、元の対象と互換性を保ちながら、外側から責務を追加するパターンです。

継承で種類を増やす代わりに、必要な機能を組み合わせられます。

## 関数を包む最小例

```ts
type SavePost = (post: Post) => Promise<void>;

function withLogging(savePost: SavePost): SavePost {
  return async (post) => {
    console.log("[savePost] start", { postId: post.id });

    try {
      await savePost(post);
      console.log("[savePost] success", { postId: post.id });
    } catch (error) {
      console.error("[savePost] failed", { postId: post.id, error });
      throw error;
    }
  };
}
```

元の関数とDecoratorは、どちらも `SavePost` として呼べます。

```ts
const savePostWithLogging = withLogging(savePost);
await savePostWithLogging(post);
```

ログを追加しても、利用側の呼び出し方は変わりません。

## 複数の責務を重ねる

```ts
function withRetry(savePost: SavePost, maxAttempts = 3): SavePost {
  return async (post) => {
    let lastError: unknown;

    for (let attempt = 1; attempt <= maxAttempts; attempt += 1) {
      try {
        await savePost(post);
        return;
      } catch (error) {
        lastError = error;
      }
    }

    throw lastError;
  };
}

const enhancedSavePost = withLogging(withRetry(savePost));
```

順序には意味があります。

- 外側がloggingなら、retry全体を1回の処理として記録する
- 内側の各試行を記録したければ、組み合わせを変える

Decoratorを重ねるときは、実行順序をテストします。

## objectを包むDecorator

GoF Decoratorは、同じinterfaceを実装するobject wrapperとして説明されます。

```ts
interface Notifier {
  send(message: string): Promise<void>;
}

class RetryingNotifier implements Notifier {
  constructor(private readonly inner: Notifier) {}

  async send(message: string): Promise<void> {
    try {
      await this.inner.send(message);
    } catch {
      await this.inner.send(message);
    }
  }
}
```

`RetryingNotifier` は別の `Notifier` を保持し、同じ `send` interfaceを提供します。

JavaScriptでは高階関数の方が簡潔な場合もあります。状態や複数メソッドをまとめる必要があるときはobject形式が向きます。

## TypeScriptのdecorator構文とは別

```ts
@sealed
class Example {}
```

この `@sealed` はECMAScript decorators proposalに基づく構文です。

Decoratorパターンと関連する用途はありますが、同義ではありません。

- Decoratorパターン：責務を合成する設計
- decorator構文：classや要素へ処理を適用する言語機能

構文を使わなくてもDecoratorパターンは実装できます。

## RxJS operatorをDecorator的に読む

pipeable operatorはObservableを受け取り、新しいObservableを返す関数です。

```ts
const result$ = source$.pipe(
  map((value) => value * 2),
  filter((value) => value > 10),
  tap((value) => console.log(value)),
);
```

各operatorはsourceを直接変更せず、変換・絞り込み・副作用などの振る舞いを持つObservableを返します。

```text
source$
  └─ map
      └─ filter
          └─ tap
```

同じObservable interfaceを保ちながら振る舞いを重ねる点はDecorator的です。同時に、関数合成やlazy stream transformationとしての性質もあります。

RxJS公式が各operatorをGoF Decoratorとして分類しているわけではありません。パターンとの類似から合成の考え方を学ぶ例です。

## NgRx meta-reducer

meta-reducerはreducerを受け取り、reducerを返します。

```ts
function logger(reducer: ActionReducer<AppState>): ActionReducer<AppState> {
  return (state, action) => {
    console.log("before", state, action);
    const nextState = reducer(state, action);
    console.log("after", nextState);
    return nextState;
  };
}
```

元のreducer interfaceを保ったまま、横断的な処理を追加するため、Decoratorとして理解しやすい例です。

## 向いている責務

- ログ・計測
- retry・timeout
- cache
- access control
- validation
- transaction境界

ただし、同じ処理に何層も重ねると、どの層が失敗や戻り値を変更したか追いにくくなります。

## 注意点

- 入出力の契約を変えていないか
- 例外を意図せず握りつぶしていないか
- 適用順序が明確か
- 同じDecoratorを二重適用していないか
- 業務の中心処理までwrapperへ隠していないか

## まとめ

Decoratorは、元の対象と同じinterfaceを保ちながら責務を追加します。

- JavaScriptでは高階関数で簡潔に書ける
- objectの複数メソッドを包む場合はclassも使える
- decorator構文とは別の概念
- RxJS operatorやNgRx meta-reducerはDecorator的に読める
- 合成順序と失敗セマンティクスをテストする
