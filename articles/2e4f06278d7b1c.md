## `var`・`let`・`const`・関数宣言の違いから整理する

JavaScriptを学んでいると、**巻き上げ** という言葉が出てきます。

巻き上げは英語で **Hoisting** と呼ばれます。

最初に結論を言うと、巻き上げとは次のような仕組みです。

> JavaScriptのコードが実行される前に、変数宣言や関数宣言がスコープの先頭で準備されるように見える仕組み

「ように見える」と書いたのは、実際にコードが物理的に上へ移動しているわけではないからです。

JavaScriptエンジンがコードを実行する前に、変数や関数の宣言情報を先に準備します。

その結果、コード上では後ろに書いたはずの宣言が、前から使えるように見える場合があります。

この記事では、JavaScriptの巻き上げについて、次の内容を整理します。

- 巻き上げとは何か
- `var` の巻き上げ
- `let` / `const` の巻き上げ
- Temporal Dead Zone
- 関数宣言の巻き上げ
- 関数式とアロー関数の巻き上げ
- 実務での注意点
- 巻き上げを避ける書き方

---

# 巻き上げとは

巻き上げとは、変数宣言や関数宣言が、スコープの先頭に移動したかのように扱われる仕組みです。

たとえば、次のコードを見てください。

```js
console.log(message);

var message = "こんにちは";
```

普通に考えると、`message` は `console.log` の後で宣言されています。

そのため、エラーになりそうに見えます。

しかし、このコードはエラーにはなりません。

出力結果は次のようになります。

```txt
undefined
```

なぜ `ReferenceError` にならないのでしょうか。

それは、`var message` の宣言部分が、実行前にスコープの先頭で準備されるからです。

イメージとしては、次のように解釈されます。

```js
var message;

console.log(message);

message = "こんにちは";
```

重要なのは、巻き上げられるのは **宣言** であって、**代入** ではないという点です。

```js
var message = "こんにちは";
```

このコードは、内部的には次のように分けて考えると理解しやすいです。

```js
var message; // 宣言
message = "こんにちは"; // 代入
```

巻き上げの対象になるのは、主に宣言部分です。

---

# `var` の巻き上げ

`var` は、巻き上げを理解するうえで最もわかりやすい例です。

```js
console.log(name);

var name = "田中";
```

出力結果です。

```txt
undefined
```

これは、次のように動いていると考えるとわかりやすいです。

```js
var name;

console.log(name);

name = "田中";
```

`var name;` は先に準備されています。

しかし、`name = "田中";` は元の位置で実行されます。

そのため、`console.log(name)` の時点では、まだ値が入っていません。

結果として `undefined` が表示されます。

---

# 宣言は巻き上がるが、代入は巻き上がらない

ここはとても重要です。

```js
console.log(count);

var count = 10;
```

このコードは、次のようなイメージです。

```js
var count;

console.log(count);

count = 10;
```

つまり、次の2つは別物です。

```js
var count;
```

```js
count = 10;
```

巻き上げられるのは `var count;` の部分です。

`count = 10;` は巻き上げられません。

そのため、実行前から変数名は存在していますが、値はまだ入っていません。

---

# `var` は関数スコープ

`var` はブロックスコープではなく、関数スコープです。

```js
if (true) {
  var message = "こんにちは";
}

console.log(message);
```

出力結果です。

```txt
こんにちは
```

`if` ブロックの中で宣言した `message` を、外側から参照できています。

これは、`var` が `{}` のブロック単位ではなく、関数単位でスコープを作るためです。

次のように関数の中で使うと、関数の外からは参照できません。

```js
function sample() {
  var message = "こんにちは";
}

sample();

console.log(message);
```

これはエラーになります。

```txt
ReferenceError: message is not defined
```

`var` は関数の中に閉じ込められるためです。

---

# `var` が嫌われる理由

現在のJavaScriptでは、`var` はあまり推奨されません。

理由は、主に次の3つです。

- 巻き上げによって意図しない `undefined` が発生しやすい
- ブロックスコープではないため、変数の有効範囲が広くなりやすい
- 再宣言できるため、バグに気づきにくい

たとえば、次のコードは問題なく動きます。

```js
var userName = "田中";
var userName = "佐藤";

console.log(userName);
```

出力結果です。

```txt
佐藤
```

同じ名前の変数を再宣言できてしまうため、意図しない上書きに気づきにくくなります。

そのため、現代のJavaScriptでは、基本的に `let` と `const` を使う方が安全です。

---

# `let` の巻き上げ

次に、`let` を見てみます。

```js
console.log(name);

let name = "田中";
```

これはエラーになります。

```txt
ReferenceError: Cannot access 'name' before initialization
```

`var` の場合は `undefined` が表示されました。

しかし、`let` の場合はエラーになります。

では、`let` は巻き上げられていないのでしょうか。

実は、`let` も巻き上げられます。

ただし、`var` のように `undefined` で初期化されないため、宣言前にアクセスするとエラーになります。

---

# `const` の巻き上げ

`const` も `let` と同じように、宣言前にアクセスするとエラーになります。

```js
console.log(age);

const age = 20;
```

出力結果です。

```txt
ReferenceError: Cannot access 'age' before initialization
```

`const` も巻き上げられます。

しかし、宣言行に到達するまでは使えません。

この「宣言されているが、まだ使えない期間」が、次に説明する Temporal Dead Zone です。

---

# Temporal Dead Zoneとは

Temporal Dead Zone は、略して **TDZ** と呼ばれます。

日本語では「一時的デッドゾーン」と呼ばれることがあります。

TDZとは、`let` や `const` で宣言された変数が、スコープの開始から宣言行に到達するまで使えない期間のことです。

```js
{
  // ここからTDZ

  console.log(value);

  let value = 10;

  // ここからvalueを使える
  console.log(value);
}
```

`value` はブロックの先頭で存在自体は認識されています。

しかし、`let value = 10;` の行に到達するまでは初期化されていません。

そのため、宣言前にアクセスするとエラーになります。

---

# `let` / `const` はなぜ安全なのか

`let` や `const` は、宣言前に使うとエラーになります。

一見すると不便に見えますが、実務ではこちらの方が安全です。

```js
console.log(totalPrice);

const totalPrice = price * quantity;
```

このようなコードがあった場合、`const` ならすぐにエラーになります。

つまり、間違った順番で変数を使っていることに気づきやすいです。

一方、`var` だと `undefined` になって処理が続くため、原因に気づきにくくなる場合があります。

```js
console.log(totalPrice);

var totalPrice = price * quantity;
```

この場合、エラーではなく `undefined` が出るため、不具合が後ろの処理まで広がる可能性があります。

---

# 関数宣言の巻き上げ

関数宣言も巻き上げの対象です。

```js
greet();

function greet() {
  console.log("こんにちは");
}
```

出力結果です。

```txt
こんにちは
```

関数の定義より前に `greet()` を呼び出しているのに、問題なく動きます。

これは、関数宣言が実行前に準備されるためです。

`var` と違い、関数宣言では関数本体も使える状態になります。

---

# 関数宣言は本体ごと巻き上がる

`var` の場合、宣言だけが巻き上がり、代入は巻き上がりませんでした。

```js
console.log(value);

var value = 10;
```

これは次のようなイメージです。

```js
var value;

console.log(value);

value = 10;
```

一方、関数宣言の場合は、関数本体も使える状態になります。

```js
sayHello();

function sayHello() {
  console.log("Hello");
}
```

これは問題なく動きます。

そのため、関数宣言はコードの下の方に書いても、上から呼び出せます。

---

# 関数式の巻き上げ

関数式は、関数宣言とは挙動が違います。

```js
greet();

const greet = function () {
  console.log("こんにちは");
};
```

これはエラーになります。

```txt
ReferenceError: Cannot access 'greet' before initialization
```

なぜなら、`greet` は `const` で宣言された変数だからです。

関数そのものは値として代入されています。

```js
const greet = function () {
  console.log("こんにちは");
};
```

この場合、巻き上げのルールは関数ではなく、`const` のルールに従います。

そのため、宣言前に呼び出せません。

---

# `var` を使った関数式の場合

では、`var` で関数式を書くとどうなるでしょうか。

```js
greet();

var greet = function () {
  console.log("こんにちは");
};
```

これはエラーになります。

```txt
TypeError: greet is not a function
```

`ReferenceError` ではなく、`TypeError` です。

なぜなら、内部的には次のような状態になるからです。

```js
var greet;

greet();

greet = function () {
  console.log("こんにちは");
};
```

`greet` という変数は存在しています。

しかし、`greet()` を呼び出した時点では、まだ関数が代入されていません。

そのため、`undefined` を関数として呼び出そうとして `TypeError` になります。

---

# アロー関数の巻き上げ

アロー関数も、関数式と同じです。

```js
greet();

const greet = () => {
  console.log("こんにちは");
};
```

これはエラーになります。

```txt
ReferenceError: Cannot access 'greet' before initialization
```

アロー関数は、関数宣言ではありません。

`const greet` という変数に、関数を代入しているだけです。

そのため、巻き上げの挙動は `const` に従います。

つまり、宣言前には使えません。

---

# class宣言の巻き上げ

`class` も少し注意が必要です。

```js
const user = new User("田中");

class User {
  constructor(name) {
    this.name = name;
  }
}
```

これはエラーになります。

```txt
ReferenceError: Cannot access 'User' before initialization
```

`class` 宣言も巻き上げられます。

しかし、`let` や `const` と同じように、宣言前にアクセスするとエラーになります。

そのため、`class` は使う前に定義しておくのが基本です。

```js
class User {
  constructor(name) {
    this.name = name;
  }
}

const user = new User("田中");
```

---

# importは先に評価される

ES Modules の `import` も、通常の変数宣言とは少し違います。

```js
import { fetchUsers } from "./api.js";

fetchUsers();
```

`import` はモジュールの先頭に書くのが一般的です。

構文上、`import` はトップレベルで使われ、モジュールの評価前に依存関係が解決されます。

そのため、`import` は「実行前に準備される」という意味では巻き上げに近い性質を持ちます。

ただし、通常の `var` や `function` の巻き上げとは別物として考えた方がわかりやすいです。

実務では、`import` はファイルの先頭にまとめて書くのが一般的です。

---

# 巻き上げでよくある勘違い

## 勘違い1：コードが本当に上に移動している

巻き上げという名前から、コードが物理的に上へ移動しているように感じるかもしれません。

しかし、実際にソースコードが書き換わるわけではありません。

JavaScriptエンジンが実行前に宣言情報を準備しているだけです。

その結果、上に移動したように見えます。

## 勘違い2：代入も巻き上がる

代入は巻き上がりません。

```js
console.log(value);

var value = 100;
```

この場合、`100` が先に入るわけではありません。

先に準備されるのは `var value;` の部分だけです。

## 勘違い3：`let` と `const` は巻き上げられない

`let` と `const` も巻き上げられます。

ただし、初期化前にアクセスできないため、巻き上げられていないように見えるだけです。

```js
console.log(value);

let value = 10;
```

このコードがエラーになるのは、`value` が存在しないからではありません。

`value` は存在していますが、まだ初期化されていないため使えないのです。

---

# 巻き上げの比較表

| 書き方 | 宣言前に使えるか | 宣言前にアクセスした場合 |
|---|---:|---|
| `var` | 一応使える | `undefined` |
| `let` | 使えない | `ReferenceError` |
| `const` | 使えない | `ReferenceError` |
| 関数宣言 | 使える | 関数を呼び出せる |
| 関数式 `const fn = function () {}` | 使えない | `ReferenceError` |
| アロー関数 `const fn = () => {}` | 使えない | `ReferenceError` |
| `class` 宣言 | 使えない | `ReferenceError` |

# 実務で巻き上げをどう考えるべきか

巻き上げはJavaScriptの重要な仕様です。

ただし、実務では「巻き上げを利用して書く」よりも、「巻き上げに依存しない書き方」をする方が安全です。

たとえば、次のようなコードは避けた方がよいです。

```js
console.log(userName);

var userName = "田中";
```

動くとしても、読み手にとってわかりにくいです。

次のように、変数は使う前に宣言する方が自然です。

```js
const userName = "田中";

console.log(userName);
```

コードは、実行できることだけでなく、読みやすいことも大切です。

---

# 巻き上げを避けるための書き方

## 1. 基本は `const` を使う

再代入しない値は `const` を使います。

```js
const userName = "田中";
const age = 25;
const isAdmin = false;
```

`const` を使うと、後から別の値を代入できません。

そのため、意図しない変更を防ぎやすくなります。

## 2. 再代入が必要なときだけ `let` を使う

値を後から変更する必要がある場合は `let` を使います。

```js
let count = 0;

count++;
count++;

console.log(count);
```

`let` はブロックスコープを持つため、`var` より安全です。

## 3. `var` は基本的に使わない

現代のJavaScriptでは、基本的に `var` を使う必要はありません。

```js
// 避けたい
var message = "こんにちは";
```

次のように書く方が安全です。

```js
const message = "こんにちは";
```

`var` を読む機会はありますが、新しく書くコードでは `let` / `const` を使うのが基本です。

## 4. 変数は使う直前で宣言する

変数は、必要になった場所の近くで宣言すると読みやすくなります。

```js
function calculateTotalPrice(price, quantity) {
  const totalPrice = price * quantity;

  return totalPrice;
}
```

関数の先頭にすべての変数をまとめるよりも、使う場所の近くで宣言した方が、変数の意味を追いやすいです。

## 5. 関数宣言の巻き上げに頼りすぎない

関数宣言は定義前に呼び出せます。

```js
main();

function main() {
  console.log("実行");
}
```

この書き方自体は悪くありません。

特に、ファイルの先頭に処理の流れを書き、詳細な関数を下に置く書き方は読みやすい場合もあります。

```js
main();

function main() {
  const users = fetchUsers();
  renderUsers(users);
}

function fetchUsers() {
  return [];
}

function renderUsers(users) {
  console.log(users);
}
```

ただし、チームのルールによっては「関数は使う前に定義する」方針もあります。

大切なのは、巻き上げの仕様を理解したうえで、読みやすい順番にすることです。

# 関数宣言と関数式、どちらを使うべきか

巻き上げの観点では、関数宣言と関数式には違いがあります。

```js
// 関数宣言
function greet() {
  console.log("こんにちは");
}
```

関数宣言は、定義前に呼び出せます。

```js
// 関数式
const greet = function () {
  console.log("こんにちは");
};
```

関数式は、定義前に呼び出せません。

```js
// アロー関数
const greet = () => {
  console.log("こんにちは");
};
```

アロー関数も、定義前に呼び出せません。

どちらが絶対に正しいというより、用途で選ぶとよいです。

## 関数宣言が向いている場面

```js
function validateEmail(email) {
  return email.includes("@");
}
```

関数宣言は、名前付きの処理をわかりやすく定義したいときに向いています。

- 汎用的な処理
- ファイル内で何度も使う処理
- 処理に明確な名前を付けたい場合
- 関数を下にまとめたい場合

## 関数式・アロー関数が向いている場面

```js
const doubled = numbers.map((number) => number * 2);
```

関数式やアロー関数は、値として関数を扱いたいときに向いています。

- コールバック関数
- 配列メソッド
- イベントハンドラ
- 関数を変数に入れたい場合
- 条件によって関数を切り替えたい場合

# 巻き上げを理解すると何が嬉しいのか

巻き上げを理解すると、次のようなコードを見たときに混乱しにくくなります。

```js
console.log(value);

var value = 10;
```

```js
greet();

function greet() {
  console.log("こんにちは");
}
```

```js
greet();

const greet = () => {
  console.log("こんにちは");
};
```

それぞれの結果を説明できるようになります。

- `var` は `undefined` になる
- 関数宣言は定義前でも呼び出せる
- `const` のアロー関数は宣言前に呼び出せない

これは、JavaScriptのエラー調査でも役立ちます。

特に、次のようなエラーの意味がわかりやすくなります。

```txt
ReferenceError: Cannot access 'xxx' before initialization
```

```txt
TypeError: xxx is not a function
```

どちらも似たような場面で出ますが、原因は違います。

---

# エラーごとの原因

## `ReferenceError: Cannot access before initialization`

```js
console.log(value);

const value = 10;
```

このエラーは、`let` / `const` / `class` などを初期化前に使ったときに発生します。

変数は存在していますが、まだ使える状態ではありません。

## `ReferenceError: xxx is not defined`

```js
console.log(value);
```

このエラーは、そもそも `value` がどこにも宣言されていない場合に発生します。

先ほどの `Cannot access before initialization` とは少し違います。

## `TypeError: xxx is not a function`

```js
greet();

var greet = function () {
  console.log("こんにちは");
};
```

このエラーは、関数ではないものを関数として呼び出したときに発生します。

この例では、`greet` は巻き上げによって存在しています。

しかし、呼び出し時点では `undefined` です。

そのため、`undefined()` を実行しようとして `TypeError` になります。

---

# まとめ

巻き上げとは、JavaScriptのコードが実行される前に、変数宣言や関数宣言がスコープの先頭で準備されるように見える仕組みです。

重要なポイントは次の通りです。

- `var` は宣言が巻き上げられ、初期値は `undefined` になる
- `var` の代入は巻き上げられない
- `let` / `const` も巻き上げられるが、初期化前には使えない
- `let` / `const` には Temporal Dead Zone がある
- 関数宣言は本体ごと使える状態になる
- 関数式やアロー関数は、変数の巻き上げルールに従う
- `class` も宣言前には使えない
- 実務では巻き上げに依存しない書き方が安全

現代のJavaScriptでは、基本的に `const` を使い、再代入が必要な場合だけ `let` を使います。

`var` は古いコードを読むために理解しておく必要はありますが、新しく書くコードでは避けるのが基本です。

巻き上げは、便利に使うためというより、JavaScriptの挙動を正しく理解するために重要な知識です。

特に、次の3つを説明できれば、巻き上げの基本はかなり理解できています。

```js
console.log(value);
var value = 10;
```

```js
greet();
function greet() {
  console.log("こんにちは");
}
```

```js
greet();
const greet = () => {
  console.log("こんにちは");
};
```

それぞれがなぜ違う結果になるのかを理解することが、巻き上げを理解する第一歩です。
