JavaScriptの「巻き上げ（hoisting）」は、コードが物理的に上へ移動する機能ではありません。

スコープ内の宣言がコード評価前に処理されるため、上へ移動したような挙動が見えることを説明するための用語です。

## 先に比較表

| 宣言 | 宣言前に参照した結果 |
| --- | --- |
| `var` | `undefined` |
| `let` | ReferenceError |
| `const` | ReferenceError |
| `class` | ReferenceError |
| 関数宣言 | 関数を呼び出せる |
| `const f = () => {}` | `const` と同じ |

違いを生むのは、「bindingがあるか」だけではなく、「いつ初期化されるか」です。

## 生成と評価に分ける

学習用には、スコープの処理を次の2段階に分けると理解しやすくなります。

1. 宣言を処理し、bindingなどを準備する
2. ソースコードを上から評価する

```js
console.log(value);
var value = 10;
```

`var value` のbindingはコード評価前に作られ、`undefined` で初期化されます。代入 `value = 10` は、その行を評価したときに行われます。

理解用に書き換えるなら、次のイメージです。

```js
var value;
console.log(value); // undefined
value = 10;
```

実際にJavaScriptエンジンがソースコードをこの形へ書き換えるわけではありません。

## varの巻き上げ

`var` は宣言前に参照できますが、値はまだ代入されていません。

```js
console.log(userName); // undefined
var userName = "Taro";
```

この挙動は、設定漏れを見逃しやすくします。

```js
if (!enabled) {
  // enabledが未設定なのかfalseなのか区別しにくい
}

var enabled = true;
```

現代のコードでは、再代入しない値に `const`、必要な場合だけ `let` を使うのが基本です。

また、`var` はblock scopeではなくfunction scopeです。

```js
if (true) {
  var message = "visible";
}

console.log(message); // visible
```

巻き上げとscopeの違いは別の概念ですが、`var` の問題として同時に現れやすいため区別して確認します。

## let・constとTDZ

`let` と `const` のbindingもスコープへ登録されますが、宣言を評価して初期化されるまではアクセスできません。

```js
console.log(count); // ReferenceError
let count = 1;
```

スコープ開始から初期化までの区間をTemporal Dead Zone（TDZ）と呼びます。

```js
const rate = 0.1;

function calculate(price) {
  // このrateは外側のrateではなく、下のlet rateのTDZにあるbindingを指す
  console.log(rate); // ReferenceError
  let rate = 0.2;
  return price * rate;
}
```

内側の `rate` は関数スコープ全体で外側の `rate` を隠します。ただし宣言行までは初期化されていないため、外側へフォールバックせずReferenceErrorになります。

## 関数宣言

関数宣言のbindingは、コード評価前に呼び出せる状態へ初期化されます。

```js
console.log(double(4)); // 8

function double(value) {
  return value * 2;
}
```

これは、主要処理をファイル上部へ、補助関数を下部へ置くスタイルを可能にします。

ただし、定義前呼び出しへ過度に依存すると読む順序と実行順序が離れます。チームの規約に合わせ、一貫した配置にします。

## 関数式とアロー関数

```js
greet(); // ReferenceError

const greet = () => {
  console.log("Hello");
};
```

アロー関数だから巻き上がらない、という説明は正確ではありません。ここで支配しているのは `const greet` の初期化規則です。

`var` を使うとエラーの種類が変わります。

```js
greet(); // TypeError: greet is not a function

var greet = function () {
  console.log("Hello");
};
```

`greet` は `undefined` で初期化済みなので、名前解決には成功します。その `undefined` を関数として呼ぼうとしてTypeErrorになります。

## class宣言

```js
const user = new User("Taro"); // ReferenceError

class User {
  constructor(name) {
    this.name = name;
  }
}
```

classのbindingも初期化前はTDZにあります。使う前にclass宣言を評価する必要があります。

## importは「巻き上げ」と分けて考える

static importはモジュールのトップレベルにだけ書けます。

```js
import { fetchUsers } from "./api.js";
```

ECMAScript Modulesは、読み込み、linking、evaluationという処理を通じて依存関係とimport bindingを準備します。importされたbindingはexport元のbindingと結び付くlive bindingです。

通常のscriptにおける `var` や関数宣言と同じ「巻き上げ」としてまとめるより、モジュールのinstantiationとevaluationとして学ぶ方が正確です。

循環依存やtop-level awaitがあると評価順序も単純ではありません。「import文がファイル上部にあるから依存先が必ず最初に全部実行される」とは考えないようにします。

## エラーから原因を見分ける

### Cannot access before initialization

`let`、`const`、`class` などをTDZで参照しています。

### is not defined

対象のbinding自体が見つかりません。スペル、scope、import/exportを確認します。

### is not a function

bindingは見つかりましたが、その時点の値が呼び出せる関数ではありません。`var` の関数式を初期化前に呼ぶ場合などに発生します。

## 実務での方針

- 基本は `const`、再代入が必要なときだけ `let`
- `var` は既存コードを読むために理解し、新規コードでは原則使わない
- 変数は利用箇所の近くで初期化する
- 宣言前呼び出しに依存しすぎない
- importの評価順序はmodule graphとして考える
- エラーの種類を見て、名前解決と値の問題を分ける

## まとめ

巻き上げは「宣言が上へ移動する」現象ではなく、コード評価前の宣言処理によって説明できます。

- `var` は `undefined` で初期化される
- `let`、`const`、`class` は初期化までTDZにある
- 関数宣言は評価前に呼び出せる状態になる
- 関数式の挙動は代入先の宣言方法に従う
- importはモジュールのlinking・evaluationとして分けて理解する
