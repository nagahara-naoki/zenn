`static` は、メソッドやフィールドをインスタンスではなくクラス自身へ持たせる構文です。

迷ったときは、「この処理や値は、個々のオブジェクトに必要か、クラス全体に1つあればよいか」を考えます。

## インスタンスメンバーとの違い

```ts
class User {
  static serviceName = "user-service";

  constructor(public name: string) {}

  greet(): string {
    return `Hello, ${this.name}`;
  }

  static createGuest(): User {
    return new User("Guest");
  }
}

const user = new User("Taro");

console.log(user.greet());
console.log(User.serviceName);
console.log(User.createGuest());
```

配置を簡略化すると、次のように考えられます。

```text
User
├─ serviceName
├─ createGuest()
└─ prototype
   └─ greet()

user
├─ name
└─ [[Prototype]] ──> User.prototype
```

- `name` はインスタンスごとに異なる
- `greet` は `User.prototype` 経由で共有される
- staticメンバーは `User` 自身にある

そのため、`user.createGuest()` とは呼べません。

## staticメソッドのthis

staticメソッド内の `this` は、そのメソッドを呼び出したクラスを指します。

```js
class Model {
  static tableName = "models";

  static describe() {
    return `table: ${this.tableName}`;
  }
}

class User extends Model {
  static tableName = "users";
}

console.log(Model.describe()); // table: models
console.log(User.describe());  // table: users
```

staticメンバーはサブクラスにも継承されます。上の `User.describe()` では、`this` は `User` です。

一方、staticメソッドから特定インスタンスの値を直接参照することはできません。

```ts
class User {
  constructor(public name: string) {}

  static normalizeName(name: string): string {
    return name.trim();
  }
}
```

`name` はインスタンスが決まらないと値を選べないため、必要なら引数で受け取ります。

## よくある使いどころ

### 名前付きコンストラクター

```ts
class Money {
  private constructor(
    readonly amount: number,
    readonly currency: string,
  ) {}

  static yen(amount: number): Money {
    return new Money(amount, "JPY");
  }

  static dollar(amount: number): Money {
    return new Money(amount, "USD");
  }
}

const price = Money.yen(1_000);
```

生成意図が `new Money(1000, "JPY")` より明確になります。

### クラスに密接な純粋処理

```ts
class UserName {
  static isValid(value: string): boolean {
    return value.trim().length >= 2;
  }
}
```

ただし、状態を持たずクラスとも密接でない処理なら、通常のexport関数の方が単純です。

```ts
export function isValidUserName(value: string): boolean {
  return value.trim().length >= 2;
}
```

### インスタンス数などの共有状態

```js
class Connection {
  static count = 0;

  constructor() {
    Connection.count += 1;
  }
}
```

共有状態はテスト間で残りやすく、並行処理でも扱いに注意が必要です。便利だからという理由だけで、変更可能な値をstaticへ置かないようにします。

## private static

staticフィールドにもprivate要素を使えます。

```js
class Token {
  static #prefix = "app";

  static create(value) {
    return `${Token.#prefix}:${value}`;
  }
}
```

`#prefix` はクラス外から参照できません。

private staticフィールドを継承と組み合わせるときは注意が必要です。private要素は宣言したクラスにだけ属するため、ポリモーフィックな `this.#field` として扱えません。基底クラス固有の値なら、上の例のように宣言クラス名で参照すると意図が明確です。

## static初期化ブロック

複数の文を使ってstatic状態を初期化したい場合は、static initialization blockを使えます。

```js
class FeatureFlags {
  static values;

  static {
    FeatureFlags.values = Object.freeze({
      newCheckout: false,
    });
  }
}
```

単純な値なら、通常のstaticフィールド初期化で十分です。

## staticを避けた方がよい場面

- リクエストやユーザーごとに値が異なる
- テストごとに依存を差し替えたい
- ライフサイクル管理や後始末が必要
- 何でも入った「便利クラス」になっている
- グローバルな変更可能状態を隠している

このような場合は、インスタンス、通常の関数、依存性注入などを検討します。

## 判断基準

| 質問 | yesなら |
| --- | --- |
| 個体ごとに値が違うか | インスタンスメンバー |
| クラス名から呼ぶと意味が自然か | staticを検討 |
| 状態を持たない独立した処理か | 通常の関数を検討 |
| 実装をテストで差し替えたいか | インスタンスやDIを検討 |

## まとめ

`static` は「インスタンスを作らず呼べる便利機能」ではなく、所有者をクラス側へ置くための構文です。

- staticメンバーはクラス自身に属する
- インスタンスメソッドはprototype経由で共有される
- staticメソッドの `this` は呼び出したクラス
- 変更可能な共有状態には慎重になる
- 独立した処理なら通常の関数も比較する
