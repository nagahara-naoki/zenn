## はじめに

JavaScript や TypeScript の `class` を学んでいると、次のようなコードを見ることがあります。

```ts
class User {
  static role = "member"

  static createGuest() {
    return new User("Guest")
  }

  constructor(public name: string) {}
}
```

この `static` は、最初は少し分かりにくいです。

特に、次のような疑問が出やすいです。

```txt
static って何？
普通のメソッドと何が違うの？
なぜインスタンスから呼べないの？
いつ使うべきなの？
```

結論から言うと、`static` は **インスタンスではなく、クラス自身に属するメンバーを定義するためのもの**です。

---
## static とは

`static` は、**クラス自身に直接紐づくプロパティやメソッド**を定義するためのキーワードです。

```ts
class User {
  static type = "user"

  static describe() {
    return "これは User クラスです"
  }
}
```

この場合、`type` や `describe` はインスタンスではなく、`User` クラス自身に属します。

そのため、次のように呼び出します。

```ts
console.log(User.type)
console.log(User.describe())
```

出力はこうです。

```txt
user
これは User クラスです
```

一方で、インスタンスからは呼び出せません。

```ts
const user = new User()

console.log(user.type)      // undefined
console.log(user.describe)  // undefined
```

`static` が付いたものは、`new User()` で作られたオブジェクトには入りません。

---
## 普通のメソッドとの違い

普通のメソッドは、インスタンスから呼び出します。

```ts
class User {
  constructor(public name: string) {}

  greet() {
    return `こんにちは、${this.name}です`
  }
}

const user = new User("Taro")

console.log(user.greet())
```

この `greet` は、`user` というインスタンスから呼び出しています。

```ts
user.greet()
```

一方で、`static` メソッドはクラスから呼び出します。

```ts
class User {
  static createGuest() {
    return new User("Guest")
  }

  constructor(public name: string) {}
}

const guest = User.createGuest()

console.log(guest.name)
```

呼び出し方の違いはこうです。

```txt
普通のメソッド: インスタンス.メソッド()
static メソッド: クラス.メソッド()
```

表にすると、次のようになります。

| 種類 | 定義 | 呼び出し方 | 所属 |
|---|---|---|---|
| 通常メソッド | `greet()` | `user.greet()` | インスタンス側 |
| static メソッド | `static create()` | `User.create()` | クラス側 |

---
## インスタンスに属するもの

インスタンスに属するものとは、`new` で作られたオブジェクトごとに扱う値や処理です。

```ts
class User {
  constructor(public name: string) {}

  greet() {
    return `こんにちは、${this.name}です`
  }
}

const taro = new User("Taro")
const hanako = new User("Hanako")

console.log(taro.greet())
console.log(hanako.greet())
```

出力はこうです。

```txt
こんにちは、Taroです
こんにちは、Hanakoです
```

`taro` と `hanako` は、それぞれ別の `name` を持っています。

```txt
taro.name   → "Taro"
hanako.name → "Hanako"
```

つまり、通常メソッドは **インスタンスごとの状態を使う処理**に向いています。

---
## クラスに属するもの

一方で、`static` はクラスに属します。

```ts
class User {
  static defaultName = "Guest"

  constructor(public name: string) {}
}

console.log(User.defaultName)
```

この `defaultName` は、特定のユーザー1人に属する値ではありません。

```txt
Taro の defaultName
Hanako の defaultName
```

というよりも、

```txt
User クラス全体としての defaultName
```

です。

そのため、`static` にするのが自然です。

---
## static メソッド

`static` メソッドは、クラス自身から呼び出すメソッドです。

```ts
class MathUtil {
  static double(value: number) {
    return value * 2
  }

  static square(value: number) {
    return value * value
  }
}

console.log(MathUtil.double(10))
console.log(MathUtil.square(5))
```

出力はこうです。

```txt
20
25
```

このような処理は、インスタンスを作る必要がありません。

```ts
const util = new MathUtil()
```

のように書かなくても、次のように直接呼べます。

```ts
MathUtil.double(10)
```

つまり、`static` メソッドは **インスタンスの状態を必要としない処理**に向いています。

---
## static プロパティ

`static` はメソッドだけでなく、プロパティにも使えます。

```ts
class AppConfig {
  static appName = "My App"
  static version = "1.0.0"
}

console.log(AppConfig.appName)
console.log(AppConfig.version)
```

出力はこうです。

```txt
My App
1.0.0
```

このような値は、インスタンスごとに変わるものではありません。

たとえば、次のような値は `static` と相性が良いです。

```txt
アプリ名
バージョン
共通の設定値
デフォルト値
定数
```

---
## static はインスタンスから呼べない

`static` で定義したものは、インスタンスからは基本的に呼べません。

```ts
class User {
  static createGuest() {
    return new User("Guest")
  }

  constructor(public name: string) {}
}

const user = new User("Taro")

user.createGuest()
```

これはエラーになります。

```txt
Property 'createGuest' does not exist on type 'User'.
```

理由は、`createGuest` が `user` ではなく `User` に属しているからです。

正しくはこうです。

```ts
const guest = User.createGuest()
```

---
## なぜ static はインスタンスに入らないのか

`static` はクラス自身に定義されるからです。

```ts
class User {
  static createGuest() {
    return new User("Guest")
  }

  constructor(public name: string) {}

  greet() {
    return `こんにちは、${this.name}です`
  }
}
```

内部イメージは、かなりざっくり言うとこうです。

```txt
User
├─ createGuest

User.prototype
├─ greet

user インスタンス
├─ name
└─ [[Prototype]] → User.prototype
```

`greet` は `User.prototype` 側にあるため、インスタンスから呼び出せます。

```ts
user.greet()
```

一方、`createGuest` は `User` クラス自身にあるため、インスタンスからは直接見えません。

```ts
User.createGuest()
```

---
## static と this

`static` メソッドの中でも `this` は使えます。

ただし、この場合の `this` はインスタンスではなく、**クラス自身**を指します。

```ts
class User {
  static defaultName = "Guest"

  static createDefault() {
    return new User(this.defaultName)
  }

  constructor(public name: string) {}
}

const user = User.createDefault()

console.log(user.name)
```

出力はこうです。

```txt
Guest
```

この `this.defaultName` の `this` は、`User` クラスを指しています。

```ts
return new User(this.defaultName)
```

は、イメージとしてはこうです。

```ts
return new User(User.defaultName)
```

---
## static メソッドから通常プロパティは直接使えない

次のコードはエラーになります。

```ts
class User {
  constructor(public name: string) {}

  static printName() {
    console.log(this.name)
  }
}
```

`static` メソッド内の `this` は、インスタンスではありません。

そのため、インスタンスの `name` を直接参照することはできません。

`name` を使いたいなら、インスタンスを受け取る必要があります。

```ts
class User {
  constructor(public name: string) {}

  static printName(user: User) {
    console.log(user.name)
  }
}

const user = new User("Taro")

User.printName(user)
```

`static` は、特定のインスタンスに依存しない処理に使うのが基本です。

---
## static のよくある使いどころ

`static` は、次のような場面で使いやすいです。

```txt
1. ユーティリティ関数
2. ファクトリーメソッド
3. 共通設定
4. 定数
5. カウンター
6. バリデーション
```

順番に見ていきます。

---
## 使いどころ1: ユーティリティ関数

インスタンスを作る必要がない処理は、`static` と相性が良いです。

```ts
class StringUtil {
  static isEmpty(value: string) {
    return value.length === 0
  }

  static capitalize(value: string) {
    if (value.length === 0) {
      return value
    }

    return value[0].toUpperCase() + value.slice(1)
  }
}

console.log(StringUtil.isEmpty(""))
console.log(StringUtil.capitalize("hello"))
```

出力はこうです。

```txt
true
Hello
```

このような処理は、特定のインスタンス状態を持つ必要がありません。

---
## 使いどころ2: ファクトリーメソッド

`static` は、オブジェクト生成用のメソッドとしてもよく使われます。

```ts
class User {
  constructor(
    public name: string,
    public role: string
  ) {}

  static createAdmin(name: string) {
    return new User(name, "admin")
  }

  static createGuest() {
    return new User("Guest", "guest")
  }
}

const admin = User.createAdmin("Taro")
const guest = User.createGuest()

console.log(admin)
console.log(guest)
```

このように、`new User(...)` を直接書かせるのではなく、意味のある名前で生成処理を用意できます。

```ts
User.createAdmin("Taro")
User.createGuest()
```

この書き方は、意図が分かりやすいです。

---
## 使いどころ3: 共通設定

全インスタンスで共通の値を持ちたい場合も、`static` が使えます。

```ts
class ApiClient {
  static baseUrl = "https://api.example.com"

  static buildUrl(path: string) {
    return `${this.baseUrl}${path}`
  }
}

console.log(ApiClient.buildUrl("/users"))
```

出力はこうです。

```txt
https://api.example.com/users
```

`baseUrl` は、各インスタンスごとに別々に持つ必要がありません。

そのため、`static` にすると自然です。

---
## 使いどころ4: 定数

TypeScript では、定数のような値を `static readonly` で表すことがあります。

```ts
class HttpStatus {
  static readonly OK = 200
  static readonly NOT_FOUND = 404
  static readonly INTERNAL_SERVER_ERROR = 500
}

console.log(HttpStatus.OK)
console.log(HttpStatus.NOT_FOUND)
```

`readonly` を付けることで、後から代入できない値として扱えます。

```ts
HttpStatus.OK = 201
```

これはエラーになります。

定数をクラスにまとめたい場合に便利です。

---
## 使いどころ5: カウンター

`static` プロパティは、クラス全体で共有する値にも使えます。

```ts
class User {
  static count = 0

  constructor(public name: string) {
    User.count++
  }
}

const user1 = new User("Taro")
const user2 = new User("Hanako")

console.log(User.count)
```

出力はこうです。

```txt
2
```

`count` は、各ユーザーが個別に持つ値ではありません。

```txt
User クラスから何個インスタンスが作られたか
```

というクラス全体の情報です。

---
## 使いどころ6: バリデーション

入力値を検証するメソッドも `static` にしやすいです。

```ts
class UserValidator {
  static isValidName(name: string) {
    return name.length >= 2
  }

  static isValidAge(age: number) {
    return age >= 0 && age <= 120
  }
}

console.log(UserValidator.isValidName("Taro"))
console.log(UserValidator.isValidAge(150))
```

このような処理は、インスタンス状態を必要としません。

```txt
引数を受け取る
判定する
結果を返す
```

という処理なので、`static` で十分です。

---
## static と private

TypeScript では、`static` と `private` を組み合わせることもできます。

```ts
class Counter {
  private static count = 0

  static increment() {
    this.count++
  }

  static getCount() {
    return this.count
  }
}

Counter.increment()
Counter.increment()

console.log(Counter.getCount())
```

出力はこうです。

```txt
2
```

`private static count` は、クラスの外から直接触れません。

```ts
Counter.count
```

これはエラーになります。

クラス内部だけで管理したい共有状態に使えます。

---
## static と継承

`static` メソッドは継承されます。

```ts
class Animal {
  static category = "animal"

  static describe() {
    return "これは動物です"
  }
}

class Dog extends Animal {}

console.log(Dog.category)
console.log(Dog.describe())
```

出力はこうです。

```txt
animal
これは動物です
```

`Dog` は `Animal` を継承しているため、`static` メンバーも利用できます。

ただし、インスタンスから呼び出せるわけではありません。

```ts
const dog = new Dog()

dog.describe()
```

これはエラーになります。

---
## static を使うべきかの判断基準

`static` を使うか迷ったら、次のように考えると分かりやすいです。

```txt
その処理は、特定のインスタンスの状態を使うか？
```

使うなら、通常メソッドが向いています。

```ts
class User {
  constructor(public name: string) {}

  greet() {
    return `こんにちは、${this.name}です`
  }
}
```

この `greet` は `this.name` を使います。

つまり、インスタンスごとの状態が必要です。

一方で、インスタンス状態を使わないなら `static` が候補になります。

```ts
class MathUtil {
  static double(value: number) {
    return value * 2
  }
}
```

この `double` は、特定のインスタンスを必要としません。

---
## static を使いすぎるとどうなるか

`static` は便利ですが、使いすぎると問題もあります。

たとえば、何でも static にすると、次のようなコードになりがちです。

```ts
class UserService {
  static users: User[] = []

  static addUser(user: User) {
    this.users.push(user)
  }

  static getUsers() {
    return this.users
  }
}
```

一見便利ですが、これはグローバル変数に近い状態を持っています。

どこからでも変更できる共有状態になるため、次のような問題が起きやすいです。

```txt
どこで値が変わったのか追いにくい
テストしにくい
状態が残り続ける
複数の利用箇所で影響し合う
```

そのため、状態を持つ `static` は慎重に使う必要があります。

---
## Angular では static をどう考えるか

Angular では、サービスを `static` メソッドだけで作るより、DIを使うことが多いです。

```ts
@Injectable({
  providedIn: "root",
})
export class UserService {
  getUsers() {
    return []
  }
}
```

コンポーネントでは、constructor で注入します。

```ts
@Component({
  selector: "app-user-list",
  template: "",
})
export class UserListComponent {
  constructor(private userService: UserService) {}
}
```

このようにすると、Angular がインスタンス管理をしてくれます。

そのため、Angular のアプリケーションロジックでは、何でも `static` にするよりも、DIでサービスとして扱う方が自然なことが多いです。

`static` は、状態を持たない補助関数や定数に使うくらいが扱いやすいです。

---
## static とユーティリティクラス

TypeScript では、次のようなユーティリティクラスを書くことがあります。

```ts
class DateUtil {
  static format(date: Date) {
    return date.toISOString().split("T")[0]
  }
}

console.log(DateUtil.format(new Date()))
```

ただし、JavaScript / TypeScript では、クラスにせず関数として書く選択肢もあります。

```ts
export function formatDate(date: Date) {
  return date.toISOString().split("T")[0]
}
```

そのため、ユーティリティ処理は必ず `static` にする必要はありません。

シンプルな関数として書けるなら、関数で十分なことも多いです。

---
## static が向いている例

`static` が向いているのは、次のようなケースです。

```txt
インスタンスを作る必要がない
クラスに強く関連する処理である
共通の定数を持たせたい
生成処理を分かりやすくしたい
状態を持たない補助処理である
```

例です。

```ts
class User {
  constructor(
    public name: string,
    public role: string
  ) {}

  static createGuest() {
    return new User("Guest", "guest")
  }
}
```

これは、`User` に強く関係する生成処理なので、`static` にする意味があります。

---
## static が向いていない例

一方で、次のようなケースでは注意が必要です。

```txt
インスタンスごとの状態を使う
テストで差し替えたい
外部API通信など副作用が大きい
共有状態をたくさん持つ
DIで管理した方が自然
```

たとえば、次のようなコードです。

```ts
class ApiService {
  static async fetchUsers() {
    const response = await fetch("/api/users")
    return response.json()
  }
}
```

これが絶対に悪いわけではありません。

ただし、アプリ全体で使うAPI通信処理なら、DIできるサービスや関数として管理した方が、テストや差し替えがしやすい場合があります。

---
## static のイメージ

最後に、通常メソッドと static メソッドの違いを図で整理します。

```txt
class User
├─ static createGuest()
├─ static defaultRole
└─ prototype
   └─ greet()

new User("Taro") で作られる user
├─ name: "Taro"
└─ [[Prototype]] → User.prototype
                  └─ greet()
```

呼び出し方はこうです。

```ts
User.createGuest()
User.defaultRole

const user = new User("Taro")
user.greet()
```

`static` はクラス側、通常メソッドはインスタンス側です。

---
## まとめ

`static` は、**インスタンスではなくクラス自身に属するメンバー**を定義するためのキーワードです。

```ts
class User {
  static createGuest() {
    return new User("Guest")
  }

  constructor(public name: string) {}
}

const guest = User.createGuest()
```

通常メソッドとの違いは、呼び出し方です。

```txt
通常メソッド: インスタンス.メソッド()
static メソッド: クラス.メソッド()
```

使いどころとしては、次のようなものがあります。

```txt
ユーティリティ関数
ファクトリーメソッド
共通設定
定数
バリデーション
クラス全体で共有する情報
```

ただし、何でも `static` にすればよいわけではありません。

特に、状態を持つ `static` はグローバル変数に近くなり、テストしにくくなったり、変更箇所を追いにくくなったりします。

判断基準はシンプルです。

```txt
その処理は、特定のインスタンスの状態を使うか？
```

インスタンスの状態を使うなら通常メソッド。

インスタンスを必要としない、クラスに紐づく処理なら `static`。

このように考えると、`static` の使いどころがかなり見えやすくなります。
