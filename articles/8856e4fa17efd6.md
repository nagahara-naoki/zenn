Promiseは、「あとで利用可能になる値」と、その成功・失敗を扱うためのオブジェクトです。

難しく見える原因は、Promiseそのもの、Promiseを作る処理、結果を受け取る処理が同じコードに登場することです。

この記事では、次の順序で整理します。

1. Promiseを返す
2. Promiseが成功または失敗する
3. 呼び出し側が結果を受け取る

## 最初に押さえる形

```js
async function fetchUser(id) {
  const response = await fetch(`/api/users/${id}`);

  if (!response.ok) {
    throw new Error(`ユーザー取得に失敗しました: ${response.status}`);
  }

  return response.json();
}

try {
  const user = await fetchUser(1);
  console.log(user.name);
} catch (error) {
  console.error(error);
}
```

`fetchUser` の戻り値は、ユーザーそのものではなく `Promise` です。`await` は、そのPromiseがsettledになるまで現在のasync関数の続きだけを中断します。

JavaScript全体を停止させるわけではありません。

## Promiseが表す3つの状態

Promiseは、次のいずれかの状態を持ちます。

| 状態 | 意味 |
| --- | --- |
| pending | まだ結果が決まっていない |
| fulfilled | 成功し、値が決まった |
| rejected | 失敗し、理由が決まった |

fulfilledとrejectedを合わせてsettledと呼びます。一度settledになったPromiseの結果は、後から別の結果へ変わりません。

## Promiseを作る

Promiseコンストラクターは、コールバック形式の処理をPromiseへ変換するときなどに使います。

```js
function delay(ms) {
  return new Promise((resolve) => {
    setTimeout(resolve, ms);
  });
}
```

executorと呼ばれる関数は、Promiseを作った時点で同期的に実行されます。

```js
console.log("A");

const promise = new Promise((resolve) => {
  console.log("B");
  resolve("done");
});

console.log("C");

// A → B → C
```

`resolve` 後に登録した `then` のコールバックは、現在実行中のJavaScriptが完了した後に実行されます。

既にPromiseを返すAPIを、改めて `new Promise` で包む必要はありません。

```js
// 不要なラップ
function fetchUserIncorrect(id) {
  return new Promise((resolve, reject) => {
    fetch(`/api/users/${id}`).then(resolve, reject);
  });
}

// そのまま返せる
function fetchUser(id) {
  return fetch(`/api/users/${id}`);
}
```

## thenで値をつなぐ

`then` は新しいPromiseを返します。コールバックの戻り値が、次の `then` へ渡されます。

```js
fetch("/api/users/1")
  .then((response) => {
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    return response.json();
  })
  .then((user) => user.name)
  .then((name) => {
    console.log(name);
  });
```

重要なのは、`then` の中で次の値やPromiseを `return` することです。

```js
fetch("/api/users/1")
  .then((response) => {
    return response.json();
  })
  .then((user) => {
    console.log(user);
  });
```

`return` を忘れると、次の `then` には `undefined` が渡されます。内側で開始した非同期処理もチェーンから切り離され、完了や失敗を追跡できません。

## catchで失敗を扱う

`catch(onRejected)` は、`then(undefined, onRejected)` と同等の働きをします。

```js
fetchUser(1)
  .then((user) => {
    console.log(user.name);
  })
  .catch((error) => {
    console.error("取得に失敗しました", error);
  });
```

チェーンの途中で `throw` されたエラーや、返したPromiseのrejectionも、後続の `catch` へ伝わります。

`catch` の中で値を返すと、そこで失敗を回復したfulfilledなPromiseになります。

```js
const user = await fetchUser(1).catch((error) => {
  console.warn(error);
  return { id: 0, name: "Guest" };
});
```

回復できないエラーをログだけ出して握りつぶすと、呼び出し側は成功と誤認します。処理を継続できない場合は、再度 `throw` します。

## finallyは後始末に使う

`finally` は、成功・失敗のどちらでも実行したい後始末に向いています。

```js
setLoading(true);

fetchUser(1)
  .then(showUser)
  .catch(showError)
  .finally(() => {
    setLoading(false);
  });
```

`finally` は通常、チェーンの成功値や失敗理由を書き換えるためには使いません。

## async / await

`async / await` は、Promiseを別の実行モデルへ変えるものではありません。Promiseチェーンを逐次処理に近い見た目で書く構文です。

```js
async function loadProfile(id) {
  const user = await fetchUser(id);
  const posts = await fetchPosts(id);

  return { user, posts };
}
```

`async` 関数は常にPromiseを返します。

```js
async function getName() {
  return "Taro";
}

const result = getName();
console.log(result instanceof Promise); // true
```

エラーは `try / catch` で扱えます。

```js
async function showProfile(id) {
  try {
    const profile = await loadProfile(id);
    renderProfile(profile);
  } catch (error) {
    renderError(error);
  }
}
```

どの範囲のエラーを回復できるかに合わせて、`try` の範囲を決めます。関数全体を大きな `try` で囲むと、原因ごとの対応が難しくなることがあります。

## 逐次実行と並列実行

次のコードは、1つ目の完了後に2つ目を開始します。

```js
const user = await fetchUser(1);
const settings = await fetchSettings(1);
```

互いに依存しない処理なら、先に両方を開始して `Promise.all` で待てます。

```js
const [user, settings] = await Promise.all([
  fetchUser(1),
  fetchSettings(1),
]);
```

`Promise.all` は、入力のどれか1つがrejectすると、自身もその理由でrejectします。ただし、他の処理を自動でキャンセルするわけではありません。

すべての成否を集めたい場合は `Promise.allSettled` を検討します。

```js
const results = await Promise.allSettled([
  fetchUser(1),
  fetchSettings(1),
]);
```

## setTimeoutとの実行順序

ブラウザーで、同じタスク中に次のコードを実行した場合を考えます。

```js
console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve().then(() => {
  console.log("C");
});

console.log("D");
```

一般的なブラウザーでは、出力は次の順です。

```text
A
D
C
B
```

同期処理の `A` と `D` が先に終わり、Promise reactionのmicrotaskが処理され、その後のtaskでtimer callbackが実行されます。

この説明には「同じtaskで登録した」「ブラウザー環境」という条件があります。Node.jsには複数のevent loop phaseや `process.nextTick` もあるため、「Promiseは常にsetTimeoutより先」と一般化しないようにします。

## Promise自体にキャンセル機能はない

処理を中止したい場合は、APIが提供する仕組みを使います。`fetch` では `AbortController` を利用できます。

```js
const controller = new AbortController();

const request = fetch("/api/users/1", {
  signal: controller.signal,
});

controller.abort();

try {
  await request;
} catch (error) {
  if (error.name !== "AbortError") {
    throw error;
  }
}
```

Promiseを無視することと、背後の処理を停止することは別です。

## よくある問題

### Promiseを値として扱う

```js
const user = fetchUser(1);
console.log(user.name); // userはPromise
```

結果を使う場所で `await` または `then` が必要です。

### awaitをループで直列化する

```js
// 並列でよい処理ならこちら
const users = await Promise.all(ids.map((id) => fetchUser(id)));
```

ただし、大量のリクエストを一度に開始すると負荷が高くなります。並列数の制限が必要な場合は、キューや専用ライブラリを使います。

### catchしない

Promiseの失敗を呼び出し元へ返す設計自体は問題ありません。問題は、最終的にどこでも処理されず、ユーザーへの表示やログにも残らないことです。

## まとめ

Promiseを読むときは、次の3点を追います。

1. どの関数がPromiseを返すか
2. fulfilledの値とrejectedの理由は何か
3. どこで待ち、どこで失敗を処理するか

`async / await` を使っても、戻り値がPromiseであること、独立した処理だけを並列化すること、キャンセルは別の仕組みであることは変わりません。
