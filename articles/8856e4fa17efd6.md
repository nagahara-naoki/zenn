# JavaScriptのPromiseを「処理の順番」から理解する

JavaScriptを学んでいると、かなり早い段階で `Promise` に出会います。

API通信、タイマー処理、ファイル読み込み、DBアクセス、画像の読み込みなど、少し実用的な処理を書こうとすると、ほぼ必ずPromiseが出てきます。

しかし、最初はかなり難しく感じます。

```js
fetch("/api/users")
  .then((response) => response.json())
  .then((users) => {
    console.log(users);
  })
  .catch((error) => {
    console.error(error);
  });
```

このコードを見たときに、

* `then` とは何か
* `catch` はいつ呼ばれるのか
* なぜ普通に `const users = fetch(...)` ではダメなのか
* `async / await` とは何が違うのか
* 結局Promiseは何をしているのか

という疑問が出てきやすいです。

この記事では、Promiseを単なる文法としてではなく、**処理の順番**から理解していきます。

Promiseは難しそうに見えますが、考え方はかなりシンプルです。

> Promiseは、今すぐ終わらない処理の結果を、あとから受け取るための仕組みです。

この感覚を持てると、`then` や `catch`、`async / await` もかなり理解しやすくなります。

---

## Promiseを理解する前に、同期処理を確認する

まず、普通のJavaScriptの処理を見てみます。

```js
console.log("1番目");
console.log("2番目");
console.log("3番目");
```

このコードを実行すると、当然この順番で表示されます。

```txt
1番目
2番目
3番目
```

JavaScriptは、基本的に上から順番に処理を実行します。

```txt
1番目の処理
  ↓
2番目の処理
  ↓
3番目の処理
```

このように、前の処理が終わってから次の処理に進む流れを、**同期処理**と呼びます。

同期処理はとてもわかりやすいです。

上から読んだ順番と、実行される順番がほぼ同じだからです。

---

## 時間のかかる処理は、同期的に待つと困る

では、次のような処理を考えてみます。

```js
console.log("ユーザー情報を取得します");

const user = getUserFromServer();

console.log(user);
console.log("画面を表示します");
```

もし `getUserFromServer()` がサーバーからユーザー情報を取得する処理だった場合、結果が返ってくるまでに時間がかかります。

サーバー通信には、0.1秒で終わることもあれば、1秒以上かかることもあります。

このとき、JavaScriptが完全に処理を止めて待ってしまうと、画面操作も止まってしまいます。

たとえばブラウザで、

* ボタンが押せない
* スクロールできない
* 入力できない
* 画面が固まったように見える

という状態になると困ります。

そこでJavaScriptでは、時間のかかる処理を開始したあと、完了を待っている間にも別の処理を進められるようにします。

これが**非同期処理**です。

---

## 非同期処理は「開始」と「完了」がズレる

非同期処理では、処理を開始したタイミングと、結果を受け取るタイミングがズレます。

たとえば、`setTimeout` を使った例を見てみます。

```js
console.log("1番目");

setTimeout(() => {
  console.log("2番目");
}, 1000);

console.log("3番目");
```

このコードの結果は、次のようになります。

```txt
1番目
3番目
2番目
```

コード上では `2番目` の処理が先に書かれています。

しかし、`setTimeout` の中の処理は1秒後に実行されるため、先に `3番目` が表示されます。

つまり、非同期処理では次のような順番になります。

```txt
1番目を実行
  ↓
2番目の処理を予約
  ↓
3番目を実行
  ↓
1秒後に2番目を実行
```

ここがPromiseを理解する上でとても重要です。

非同期処理は、**その場で結果が返るとは限らない処理**です。

---

## Promiseとは何か

Promiseは、非同期処理の結果を扱うためのオブジェクトです。

もう少し具体的に言うと、Promiseは次のようなものです。

> 今はまだ結果がないけれど、あとで成功か失敗のどちらかになる処理を表すもの

たとえば、API通信を考えてみます。

```js
const result = fetch("/api/users");

console.log(result);
```

`fetch` はPromiseを返します。

ここで `result` に入るのは、ユーザー一覧のデータそのものではありません。

`result` に入るのは、

> サーバー通信が終わったら、あとで結果を返す予定のもの

です。

つまり、Promiseです。

Promiseは「データそのもの」ではなく、**あとでデータが入る予定の箱**のようなものです。

---

## Promiseの基本形

Promiseは、次のように作れます。

```js
const promise = new Promise((resolve, reject) => {
  // 非同期処理を書く
});
```

`new Promise()` の中には関数を渡します。

その関数は、2つの引数を受け取ります。

```js
(resolve, reject) => {
  // ...
}
```

それぞれの意味は次の通りです。

| 名前        | 意味           |
| --------- | ------------ |
| `resolve` | 処理が成功したときに呼ぶ |
| `reject`  | 処理が失敗したときに呼ぶ |

たとえば、1秒後に成功するPromiseを書いてみます。

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve("データ取得成功");
  }, 1000);
});

promise.then((result) => {
  console.log(result);
});
```

実行すると、1秒後に次のように表示されます。

```txt
データ取得成功
```

この流れを整理すると、次のようになります。

```txt
Promiseを作る
  ↓
1秒後にresolveを呼ぶ
  ↓
Promiseが成功状態になる
  ↓
thenの中の処理が実行される
```

ここで大事なのは、`then` はすぐに実行されるのではなく、Promiseが成功したあとに実行されるという点です。

---

## Promiseには3つの状態がある

Promiseには、主に3つの状態があります。

| 状態          | 意味   |
| ----------- | ---- |
| `pending`   | 処理中  |
| `fulfilled` | 成功した |
| `rejected`  | 失敗した |

Promiseを作った直後は、まだ成功も失敗もしていません。

この状態を `pending` と呼びます。

```txt
pending
```

その後、`resolve` が呼ばれると成功状態になります。

```txt
pending → fulfilled
```

一方で、`reject` が呼ばれると失敗状態になります。

```txt
pending → rejected
```

つまりPromiseは、最初は処理中で、最終的に成功か失敗のどちらかになります。

```txt
Promise
  ├─ pending   処理中
  ├─ fulfilled 成功
  └─ rejected  失敗
```

Promiseは一度成功または失敗すると、その状態から変わりません。

`resolve` が呼ばれたあとに `reject` を呼んでも、すでに成功しているため、あとから失敗に変わることはありません。

---

## thenは成功したときに呼ばれる

Promiseが成功したときの処理は、`then` に書きます。

```js
const promise = new Promise((resolve) => {
  resolve("成功しました");
});

promise.then((result) => {
  console.log(result);
});
```

結果は次のようになります。

```txt
成功しました
```

`resolve("成功しました")` の値が、`then` の引数 `result` に渡されます。

```js
resolve("成功しました");
```

この値が、

```js
(result) => {
  console.log(result);
}
```

ここに渡されるイメージです。

つまり、`then` は成功した結果を受け取る場所です。

---

## catchは失敗したときに呼ばれる

Promiseが失敗したときの処理は、`catch` に書きます。

```js
const promise = new Promise((resolve, reject) => {
  reject("失敗しました");
});

promise.catch((error) => {
  console.error(error);
});
```

結果は次のようになります。

```txt
失敗しました
```

`reject("失敗しました")` の値が、`catch` の引数 `error` に渡されます。

実際のAPI通信では、通信エラーやサーバーエラーなどが発生する可能性があります。

そのため、Promiseを使うときは成功時の処理だけでなく、失敗時の処理も書くことが大切です。

```js
fetch("/api/users")
  .then((response) => {
    return response.json();
  })
  .catch((error) => {
    console.error("通信に失敗しました", error);
  });
```

---

## finallyは成功・失敗に関係なく最後に呼ばれる

Promiseには `finally` もあります。

`finally` は、成功しても失敗しても最後に実行されます。

```js
const promise = new Promise((resolve) => {
  resolve("成功");
});

promise
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.error(error);
  })
  .finally(() => {
    console.log("処理が完了しました");
  });
```

結果は次のようになります。

```txt
成功
処理が完了しました
```

たとえば、ローディング表示を消す処理などに使えます。

```js
showLoading();

fetch("/api/users")
  .then((response) => response.json())
  .then((users) => {
    console.log(users);
  })
  .catch((error) => {
    console.error(error);
  })
  .finally(() => {
    hideLoading();
  });
```

成功しても失敗しても、最後にはローディングを消したい。

このような処理に `finally` は向いています。

---

## Promiseチェーンを理解する

Promiseでは、`then` をつなげて書くことができます。

```js
fetch("/api/users")
  .then((response) => {
    return response.json();
  })
  .then((users) => {
    console.log(users);
  });
```

このように、`then` をつなげる書き方をPromiseチェーンと呼びます。

ここで重要なのは、前の `then` の `return` が、次の `then` に渡されるということです。

```js
Promise.resolve(10)
  .then((value) => {
    return value * 2;
  })
  .then((value) => {
    return value + 5;
  })
  .then((value) => {
    console.log(value);
  });
```

この結果は次のようになります。

```txt
25
```

処理の流れはこうです。

```txt
最初の値: 10
  ↓
10 * 2 = 20
  ↓
20 + 5 = 25
  ↓
console.log(25)
```

Promiseチェーンは、非同期処理を順番に実行したいときに便利です。

---

## thenの中でreturnし忘れるとどうなるか

Promiseでよくあるミスが、`then` の中で `return` を忘れることです。

たとえば次のコードを見てください。

```js
fetch("/api/users")
  .then((response) => {
    response.json();
  })
  .then((users) => {
    console.log(users);
  });
```

一見よさそうに見えますが、これは問題があります。

最初の `then` で `response.json()` を呼んでいますが、`return` していません。

```js
.then((response) => {
  response.json();
})
```

この場合、次の `then` に渡される値は `undefined` になります。

正しくは次のように書きます。

```js
fetch("/api/users")
  .then((response) => {
    return response.json();
  })
  .then((users) => {
    console.log(users);
  });
```

また、アロー関数では `{}` を使わなければ暗黙的にreturnできます。

```js
fetch("/api/users")
  .then((response) => response.json())
  .then((users) => {
    console.log(users);
  });
```

Promiseチェーンでは、**次のthenに渡したい値はreturnする**と覚えておくとよいです。

---

## Promiseはすぐに結果を取り出せない

Promiseで最初につまずきやすいのが、次のようなコードです。

```js
function fetchUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve({ name: "Taro" });
    }, 1000);
  });
}

const user = fetchUser();

console.log(user);
```

このコードでは、`console.log(user)` にユーザー情報が表示されると思うかもしれません。

しかし実際には、Promiseオブジェクトが表示されます。

なぜなら、`fetchUser()` はすぐに `{ name: "Taro" }` を返すわけではないからです。

`fetchUser()` が返しているのは、あとでユーザー情報を返す予定のPromiseです。

ユーザー情報を使いたい場合は、`then` で受け取ります。

```js
fetchUser().then((user) => {
  console.log(user);
});
```

結果は1秒後に表示されます。

```txt
{ name: "Taro" }
```

ここがPromiseの大事なポイントです。

> Promiseから値を取り出すには、thenまたはawaitを使う必要があります。

---

## async / await はPromiseを読みやすく書くための構文

Promiseチェーンは便利ですが、処理が増えると読みにくくなることがあります。

```js
fetchUser()
  .then((user) => {
    return fetchPosts(user.id);
  })
  .then((posts) => {
    return fetchComments(posts[0].id);
  })
  .then((comments) => {
    console.log(comments);
  })
  .catch((error) => {
    console.error(error);
  });
```

このように `then` が続くと、処理の流れを追いにくくなることがあります。

そこで使われるのが `async / await` です。

```js
async function main() {
  try {
    const user = await fetchUser();
    const posts = await fetchPosts(user.id);
    const comments = await fetchComments(posts[0].id);

    console.log(comments);
  } catch (error) {
    console.error(error);
  }
}

main();
```

`await` は、Promiseが完了するまで待ち、成功した結果を取り出します。

```js
const user = await fetchUser();
```

これは、

```js
fetchUser().then((user) => {
  // userを使う
});
```

に近い意味です。

ただし、`await` を使うと、同期処理のように上から順番に読めます。

```txt
ユーザーを取得
  ↓
投稿を取得
  ↓
コメントを取得
  ↓
表示
```

このように、`async / await` はPromiseをより読みやすく書くための構文です。

Promiseと別物というより、Promiseを扱いやすくする書き方だと考えると理解しやすいです。

---

## awaitを使うにはasyncが必要

`await` は基本的に `async` 関数の中で使います。

次のようなコードはエラーになります。

```js
const user = await fetchUser();
console.log(user);
```

通常の関数やトップレベルで何も考えずに `await` を使うことはできません。

基本形は次のようになります。

```js
async function main() {
  const user = await fetchUser();
  console.log(user);
}

main();
```

`async` を付けた関数の中では、`await` が使えます。

```js
async function main() {
  // ここではawaitが使える
}
```

また、`async` 関数は必ずPromiseを返します。

```js
async function getNumber() {
  return 10;
}

const result = getNumber();

console.log(result);
```

この `result` は `10` そのものではなく、Promiseです。

値を取り出すには、`then` または `await` を使います。

```js
getNumber().then((value) => {
  console.log(value);
});
```

または、

```js
async function main() {
  const value = await getNumber();
  console.log(value);
}

main();
```

---

## async / await のエラー処理

`then / catch` の場合、エラー処理は `catch` に書きました。

```js
fetchUser()
  .then((user) => {
    console.log(user);
  })
  .catch((error) => {
    console.error(error);
  });
```

`async / await` の場合は、`try / catch` を使います。

```js
async function main() {
  try {
    const user = await fetchUser();
    console.log(user);
  } catch (error) {
    console.error(error);
  }
}

main();
```

`await` しているPromiseが失敗すると、`catch` に処理が移ります。

```js
function fetchUser() {
  return new Promise((resolve, reject) => {
    reject("ユーザー取得に失敗しました");
  });
}

async function main() {
  try {
    const user = await fetchUser();
    console.log(user);
  } catch (error) {
    console.error(error);
  }
}

main();
```

結果は次のようになります。

```txt
ユーザー取得に失敗しました
```

`async / await` を使う場合でも、失敗する可能性がある処理にはエラー処理を書いておくことが大切です。

## Promise.allで複数の非同期処理をまとめる

複数の非同期処理をまとめて実行したい場合は、`Promise.all` が便利です。

たとえば、ユーザー情報と記事一覧を両方取得したい場合を考えます。

```js
const userPromise = fetch("/api/user");
const postsPromise = fetch("/api/posts");

Promise.all([userPromise, postsPromise])
  .then(([userResponse, postsResponse]) => {
    console.log(userResponse);
    console.log(postsResponse);
  })
  .catch((error) => {
    console.error(error);
  });
```

`Promise.all` は、渡したPromiseがすべて成功したときに `then` に進みます。

```txt
ユーザー取得
記事一覧取得
  ↓
両方成功
  ↓
thenを実行
```

`async / await` で書くと、次のようになります。

```js
async function main() {
  try {
    const [userResponse, postsResponse] = await Promise.all([
      fetch("/api/user"),
      fetch("/api/posts"),
    ]);

    console.log(userResponse);
    console.log(postsResponse);
  } catch (error) {
    console.error(error);
  }
}

main();
```

ここで重要なのは、2つの通信を順番に待っているのではなく、同時に開始している点です。

次のように書くと、処理は順番に実行されます。

```js
const userResponse = await fetch("/api/user");
const postsResponse = await fetch("/api/posts");
```

この場合、ユーザー情報の取得が終わってから、記事一覧の取得が始まります。

一方、`Promise.all` を使うと、両方を同時に開始できます。

```js
const [userResponse, postsResponse] = await Promise.all([
  fetch("/api/user"),
  fetch("/api/posts"),
]);
```

2つの処理に依存関係がない場合は、`Promise.all` を使うことで待ち時間を短くできます。

---

## Promise.allは1つでも失敗すると失敗する

`Promise.all` は便利ですが、注意点があります。

渡したPromiseのうち1つでも失敗すると、全体が失敗します。

```js
const promise1 = Promise.resolve("成功1");
const promise2 = Promise.reject("失敗2");
const promise3 = Promise.resolve("成功3");

Promise.all([promise1, promise2, promise3])
  .then((results) => {
    console.log(results);
  })
  .catch((error) => {
    console.error(error);
  });
```

結果は次のようになります。

```txt
失敗2
```

`promise1` と `promise3` は成功していますが、`promise2` が失敗しているため、`Promise.all` 全体は失敗します。

すべての結果を成功・失敗に関係なく受け取りたい場合は、`Promise.allSettled` を使います。

```js
const promise1 = Promise.resolve("成功1");
const promise2 = Promise.reject("失敗2");
const promise3 = Promise.resolve("成功3");

Promise.allSettled([promise1, promise2, promise3]).then((results) => {
  console.log(results);
});
```

`Promise.allSettled` は、すべてのPromiseが完了するまで待ちます。

成功しても失敗しても、それぞれの結果を配列で返します。

---

## 処理の順番を確認する

Promiseを理解する上で、処理の順番を確認することはとても大切です。

次のコードを見てください。

```js
console.log("A");

const promise = new Promise((resolve) => {
  console.log("B");
  resolve();
});

promise.then(() => {
  console.log("C");
});

console.log("D");
```

このコードの結果はどうなるでしょうか。

答えは次の通りです。

```txt
A
B
D
C
```

順番を整理します。

まず、最初に `A` が表示されます。

```js
console.log("A");
```

次に、Promiseを作ったとき、`new Promise` の中の処理はすぐに実行されます。

```js
const promise = new Promise((resolve) => {
  console.log("B");
  resolve();
});
```

そのため、`B` が表示されます。

次に、`then` の中の処理はすぐには実行されません。

```js
promise.then(() => {
  console.log("C");
});
```

Promiseはすでに `resolve` されていますが、`then` のコールバックは現在の同期処理が終わったあとに実行されます。

そのため、先に `D` が表示されます。

```js
console.log("D");
```

最後に `then` の中の `C` が表示されます。

つまり、順番はこうです。

```txt
A
B
D
C
```

ここで覚えておきたいのは、次の2つです。

* `new Promise` の中身はすぐ実行される
* `then` の中身は同期処理が終わったあとに実行される

この違いを理解すると、Promiseの挙動がかなり読みやすくなります。

## setTimeoutとPromiseの順番

もう少し発展した例を見てみます。

```js
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

Promise.resolve().then(() => {
  console.log("C");
});

console.log("D");
```

結果は次のようになります。

```txt
A
D
C
B
```

`setTimeout` の時間は `0` ですが、すぐに実行されるわけではありません。

まず同期処理が実行されます。

```txt
A
D
```

そのあと、Promiseの `then` が実行されます。

```txt
C
```

最後に `setTimeout` が実行されます。

```txt
B
```

そのため、全体の順番は次のようになります。

```txt
A
D
C
B
```

ここは少し難しいですが、最初のうちは次のように覚えておくとよいです。

> Promiseのthenは、今の同期処理が終わったあと、setTimeoutより先に実行されやすい

厳密にはイベントループやマイクロタスクの話になりますが、初心者の段階ではまずこの順番を押さえれば十分です。

## よくあるつまずきポイント

最後に、Promiseでよくあるつまずきポイントを整理します。

### 1. Promiseを値そのものだと思ってしまう

```js
const users = fetchUsers();

console.log(users);
```

この `users` はユーザー一覧ではなく、Promiseです。

結果を使いたい場合は、`then` または `await` を使います。

```js
fetchUsers().then((users) => {
  console.log(users);
});
```

または、

```js
const users = await fetchUsers();
```

### 2. thenの中でreturnし忘れる

```js
fetch("/api/users")
  .then((response) => {
    response.json();
  })
  .then((users) => {
    console.log(users);
  });
```

この場合、次の `then` に `users` は渡りません。

正しくは `return` します。

```js
fetch("/api/users")
  .then((response) => {
    return response.json();
  })
  .then((users) => {
    console.log(users);
  });
```

### 3. awaitを使っているのにasyncを付けていない

```js
function main() {
  const users = await fetchUsers();
}
```

`await` を使う関数には `async` を付けます。

```js
async function main() {
  const users = await fetchUsers();
}
```

### 4. エラー処理を書いていない

API通信などは失敗する可能性があります。

```js
const users = await fetchUsers();
```

これだけだと、失敗したときの処理がありません。

実用的なコードでは、`try / catch` を使います。

```js
async function main() {
  try {
    const users = await fetchUsers();
    console.log(users);
  } catch (error) {
    console.error("ユーザー取得に失敗しました", error);
  }
}
```

### 5. 並列でよい処理を順番に待ってしまう

依存関係がない処理を順番に待つと、無駄な待ち時間が発生します。

```js
const user = await fetchUser();
const settings = await fetchSettings();
```

この2つに依存関係がないなら、`Promise.all` を使えます。

```js
const [user, settings] = await Promise.all([
  fetchUser(),
  fetchSettings(),
]);
```

---

## まとめ

Promiseは、最初は難しく見えます。

`then`、`catch`、`finally`、`async`、`await`、`Promise.all` など、関連する構文が多いからです。

しかし、Promiseの中心にある考え方はシンプルです。

> Promiseは、今すぐ終わらない処理の結果を、あとから受け取るための仕組みです。

この記事で見てきたポイントを整理します。

* JavaScriptは基本的に上から順番に処理を実行する
* 時間のかかる処理は非同期で扱う
* 非同期処理は開始と完了のタイミングがズレる
* Promiseは、あとで成功または失敗する処理を表す
* 成功したら `then`
* 失敗したら `catch`
* 最後に必ず実行したい処理は `finally`
* `then` の戻り値は次の `then` に渡される
* Promiseから値を取り出すには `then` または `await` を使う
* `async / await` はPromiseを読みやすく書くための構文
* 複数の非同期処理をまとめるなら `Promise.all` が使える
* `new Promise` の中身はすぐ実行されるが、`then` の中身はあとで実行される

Promiseを理解すると、JavaScriptの非同期処理がかなり読みやすくなります。

特にAPI通信を書くときに、

```js
const response = await fetch("/api/users");
const users = await response.json();
```

このようなコードの意味が自然に追えるようになります。

Promiseは、JavaScriptで実用的なアプリケーションを書く上で避けて通れない仕組みです。

最初からすべてを完璧に理解する必要はありません。

まずは、

> Promiseは「あとで結果が返る処理」

というイメージを持つところから始めると、`then` や `async / await` の理解が一気に進みます。
