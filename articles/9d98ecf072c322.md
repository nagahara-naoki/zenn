エンジニア求人を探していると、同じ求人が複数の媒体に載っていて、少しずつ内容が違うことがあります。どれが企業の書いた情報なのか、給与や働き方をどの項目で比べればよいのか。求人を開くたびに読み替えるのは、思った以上に手間がかかります。

そこで、企業の公式採用ページから取得したエンジニア求人だけを集める検索サービス「OpenIndex」を公開しました。

https://open-index.dev/

![OpenIndexのトップページ。使う技術から次の仕事を選ぶというメッセージと、掲載企業・求人・技術タグの件数を表示している](/images/openindex/launch.jpg)

OpenIndexが目指したのは、企業の一次情報を同じ物差しで比べられる索引です。**検索の起点は、技術です。**

数字は日々変わります。2026年8月1日時点では、1,504社、公開中の求人6,915件、技術タグ79種を掲載しています。最新の件数はサイト上でご確認ください。

## 公式情報を探し直す手間を減らしたかった

求人媒体には、複数企業を一度に比較できる便利さがあります。一方で、応募を検討する段階では、給与の注記や勤務地の範囲、リモート勤務の条件を確認するために、企業の採用ページをもう一度開くことがあります。同じ求人が複数の媒体に掲載され、更新時期によって説明が異なるケースもあります。

OpenIndexでは、最初から企業の公式採用ページを起点にしました。取得した内容を共通の項目へ整理しつつ、求人詳細には必ず取得元へのリンクを残します。OpenIndexだけで情報を閉じず、原文へ戻れることを優先しています。

サービス内で応募を受け付けたり、企業を評価したりはしません。口コミや転職支援も扱いません。役割を「公式情報を見つけ、比較し、元ページへ案内するところ」までに絞っています。

## 技術・職種・働き方を組み合わせて探せます

求人一覧では、職種、技術スタック、年収下限を指定できます。さらに、都道府県、リモート可否、雇用形態で絞り込めます。キーワード検索の対象は求人タイトル、企業名、職種、技術です。

| 条件 | 探せる内容 |
| --- | --- |
| キーワード | 求人タイトル、企業名、職種、技術。空白で区切った語はすべて含む求人を探す |
| エンジニア職種 | バックエンド、フロントエンド、SRE、QA、AIエンジニアなど |
| 技術スタック | 言語、フレームワーク、クラウド、データベース、開発ツール |
| 年収 | 300万〜1,000万円の範囲から下限を指定 |
| 詳細条件 | 都道府県、フルリモート・ハイブリッドなどの働き方、雇用形態 |

たとえばSREを選ぶと、会社ごとに表記の異なる求人を、同じ一覧で見比べられます。複数の技術を選んだ場合は、選んだ技術をすべて含む求人だけが残ります。検索条件はURLにも反映されるので、そのまま共有できます。

「PythonとAWSを使う」「東京都または神奈川県」「リモート可」といった条件を重ねても、結果件数はその場で更新されます。条件を外すと一覧もすぐに戻るため、最初から条件を決め切らず、候補を広げたり狭めたりしながら探せます。

![SREで絞り込んだOpenIndexの求人一覧。企業名、求人名、技術タグ、給与を共通の形式で表示している](/images/openindex/jobs.jpg)

並び順の初期値は「おまかせ」です。訪問ごとに順番を変え、特定の企業ばかりが先頭に出続けないようにしています。目的が決まっている場合は「新しい順」「企業名順」に切り替えられます。広告枠や掲載料による順位の優遇はありません。

## 求人詳細から企業の原文へ戻れます

求人詳細では、取得できた範囲で次の情報を整理しています。

- 給与
- 勤務地と働き方
- 雇用形態
- 使用する技術
- 必須条件と歓迎条件
- 福利厚生・待遇
- 公式ページから取得した日と、初めて掲載を確認した日

給与は正規化した金額だけでなく、公式ページに書かれていた元の表記も併記します。仕事内容は短い要約で全体をつかみ、必要になったら「募集要項の全文を見る」を開けます。要約だけを読んで応募条件を判断しないよう、公式ページへの導線を目立つ位置に置きました。

応募先は企業です。求人詳細の「公式ページを開く」から、企業の採用ページへ移動します。OpenIndex内に応募機能や会員登録はありません。応募と募集状況の最終確認も、企業の公式ページで行います。

保存にログインはいりません。気になった求人は「あとで見る」に保存できます。保存先はブラウザー内です。2件以上保存すると、給与、勤務地、働き方、雇用形態、職種、技術スタックを横に並べる「比べる」表示も使えます。

保存したIDは端末内にだけ残り、サーバー側に利用者のアカウントを作りません。掲載を確認できなくなった求人が保存リストに残っている場合は、その件数を知らせ、リストから整理できるようにしています。

## 企業を、求人と技術記事の両方から見られます

企業一覧には、事業内容、募集中の職種、求人に登場する技術、募集件数を表示しています。企業詳細を開けば、その会社の求人だけをまとめて確認できます。

企業名を知らない段階では、求人一覧から技術や職種で探します。気になる求人が見つかった後は企業詳細へ移り、その会社がほかに募集している職種や、求人全体でよく使われている技術を確認できます。「求人を探す」と「会社を知る」を往復できる構成です。

もう一つ、企業のテックブログも索引化しました。2026年8月1日時点では、71社から1,663件の記事を収録しています。会社名やキーワードに加え、記事タイトルと抜粋に登場する技術名でも絞り込めます。

![OpenIndexの企業テックブログ一覧。会社をまたいで新着記事を検索し、技術名で絞り込める](/images/openindex/blogs.jpg)

企業詳細には、その会社の新着技術記事も表示します。「求人票からは分からない開発の雰囲気を、実際の記事から知る」という流れを、同じ企業ページの中でつなげました。記事は元サイトで読みます。OpenIndexには本文を転載していません。

テックブログ一覧では、会社をまたいで新着順に読めます。たとえばGoやTypeScriptを選ぶと、その技術が記事タイトルや抜粋に登場する記事だけが残ります。特定企業の記事を続けて読みたい場合は、企業詳細からその会社で絞り込んだ一覧へ移動できます。

## 掲載データの傾向も公開しています

「データ」ページでは、掲載中の求人を次の切り口で可視化しています。

- 推定年収の分布
- 職種の分布
- 求人によく登場する技術の上位15件
- 勤務地の分布
- 雇用形態と働き方の内訳

![OpenIndexのデータページ。公開中の求人・企業・職種・技術タグの件数と、推定年収の分布を表示している](/images/openindex/stats.jpg)

同日時点では、年収を集計できた3,630件の下限中央値が約500万円で、最も件数が多いのも500万円台でした。月給は12倍して年収へ換算し、時給や給与記載のない求人、抽出ノイズを避けるため年収300万円未満の値は集計から外しています。

職種と技術の上位は次のとおりでした。技術は1件の求人に複数付くため、件数を合計しても求人総数とは一致しません。

| 順位 | 職種 | 求人数 | 技術 | 登場する求人数 |
| ---: | --- | ---: | --- | ---: |
| 1 | バックエンド | 1,332 | AWS | 2,857 |
| 2 | フロントエンド | 654 | Python | 2,026 |
| 3 | エンジニアリングマネージャー | 572 | Java | 1,847 |
| 4 | アーキテクト | 540 | Azure | 1,649 |
| 5 | インフラ | 431 | Google Cloud | 1,366 |

勤務地を都道府県として読み取れた求人は5,677件でした。上位は東京都4,462件、大阪府1,103件、愛知県865件、神奈川県709件です。1件の求人に複数勤務地が書かれている場合は、それぞれに数えています。

働き方を確認できた2,997件の内訳は、リモート可1,399件、ハイブリッド949件、フルリモート446件、出社203件でした。「リモート可」が出社頻度まで保証するわけではないため、具体的な勤務条件は求人詳細から公式ページへ進んで確認する必要があります。

集計には限界があります。この統計は、OpenIndexに掲載している求人の内訳です。転職市場全体の傾向を示すものではありません。掲載企業の偏りや、同じ企業が複数の求人で同じ給与を提示する影響も受けます。

## 公式サイトの探索から公開までを自動化しました

求人が掲載されるまでの流れは、次のようになっています。

```mermaid
flowchart LR
    A[企業の公式サイト] --> B[採用ページを探索]
    B --> C[求人候補を抽出]
    C --> D[職種・技術・給与などを正規化]
    D --> E[重複と掲載状態を確認]
    E --> F[(Turso)]
    F --> G[Hono API / Cloudflare Workers]
    G --> H[Reactの検索画面]
```

クローラーは、取得前にURLの安全性と`robots.txt`を確認します。そのうえで、公開求人API、`JobPosting`のJSON-LD、HTML内のデータ、一般的なHTMLの順に求人を探します。静的な取得で情報が足りないページに限り、ブラウザーで描画して確認します。

収集と判定にはAIやLLMを使っていません。URL、HTML、JSON、求人項目に対する決定論的なルールで処理しています。見つけただけでは公開しません。企業名、職種、URL、内容の重複を確認してから掲載データへ加えます。

テックブログ側では、企業サイトのリンクや既知のサブドメインなどからブログ候補を探し、フィード本文で技術ブログかどうかを判定します。別会社のブログを誤って紐づけないよう、ドメイン、企業サイトへの逆リンク、企業名も確認します。

公開部分はReactとHono、Cloudflare Workers、Tursoで構成しました。ブラウザーからデータベースへ直接接続せず、同一オリジンのHono APIを経由します。一覧用データはCloudflare側でキャッシュし、検索や絞り込みのたびにデータベースを読まないようにしています。

## 自動収集だからこそ、取得日と訂正窓口を用意しています

公式ページを起点にしていても、掲載内容が常に正しいとは限りません。巡回はリアルタイムではなく、本文からの項目抽出にも取り違えが起こり得ます。そのため、各求人に取得日を表示し、募集状況と条件は公式ページで確認するよう案内しています。

求人詳細の「掲載内容の誤りを知らせる」を押すと、対象求人と現在の掲載内容が入った問い合わせ画面へ移動します。掲載情報の修正・削除、求人掲載の相談、不具合の報告も受け付けています。

まずは、普段使っている技術名で検索してみてください。企業名から探すのとは違う顔ぶれが見つかるかもしれません。
