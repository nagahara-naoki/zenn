JavaScriptには、関数宣言、関数式、アロー関数、メソッド、コールバック、高階関数、純粋関数など、多くの名前があります。どれを選ぶべきか迷う原因は、これらが同じ分類軸の用語ではないことです。

先に結論を述べると、関数は次の3軸を分けると整理できます。

1. **どう作るか**：関数宣言、関数式、アロー関数、メソッド構文。
2. **どう使うか**：通常の呼び出し、コールバック、高階関数、constructor。
3. **どんな性質か**：同期・非同期、純粋・副作用あり、generatorなど。

例えば、アロー関数で書いた純粋なコールバックは、3軸すべての説明を同時に満たします。「アロー関数とコールバックのどちらを使うか」と比較する必要はありません。

この記事では、注文金額を計算する処理を少しずつ設計しながら、構文の違い、引数と戻り値、`this`、高階関数、非同期処理、設計とテストまで説明します。構文の暗記ではなく、意図に合う関数を選べることが目標です。

## 最初に選び方をまとめる

一般的なアプリケーションコードでは、次を起点にすると十分です。

| 表現したいこと | 候補 | 理由 |
| --- | --- | --- |
| 名前のある主要処理 | 関数宣言 | 名前と処理のまとまりが明確 |
| 値として渡す短い処理 | アロー関数 | コールバックとして簡潔 |
| `this` を使うオブジェクト操作 | メソッド構文 | 所有者と操作を一緒に表せる |
| 条件によって実装を選ぶ | 関数式 | 関数を値として代入できる |
| 非同期結果を返す | `async` 関数 | Promiseの連鎖を直線的に書ける |
| 複数の値を順番に生成する | generator関数 | 反復プロトコルを実装できる |

これは絶対規則ではありません。最優先は、呼び出し側が「何を渡し、何が返り、失敗時にどうなるか」を理解できることです。短さだけで構文を決めず、`this`、`new`、巻き上げ、デバッグ時の名前といった意味の違いを確認します。

## 関数宣言は名前のある処理を示す

関数宣言は `function`、名前、仮引数、関数本体で構成されます。注文小計を計算する関数を作ります。

```js
function calculateSubtotal(items) {
  return items.reduce(
    (sum, item) => sum + item.unitPrice * item.quantity,
    0,
  );
}

const subtotal = calculateSubtotal([
  { unitPrice: 1200, quantity: 2 },
  { unitPrice: 300, quantity: 1 },
]);

console.log(subtotal); // 2700
```

関数宣言は、同じスコープのコードを評価する前に関数オブジェクトまで初期化されるため、宣言より前から呼べます。主要な流れを先に、補助関数を下に置く構成も可能です。ただし、関数が参照する外部の `let` や `const` まで初期化済みとは限りません。

名前は実装より契約を表します。`calc` より `calculateSubtotal`、`handle` より `handleCheckoutSubmit` の方が、何をする関数か検索しやすくなります。戻り値が真偽なら `is`、`has`、`can`、副作用なら `save`、`send`、`render` など、プロジェクト内で語彙を揃えます。

## 関数式は関数を値として扱う

関数式は関数オブジェクトを式として作り、変数やプロパティへ代入できます。条件に応じて割引計算を選ぶ例です。

```js
const calculateDiscount = campaignEnabled
  ? function campaignDiscount(subtotal) {
      return Math.min(subtotal * 0.2, 2000);
    }
  : function noDiscount() {
      return 0;
    };

const discount = calculateDiscount(2700);
```

右辺の関数に名前を付けた「名前付き関数式」にすると、スタックトレースで意図が分かりやすく、関数内部から再帰的に参照もできます。現代のエンジンは代入先から名前を推測する場合がありますが、重要な処理へ明示名を付ける価値は残ります。

`const` へ代入した関数式は、宣言を評価する前には使えません。関数宣言と関数式は見た目だけでなく、利用可能になる時点が異なります。また、`const` が禁止するのは変数への再代入であり、関数オブジェクト自体が完全に不変になるわけではありません。

## アロー関数は短い関数式以上の違いを持つ

アロー関数は、値として渡す短い変換を簡潔に書けます。式本体なら式の結果を暗黙にreturnします。

```js
const lineTotals = items.map(
  (item) => item.unitPrice * item.quantity,
);

const positiveItems = items.filter(
  (item) => item.quantity > 0,
);
```

ただし、アロー関数は通常関数を短くしただけではありません。自身の `this`、`arguments`、`super`、`new.target` bindingを作らず、外側のものをレキシカルに参照します。constructorとして `new` で呼べず、通常は `prototype` プロパティも持ちません。

```js
const calculator = {
  taxRate: 0.1,

  // 外側はメソッドなので、呼び出し時にthisを受け取る
  calculate(items) {
    return items
      .map((item) => item.unitPrice * item.quantity)
      .map((amount) => amount * (1 + this.taxRate));
  },
};
```

内側のアロー関数は、`calculate` メソッドの `this` を使います。反対に、オブジェクトのメソッドそのものをアロー関数にすると、オブジェクトを `this` として受け取りません。

```js
const badCalculator = {
  taxRate: 0.1,
  calculate: (amount) => amount * (1 + this.taxRate),
};
```

`this` が不要な変換にはアロー関数、呼び出したオブジェクトを `this` として使う操作にはメソッド構文、という分け方が実用的です。

## オブジェクトのメソッドは状態の所有者を示す

オブジェクトリテラルのメソッド構文は、データと操作を一緒に表します。注文計算の設定を持つcalculatorを作ります。

```js
const priceCalculator = {
  taxRate: 0.1,

  subtotal(items) {
    return items.reduce(
      (sum, item) => sum + item.unitPrice * item.quantity,
      0,
    );
  },

  total(items, discount = 0) {
    const subtotal = this.subtotal(items);
    return Math.floor((subtotal - discount) * (1 + this.taxRate));
  },
};
```

メソッドの `this` は通常、定義したオブジェクトではなく呼び出し方で決まります。`priceCalculator.total()` なら `this` は `priceCalculator` ですが、メソッドだけ取り出して `const total = priceCalculator.total; total(...)` と呼ぶと関連が外れます。

状態を使わない計算までメソッドにする必要はありません。純粋な計算関数を独立させると、所有者に依存せず再利用・テストできます。オブジェクトにまとめるのは、設定や状態と操作の関係がドメイン上明確な場合です。

## 引数は関数の契約

JavaScriptは、仮引数の個数と実引数の個数が一致しなくても呼び出せます。足りない引数は `undefined`、余分な引数は通常無視されます。柔軟ですが、検証しないと誤りが計算の後半まで伝わります。

```js
function calculateLineTotal(unitPrice, quantity) {
  if (!Number.isFinite(unitPrice) || unitPrice < 0) {
    throw new TypeError("unitPriceには0以上の有限数が必要です");
  }
  if (!Number.isInteger(quantity) || quantity <= 0) {
    throw new TypeError("quantityには正の整数が必要です");
  }

  return unitPrice * quantity;
}
```

関数内部ですべてを検証すべきとは限りません。外部入力を受ける境界では厳密に検証し、信頼できる内部値だけを扱う小さな関数では型や上位の検証を契約としてもよいでしょう。重要なのは検証責任を曖昧にしないことです。

引数が増え、同じ型の値が並ぶならオプションオブジェクトが読みやすくなります。分割代入、デフォルト値、rest parametersを組み合わせられます。

```js
function calculatePrice({
  items,
  taxRate = 0.1,
  discount = 0,
  shipping = 0,
}) {
  const subtotal = calculateSubtotal(items);
  const taxable = Math.max(0, subtotal - discount);
  return Math.floor(taxable * (1 + taxRate)) + shipping;
}

const total = calculatePrice({
  items,
  discount: 500,
  shipping: 600,
});
```

デフォルト引数が使われるのは、引数が省略された場合か明示的に `undefined` の場合です。`null`、`0`、空文字列には適用されません。`null` を「未指定」と扱うなら、APIの境界で明示的に正規化します。

rest parametersは可変個の引数を配列として受け取ります。古い `arguments` と異なり、本物の配列で、アロー関数でも利用できます。

```js
function sum(...amounts) {
  return amounts.reduce((total, amount) => total + amount, 0);
}

console.log(sum(1200, 300, 500)); // 2000
```

ただし、呼び出し側がすでに配列を持つなら、配列を一つ受け取るAPIの方が型と意味を表しやすいことがあります。構文の便利さより、データが何を表すかで決めます。

## returnは値と制御を呼び出し元へ戻す

`return` がない関数、または値なしの `return` は `undefined` を返します。改行位置にも注意が必要です。自動セミコロン挿入により、`return` の直後で改行するとそこでreturnしたと解釈されます。

```js
function createSummary(order) {
  return {
    id: order.id,
    total: order.total,
  };
}

const toSummary = (order) => ({
  id: order.id,
  total: order.total,
});
```

アロー関数でオブジェクトリテラルを暗黙returnするには丸括弧で囲みます。`(order) => { id: order.id }` の波括弧は関数本体として解釈され、オブジェクトを返しません。

一つの関数が場面によって数値、`null`、`undefined`、例外を返すと、呼び出し側の分岐が複雑になります。見つからない場合を `undefined` で表す、業務上の失敗を結果オブジェクトで表す、契約違反は例外にするなど、戻り値の形を一貫させます。

## コールバックは「後で呼ばれる関数」だけではない

別の関数へ引数として渡され、決められた契約で呼ばれる関数がコールバックです。同期的な `map` のコールバックも、クリック時に呼ばれるイベントハンドラーも該当します。

```js
function applyPriceRule(items, rule) {
  return items.map((item, index) => {
    const amount = calculateLineTotal(item.unitPrice, item.quantity);
    return {
      ...item,
      amount: rule(amount, item, index),
    };
  });
}

const discounted = applyPriceRule(
  items,
  (amount, item) => item.category === "book" ? amount * 0.9 : amount,
);
```

`applyPriceRule` は関数を受け取るので高階関数です。渡す側は、引数の順番、戻り値の用途、同期か非同期か、例外をどう扱うかというコールバック契約を理解する必要があります。

配列メソッドへ既存関数を直接渡すとき、余分な引数が問題になる場合があります。`map` は要素だけでなくindexと配列も渡します。受け取る関数のシグネチャが一致するか確認し、必要ならアロー関数で包みます。

```js
const texts = ["10", "11", "12"];

const wrong = texts.map(parseInt);
// parseInt(value, index)として呼ばれ、基数が0, 1, 2になる

const numbers = texts.map((text) => Number.parseInt(text, 10));
```

コールバックを渡すのか、その場で実行した結果を渡すのかも区別します。`addEventListener("click", handleClick())` は戻り値を渡してしまいます。登録したいなら `handleClick` を渡します。

## 純粋関数と副作用の境界を作る

同じ入力に同じ結果を返し、外部状態を変更しない関数を純粋関数と呼びます。価格計算は純粋に保ち、通信や画面更新を外側へ分けるとテストが簡単になります。

```js
function buildOrder({ items, discount = 0, taxRate = 0.1 }) {
  const subtotal = calculateSubtotal(items);
  const taxable = Math.max(0, subtotal - discount);

  return {
    items: items.map((item) => ({ ...item })),
    subtotal,
    discount,
    tax: Math.floor(taxable * taxRate),
    total: Math.floor(taxable * (1 + taxRate)),
  };
}

async function submitOrder(input, saveOrder) {
  const order = buildOrder(input);
  await saveOrder(order);
  return order;
}
```

`buildOrder` は計算だけなので多数の条件を高速にテストできます。`submitOrder` は外部I/Oという副作用を担います。すべての関数を純粋にすることは目的ではありません。アプリは保存、通信、表示を行う必要があります。副作用の場所を境界へ寄せ、計算との混在を減らすことが重要です。

引数の配列やオブジェクトを直接変更すると、呼び出し元へ見えない副作用を作ります。性能上の理由で破壊的変更が必要なら、`sortInPlace` のように名前や契約で明示し、所有権を共有しない設計にします。

## async関数は戻り値をPromiseにする

`async` 関数は必ずPromiseを返します。通常値をreturnするとその値でfulfilled、例外を投げるとrejectedになります。呼び出し側はreturnされたPromiseをawaitするか、次の層へreturnします。

```js
async function submitOrder(input, { saveOrder, notify }) {
  const order = buildOrder(input);
  const savedOrder = await saveOrder(order);
  await notify(savedOrder.id);
  return savedOrder;
}

try {
  const saved = await submitOrder(input, services);
  renderSuccess(saved);
} catch (error) {
  renderFailure(error);
}
```

よくある失敗は、`map` へasync関数を渡して得た `Promise[]` を、完成した値の配列だと思うことです。すべて必要なら `Promise.all` で待ちます。

```js
const itemPromises = items.map(async (item) => {
  const stock = await fetchStock(item.id);
  return { ...item, stock };
});

const itemsWithStock = await Promise.all(itemPromises);
```

独立した通信ならこの並行実行が効率的です。件数が非常に多い場合は同時実行数を制限します。順番に前の結果を使う処理なら、`for...of` と `await` が意図を明確にします。「awaitは遅い」ではなく、依存関係に合う待ち方を選びます。

## generator関数は複数の値を段階的に返す

`function*` で定義するgenerator関数は、呼び出すとiteratorを返します。`yield` ごとに中断・再開でき、一連の値を遅延生成できます。

```js
function* orderIdSequence(prefix = "order") {
  let number = 1;

  while (true) {
    yield `${prefix}-${number}`;
    number += 1;
  }
}

const ids = orderIdSequence();
console.log(ids.next().value); // order-1
console.log(ids.next().value); // order-2
```

通常関数が一回の呼び出しで一つの結果を返すのに対し、generatorは反復プロトコルに沿って複数結果を供給します。単純な配列変換に使うと学習コストが増えるため、巨大・無限の列、探索、状態機械など、遅延評価が設計を明確にする場面で選びます。非同期に複数値が届く場合はasync generatorも候補です。

## 関数はオブジェクトでもある

JavaScriptの関数は呼び出し可能なオブジェクトです。変数へ代入し、配列へ入れ、引数・戻り値として渡し、プロパティを持てます。この性質が高階関数やコールバックを可能にします。

```js
function calculateSubtotal(items) {
  return items.reduce(
    (sum, item) => sum + item.unitPrice * item.quantity,
    0,
  );
}

calculateSubtotal.description = "注文商品の小計を計算する";

console.log(calculateSubtotal.name);   // calculateSubtotal
console.log(calculateSubtotal.length); // 1
```

`name` や `length` はデバッグやメタプログラミングの手掛かりですが、業務上の型契約を保証しません。関数へ可変設定を直接生やすと依存が見えづらいため、通常は設定を引数やファクトリーで渡します。

通常の関数は呼び出し方によって `this` が決まり、constructableな関数なら `new` でも呼べます。しかし「普通の処理関数」と「constructor」の両方として使える柔軟さは誤用を招きます。インスタンス生成が目的ならclassや明確なファクトリー関数を選びます。

## 読みやすい関数を設計する

関数の品質は行数だけでは決まりません。次の問いで責務を確認します。

- 名前だけで、観測可能な結果を説明できるか。
- 入力、戻り値、失敗の契約が一貫しているか。
- 計算と通信、保存、DOM更新が不必要に混ざっていないか。
- 外側の可変状態や `this` へ暗黙に依存しすぎていないか。
- 抽象化したコールバックの契約が、直接書くより理解しやすいか。

長い関数を機械的に5行ずつへ分割すると、処理を追うためのジャンプが増えます。名前を付けることでドメイン上の意味が生まれる部分、独立してテストしたい計算、外部I/Oの境界で分けます。反対に、一度しか使わず意味も増えない一行を関数へ切り出す必要はありません。

引数が増え続ける場合、関数が複数の責務を持っていないか確認します。単にオプションオブジェクトへ詰め替えるだけでは複雑さは消えません。値のまとまりがドメイン概念ならオブジェクトにし、ライフサイクルを持つ状態と多数の操作があるならclassや専用モジュールも検討します。

## デバッグとテストの確認順

関数が期待と違う結果を返すときは、次の順で確認します。

1. どの関数オブジェクトを実際に呼んだか、名前と定義元を確認する。
2. 引数の個数、型、`undefined` と `null`、デフォルト値を確認する。
3. すべての分岐が同じ種類の値をreturnしているか確認する。
4. メソッドなら、呼び出し時の `this` が外れていないか確認する。
5. コールバックの引数と戻り値の契約を確認する。
6. async関数のPromiseをreturnまたはawaitしているか確認する。
7. 入力オブジェクトを意図せず変更していないか確認する。

純粋な計算関数は、境界値を表にしてテストします。空配列、数量1、割引が小計を超える場合、端数、無効な値を含めます。副作用を持つ関数は依存を引数で渡し、呼び出された内容と失敗時の振る舞いを検証します。

```js
const order = buildOrder({
  items: [{ unitPrice: 1000, quantity: 2 }],
  discount: 500,
  taxRate: 0.1,
});

console.assert(order.subtotal === 2000);
console.assert(order.tax === 150);
console.assert(order.total === 1650);
```

実務ではテストランナーの比較機能を使い、浮動小数点や通貨の丸め規則も明示します。コードカバレッジだけでなく、関数の契約として重要な例を読めるテスト名にします。

## まとめ

JavaScriptの関数用語は、一列の「種類」ではありません。関数宣言やアロー関数は作り方、コールバックや高階関数は使い方、純粋関数やasync関数は性質を説明します。軸を分ければ、用語に迷わず設計上の判断へ集中できます。

- 名前のある主要処理には関数宣言、値として渡す短い処理にはアロー関数を起点にする。
- `this` を使う操作にはメソッド構文を使い、アロー関数との意味の違いを理解する。
- 引数、戻り値、例外、同期・非同期を関数の契約として揃える。
- 高階関数では、渡すコールバックの引数と戻り値を明確にする。
- 計算を純粋に保ち、通信や画面更新などの副作用を境界へ寄せる。
- async関数が返すPromiseを所有し、必要な場所でawaitと失敗処理を行う。

最適な構文を探すことより、「この関数は何を知り、何を変え、呼び出し元へ何を約束するか」を説明できることが重要です。その契約が明確なら、関数は短さを競わなくても、読みやすく安全な部品になります。
