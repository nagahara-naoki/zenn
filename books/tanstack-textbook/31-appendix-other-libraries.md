本編で扱わなかったライブラリを紹介します。名前と役割を知っておけば、必要になったときに調べられます。

バージョンは執筆時点のものです。0系のものは、APIが変わる可能性を見込んで採用を判断してください。

## 安定度の見取り図

| ライブラリ | バージョン | 位置付け |
|---|---|---|
| Query | v5系 | 安定。実務での採用例が多い |
| Router | v1系 | 安定 |
| Table | v8系・v9系 | どちらも安定。v9は2026年8月公開 |
| Form | v1系 | 安定 |
| Virtual | v3系 | 安定 |
| Start | v1系（RC） | リリース候補 |
| Store | 0系 | 各ライブラリの内部基盤 |
| DB | 0系 | ベータ |
| Pacer | 0系 | ベータ |
| AI | 0系 | ベータ |
| Charts | 0系 | 開発の動きが緩やか |

判断の目安は、メジャーバージョンが1以上になっているかどうかです。0系は破壊的変更が入りえます。試す価値はありますが、長く保守するコードの土台に据えるのは慎重に判断してください。

## TanStack Store

フレームワークに依存しない、小さなリアクティブストアです。

TanStack Query、Router、Table、Formの内部で使われています。各ライブラリが「状態が変わったらコンポーネントに知らせる」仕組みを、共通の部品で実現するためのものです。

アプリの状態管理ライブラリとして前面に出す設計ではありません。UI状態をグローバルに持ちたい場合は、Contextか、その用途に特化したライブラリを検討するほうが素直です。

Table v9では、テーブルの状態管理がこのStoreの上に載りました。細かい購読ができるようになり、再描画の範囲が狭くなっています。

## TanStack DB

クライアント側にデータベースのような層を作るライブラリです。

TanStack Queryが「サーバーのデータをキャッシュする」のに対して、DBは「クライアント側にコレクションを持ち、その上でクエリを実行する」という考え方です。

- コレクションにデータを保持する
- SQLに似た形で問い合わせる（結合や集計ができる）
- 変更を即座に反映し、サーバーとの同期は裏で行う
- 差分の同期に対応する

オフライン対応、リアルタイムな共同編集、複雑な絞り込みをクライアント側で行うアプリに向いています。TanStack Queryと併用でき、Queryが取得したデータをDBのコレクションに載せる形になります。

ベータ段階なので、まずは小さな画面で試すのが安全です。

## TanStack Pacer

時間に関わる制御をまとめたライブラリです。

| 機能 | 用途 |
|---|---|
| デバウンス | 入力が止まってから処理する |
| スロットル | 一定間隔に間引く |
| レート制限 | 単位時間あたりの実行回数を抑える |
| キュー | 順番に実行する |
| バッチ処理 | まとめて実行する |

本編では、キーワード検索のデバウンスを自分で書く前提にしていました。この種の処理を複数の画面で使うなら、Pacerに寄せると実装がそろいます。

TanStack Queryと組み合わせて「入力が止まってから取得する」を宣言的に書けます。

## TanStack AI

AIモデルとの連携を扱うライブラリです。ストリーミングでの応答表示、会話の状態管理、ツール呼び出しに対応します。

特定のモデル提供者に縛られない設計になっているのが特徴です。チャットのUIを自分で組み立てる前提（Headless）なので、TableやFormと同じ感覚で使えます。

チャット機能を実装する場合、ストリーミングの扱いや中断の処理を自分で書くのは手間がかかります。その部分を引き受けてくれる位置付けです。

## TanStack Charts

グラフを描くためのライブラリです。

TanStackの中では、開発の動きがもっとも緩やかな部分です。実務でグラフが必要な場合は、この分野で選択肢が豊富な他のライブラリ（RechartsやVisXなど）と比較して判断するのが現実的です。

## TanStack Hotkeys

キーボードショートカットを扱うライブラリです。

`Ctrl+K`でコマンドパレットを開く、`j`と`k`で行を移動するといった操作を、宣言的に書けます。業務システムでキーボード操作を充実させたい場合に候補になります。

## TanStack Devtools

複数のTanStackライブラリの開発者ツールを、1つのパネルにまとめるライブラリです。

本編では`@tanstack/react-query-devtools`と`@tanstack/react-router-devtools`を個別に導入しました。これらを統合し、1か所で切り替えて見られるようにするものです。

まだ0系のため、本編では個別のDevtoolsを使いました。安定してくれば、こちらに寄せるほうが画面が散らかりません。

## TanStack Config

TanStackのライブラリ自身をビルド・公開するための設定集です。

アプリ開発者が使うものではありません。TanStackに近い形でライブラリを公開したい場合の参考になります。

## TanStack Intent

コーディングエージェント（AIによる開発支援ツール）に、ライブラリの正しい使い方を伝えるための仕組みです。

ライブラリの作者が、使い方を書いたMarkdown（Skill）をnpmパッケージに同梱します。利用する側は`npx @tanstack/intent@latest install`を実行し、それをエージェントの設定ファイルへ取り込みます。Skillはパッケージのバージョンと一緒に更新されるので、依存を上げれば説明も新しくなります。

TanStack専用の仕組みではありません。同じ形式に沿えば、どのnpmパッケージの作者でも使えます。エージェントが古いAPIのコードを書いてしまう問題への対策として用意されたものです。

本書で見てきたとおり、TanStackはバージョン間の変化が大きいライブラリ群です。AIの学習データに古い書き方が多く含まれている以上、こうした補助の仕組みには意味があります。

## 採用を判断するときに

新しいライブラリを検討するときの確認事項を挙げます。

1. メジャーバージョンが1以上か
2. 公式ドキュメントに「beta」「experimental」の記載がないか
3. 直近の更新頻度と、破壊的変更の頻度
4. 自分の用途が、そのライブラリの中心的な用途と重なっているか
5. 使わない場合、自分で書くとどれくらいの規模になるか

5つめが実際の判断を左右します。デバウンスを1か所で使うだけなら`setTimeout`で足ります。10か所で使い、キューやレート制限も必要になるなら、ライブラリに寄せる価値が出てきます。
