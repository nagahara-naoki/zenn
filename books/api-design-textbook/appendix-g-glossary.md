title: "用語集"

本書で使う用語を、API設計の文脈に合わせてまとめます。

## 英数字の用語

**ABAC（Attribute-Based Access Control）**
主体、リソース、環境の属性を条件にする認可方式。所属テナント、リソースの状態、時刻などを判断材料にします。

**API（Application Programming Interface）**
ソフトウェア同士が機能やデータを利用するための境界。本書では主にHTTP上のWeb APIを扱います。

**APIキー**
呼び出し元のアプリやプロジェクトを識別する資格情報。通常、人の本人認証には使いません。

**Bearerトークン**
持っているだけで利用できるトークン。漏えいした第三者にも使われるため、TLS、短い有効期間、安全な保管が必要です。

**Cache-Control**
HTTP応答をどこへ、どのくらい保存し、いつ再検証するかを伝えるヘッダーです。

**CDN（Content Delivery Network）**
利用者に近い拠点からコンテンツを配信する仕組み。公開APIのキャッシュにも使われます。

**CloudEvents**
イベントの識別子、種類、発生元、時刻など、通知に共通する属性を定めた仕様です。

**CORS（Cross-Origin Resource Sharing）**
別オリジンの応答をブラウザー上のJavaScriptへ公開する条件を、HTTPヘッダーで制御する仕組みです。

**CRUD（Create, Read, Update, Delete）**
データの作成、取得、更新、削除という基本操作の分類。API設計では、公開や取消などの業務操作をCRUDへ無理に当てはめないことも重要です。

**CSRF（Cross-Site Request Forgery）**
ブラウザーが資格情報を自動送信する性質を悪用し、利用者が意図しない要求を送らせる攻撃です。

**Deprecation**
機能やAPIが非推奨になった時点を利用者へ知らせるHTTP応答ヘッダーです。

**DPoP（Demonstrating Proof of Possession）**
アクセストークンをクライアントの鍵へ結び付け、盗まれたトークンだけでは使えないようにする方式です。

**ETag**
HTTP表現の版を識別する値。キャッシュ再検証の`If-None-Match`や競合検出の`If-Match`と組み合わせます。

**HTTPメソッド**
要求の意味を示す`GET`、`POST`、`PUT`、`PATCH`、`DELETE`などの値です。

**JSON Merge Patch / JSON Patch**
JSONを部分更新する二つの形式。Merge Patchは更新後の形に近いJSONを、JSON Patchは追加・削除・置換などの操作列を送ります。

**JWT（JSON Web Token）**
クレームを持ち、署名や暗号化が可能なトークン形式。署名付きJWTの内容は通常、暗号化されていません。

**OAuth 2.0**
クライアントがリソースへ限定的なアクセス権を得るための認可フレームワークです。

**OpenAPI**
HTTP APIのパス、入力、応答、セキュリティ要件などを機械可読に記述する仕様です。

**OpenID Connect（OIDC）**
OAuth 2.0の上に本人認証を加える仕組み。IDトークンでログイン結果をクライアントへ伝えます。

**PKCE（Proof Key for Code Exchange）**
OAuthの認可要求とトークン交換を一時的な秘密で結び、認可コードの横取りを防ぐ仕組みです。

**Problem Details**
HTTP APIのエラーを`type`、`title`、`status`、`detail`、`instance`などで表す形式です。

**RBAC（Role-Based Access Control）**
管理者、編集者、閲覧者などの役割に権限を割り当てる認可方式です。

**ReBAC（Relationship-Based Access Control）**
所有者、所属メンバー、親子関係など、主体と対象の関係から認可する方式です。

**SDK（Software Development Kit）**
APIを特定の言語から呼び出しやすくするライブラリや開発用ツールのまとまりです。

**SLI（Service Level Indicator）**
成功率や応答時間など、利用者が受けるサービス品質を測る指標です。

**SLO（Service Level Objective）**
SLIに対して定める目標値。たとえば「予約作成の99.9%が成功する」のように表します。

**SSRF（Server-Side Request Forgery）**
攻撃者が指定したURLへサーバーをアクセスさせ、内部ネットワークなどへ到達する攻撃です。

**Sunset**
APIや機能の提供を終了する予定時点を知らせるHTTP応答ヘッダーです。

**URI（Uniform Resource Identifier）**
リソースを識別する文字列。URLはURIの一種です。

**Webhook**
出来事が起きたとき、提供者が購読者のHTTPエンドポイントへ通知を送る仕組みです。

## 日本語の用語

**安全なメソッド**
サーバー状態を変更する意図を持たないHTTPメソッド。`GET`、`HEAD`、`OPTIONS`、`TRACE`、`QUERY`が該当します。

**エラーバジェット**
SLOの範囲内で許容できる失敗量。残量に応じて、新機能の公開と信頼性改善の優先度を判断します。

**オフセットページネーション**
先頭から読み飛ばす件数と取得件数で、一覧のページを指定する方式です。

**カーソル**
一覧の前回位置を表す不透明な値。安定した並び順や検索条件と結び付けます。

**カーディナリティ**
メトリクスのラベル値に何種類の組み合わせがあるかを示す度合い。利用者IDなど種類が増え続ける値をラベルにすると、保存量と費用が急増します。

**回路遮断**
障害中の依存先を一時的に呼ばないことで、待ち時間と連鎖障害を抑える仕組みです。

**後方互換性**
提供者が変更しても、既存の利用者が従来どおり動作できる性質です。

**条件付きリクエスト**
`If-Match`や`If-None-Match`を使い、現在の表現や版を条件に実行するHTTP要求です。

**状態遷移**
リソースが、業務上許された状態から別の状態へ移ること。遷移条件、副作用、実行権限を伴います。

**ジッター**
再試行の待ち時間へ加えるランダムなずれ。多数のクライアントが同時に再送する事態を避けます。

**テナント**
SaaSでデータと権限を分離する組織や契約の単位です。

**トランザクショナルアウトボックス**
業務データの更新と、後で送るイベントの記録を同じDBトランザクションで保存する方法です。

**入力フィンガープリント**
正規化した入力から計算する識別値。冪等性キーが同じでも内容が異なる要求を見分けるために使います。

**認証**
呼び出し元が誰であるかを確かめることです。

**認可**
認証した主体が、対象のリソースへ要求した操作を実行してよいか判断することです。

**破壊的変更**
既存の正しいクライアントを動作不能にしたり、意味を変えたりする契約変更です。

**冪等**
同じ要求を複数回行っても、意図したサーバー上の効果が一回の場合と同じになる性質です。

**冪等性キー**
同じ操作の再送を識別し、予約作成などの二重処理を防ぐためのキーです。

**分散トレース**
一つの要求がサービスやDBを通る流れを、処理区間の記録をつないで追跡する仕組みです。一つ一つの処理区間をspanと呼びます。

**補償処理**
複数システムにまたがる処理が途中で失敗したとき、すでに完了した変更を取り消したり、打ち消す変更を加えたりする処理です。

**ランブック**
障害やアラートが発生したときの確認方法、緩和策、復旧手順をまとめた運用文書です。

**リソース**
API利用者が識別し、状態や関係を扱う対象。イベント、予約、公開処理などが該当します。

**リソース表現**
ある時点のリソースをJSONなどで表したもの。リソースそのものと、通信で受け渡す表現を区別します。

**レート制限**
一定時間内に受け付ける要求数を制限する仕組み。公平性を保ち、過負荷からサービスを守ります。

**ロードシェディング**
処理能力を超えそうなとき、優先度の低い要求を早めに拒否し、システム全体を守る制御です。
