title: "付録G：用語集"
---

本書で使う用語を、API設計の文脈に合わせてまとめます。

## A–C

**ABAC（Attribute-Based Access Control）**  
主体、リソース、環境の属性を条件にする認可方式。所属テナント、状態、時刻などを判断材料にします。

**API（Application Programming Interface）**  
ソフトウェア同士が機能やデータを利用するための境界。本書では主にHTTP上のWeb APIを扱います。

**APIキー**  
呼び出し元のアプリやプロジェクトを識別する資格情報。通常、人の本人認証だけには使いません。

**Bearerトークン**  
保持している主体が利用できるトークン。漏えいした第三者にも使われるため、TLS、短い有効期間、安全な保管が必要です。

**BOLA（Broken Object Level Authorization）**  
オブジェクトごとの認可不足。IDを差し替えて他人のリソースへアクセスできる問題です。

**Cache-Control**  
HTTP応答をどこへ、どのくらい保存し、いつ再検証するか伝えるヘッダーです。

**CDN（Content Delivery Network）**  
利用者に近い拠点でコンテンツを配信する仕組み。公開APIのキャッシュにも使われます。

**CloudEvents**  
イベントの識別子、種類、発生元、時刻などの共通属性を定める仕様です。

**CORS（Cross-Origin Resource Sharing）**  
ブラウザーが別オリジンの応答をJavaScriptへ公開する条件をHTTPヘッダーで制御する仕組みです。

**CSRF（Cross-Site Request Forgery）**  
ブラウザーが資格情報を自動送信する性質を悪用し、利用者の意図しない要求を送らせる攻撃です。

## D–H

**Deprecation**  
機能やAPIを非推奨として扱うこと。RFC 9745は非推奨時点を知らせるHTTP応答ヘッダーを定義しています。

**DPoP（Demonstrating Proof of Possession）**  
アクセストークンをクライアントの鍵へ結び付け、盗まれたトークン単体の悪用を抑える方式です。

**ETag**  
HTTP表現の版を識別する値。キャッシュ再検証の`If-None-Match`や競合検出の`If-Match`と組み合わせます。

**GraphQL**  
型付きスキーマに対し、クライアントが必要なフィールドを指定するAPIクエリ言語と実行方式です。

**gRPC**  
Protocol Buffersでサービスとメッセージを定義するRPCフレームワーク。内部サービス間通信やストリーミングで使われます。

**HTTPメソッド**  
要求の意味を示す`GET`、`POST`、`PUT`、`PATCH`、`DELETE`などのトークンです。

## I–O

**冪等（idempotent）**  
同じ要求を複数回行っても、意図したサーバー上の効果が一回と同じになる性質です。

**冪等性キー**  
非冪等な操作の再送を同一要求として識別し、二重処理を防ぐためのキーです。

**JWT（JSON Web Token）**  
署名や暗号化が可能な、クレームを持つトークン形式。署名付きJWTの内容は通常、誰でも読めます。

**カーソル**  
一覧の前回位置を表す不透明な値。安定した並び順、検索条件、有効期限と結び付けます。

**OAuth 2.0**  
クライアントがリソースへ限定的なアクセス権を得るための認可フレームワークです。

**OpenAPI**  
HTTP APIのパス、入力、応答、セキュリティ要件などを機械可読に記述する仕様です。

**OpenID Connect（OIDC）**  
OAuth 2.0上に本人認証を加える仕組み。IDトークンでログイン結果をクライアントへ伝えます。

**offsetページネーション**  
先頭から読み飛ばす件数と取得件数でページを指定する方式です。

## P–R

**PKCE（Proof Key for Code Exchange）**  
OAuth認可コードの横取りを防ぐため、認可要求とトークン交換を一時的な秘密で結ぶ仕組みです。

**Problem Details**  
HTTP APIのエラーを`type`、`title`、`status`、`detail`、`instance`などで表すRFC 9457の形式です。

**RBAC（Role-Based Access Control）**  
管理者、編集者、閲覧者などの役割に権限を割り当てる認可方式です。

**ReBAC（Relationship-Based Access Control）**  
所有者、所属メンバー、親子関係など、主体と対象の関係から認可する方式です。

**リソース**  
API利用者が識別し、状態や関係を扱う対象。イベント、予約、公開処理などが該当します。

**リソース表現**  
ある時点のリソースをJSONなどで表したもの。リソースそのものと表現を区別します。

## S–Z

**安全なメソッド（safe method）**  
サーバー状態を変更する意図を持たないHTTPメソッド。`GET`、`HEAD`、`OPTIONS`、`QUERY`などです。

**SLO（Service Level Objective）**  
可用性、遅延、鮮度など、利用者視点の信頼性指標に対する目標値です。

**SSRF（Server-Side Request Forgery）**  
攻撃者が指定したURLへサーバーをアクセスさせ、内部ネットワークやメタデータへ到達する攻撃です。

**Sunset**  
APIや機能の提供を終了する予定時点。RFC 8594は`Sunset`応答ヘッダーを定義しています。

**テナント**  
SaaSでデータと権限を分離する組織や契約単位です。

**トレース**  
一つの要求が複数サービスやDBを通る流れをspanの集合として追跡する観測信号です。

**URI（Uniform Resource Identifier）**  
リソースを識別する文字列。URLはURIの一種です。

**Webhook**  
出来事の発生時に、提供者が購読者のHTTPエンドポイントへ通知を送る仕組みです。

**WebSocket**  
一つの接続上で双方向にメッセージを送受信するプロトコルです。

**SSE（Server-Sent Events）**  
HTTP接続を通じて、サーバーからブラウザーへテキストイベントを連続送信する仕組みです。

## 日本語の設計用語

**後方互換性**  
提供者が変更しても、既存の利用者が従来どおり動作できる性質です。

**条件付きリクエスト**  
`If-Match`や`If-None-Match`など、現在の表現や版を条件に実行するHTTP要求です。

**状態遷移**  
リソースが業務上許された状態から別の状態へ移ること。遷移条件、副作用、実行権限を伴います。

**破壊的変更**  
既存の正しいクライアントを動作不能または意味的に不正にする契約変更です。

**分散トレース**  
サービス境界を越える要求へ同じトレース文脈を伝え、処理全体を追跡する仕組みです。
