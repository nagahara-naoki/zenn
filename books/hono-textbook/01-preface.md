本書は、Honoを使ってWeb APIを作りながら、HTTP、Web標準API、TypeScript、バリデーション、認証、テスト、マルチランタイムまでを順番に学ぶための教科書です。

Honoの使い方だけを短く知りたいなら、公式ドキュメントやサンプルコードを読むだけでも十分です。けれども、実際の開発では「ルートはどう分けるのか」「どこで入力値を検証するのか」「エラーの形はそろえるべきか」「テストしやすい構成にするにはどうするのか」といった判断が何度も出てきます。

本書では、そうした判断を避けずに扱います。ひとつのタスク管理APIを少しずつ育てながら、Honoの機能と、その背後にあるWeb API設計の考え方を結びつけて学びます。

## 本書で目指すもの

本書の目的は、HonoのAPIを暗記することではありません。Honoを使って、型安全で、読みやすく、テストしやすいWeb APIを設計できるようになることです。

そのために、次の3つを軸にして進めます。

- **Web標準を理解すること**: Honoは`Request`、`Response`、`Headers`、`URL`など、Web標準APIと相性のよいフレームワークです。Hono独自の記法だけでなく、HTTPとWeb標準の考え方から説明します。
- **型安全に作ること**: TypeScript、Zod、Hono RPC、Hono Clientを使い、サーバー側とクライアント側の型が離れていかない設計を扱います。
- **実務に近い形まで育てること**: CRUDだけで終わらせず、認証、認可、エラー設計、テスト、OpenAPI、ランタイムごとの境界まで扱います。

Honoは軽量なフレームワークです。だからこそ、何も考えずに書くと、すぐに自由すぎるコードになります。本書では、Honoの軽さを活かしながら、アプリケーションとして壊れにくい形に整えていきます。

## 対象読者

本書は、次のような読者を想定しています。

- Honoをこれから学び始める人
- ExpressやFastifyなどを使ったことがあり、Honoとの違いを知りたい人
- Cloudflare WorkersでWeb APIを作りたい人
- TypeScriptで型安全なAPIを作りたい人
- フロントエンド開発からバックエンド開発へ学習範囲を広げたい人
- APIの設計、認証、テスト、仕様化まで一通りつなげて学びたい人

Honoの経験は前提にしません。最初は`new Hono()`から始め、ルーティング、リクエスト、レスポンス、ミドルウェアへ順番に進みます。

ただし、TypeScriptとJavaScriptの基本文法は知っているものとして進めます。たとえば、変数、関数、オブジェクト、配列、`async` / `await`、npmによるパッケージ管理が分かっていれば読み進められます。

HTTP、データベース、認証については、本書の中で必要な範囲から説明します。最初から詳しく知っている必要はありません。

## 本書で作成するAPI

本書では、タスク管理APIを作ります。題材としては小さく見えますが、Web APIの基本を学ぶにはちょうどよい大きさです。

タスク管理APIには、次のような機能を持たせます。

- ユーザー登録とログイン
- JWTによる認証
- 自分のユーザー情報の取得
- タスクの作成、取得、更新、削除
- タスクの検索、絞り込み、並び替え、ページネーション
- ユーザーごとのデータ分離
- 所有者やロールに基づく認可
- 入力値のバリデーション
- 一貫したエラーレスポンス
- OpenAPIドキュメントの生成
- 自動テスト
- Hono RPCとOpenAPIによる型と仕様の共有
- ローカルでの統合テスト

単なるサンプルAPIではなく、実務の入口に立てる構成を目指します。もちろん、本書のコードをそのまま大規模サービスに持ち込めるわけではありません。けれども、実務で必要になる判断の土台は、この小さなAPIの中に十分に含められます。

## APIの全体像

最終的には、次のようなエンドポイントを持つAPIを作ります。

| 分類 | メソッド | パス | 役割 |
|---|---:|---|---|
| ヘルスチェック | GET | `/health` | APIが動作しているか確認する |
| 認証 | POST | `/auth/register` | ユーザーを登録する |
| 認証 | POST | `/auth/login` | ログインしてトークンを取得する |
| ユーザー | GET | `/me` | ログイン中のユーザー情報を取得する |
| タスク | GET | `/tasks` | タスク一覧を取得する |
| タスク | POST | `/tasks` | タスクを作成する |
| タスク | GET | `/tasks/:id` | タスクの詳細を取得する |
| タスク | PATCH | `/tasks/:id` | タスクを更新する |
| タスク | DELETE | `/tasks/:id` | タスクを削除する |
| ドキュメント | GET | `/openapi.json` | OpenAPI仕様を返す |
| ドキュメント | GET | `/docs` | APIドキュメントを表示する |

最初からこのすべてを作るわけではありません。序盤では、インメモリのデータを使って小さなルートを作ります。中盤でD1に保存先を移し、終盤で認証、テスト、ドキュメント、ランタイムごとの考え方を加えていきます。

この進め方にしているのは、API開発では「動くものを作ること」と「壊れにくく育てること」の両方が必要だからです。最初から理想的な構成を目指すと、手を動かす前に疲れてしまいます。逆に、動けばよいという感覚だけで進めると、あとから直しにくくなります。本書では、その間を一歩ずつ進みます。

## 主な実行環境

本書のサンプルアプリケーションでは、主な実行環境としてCloudflare Workersを使います。データベースにはCloudflare D1を使います。

Cloudflare Workersを中心にする理由は、Honoの特徴を理解しやすいからです。HonoはWeb標準APIを土台にしているため、`Request`を受け取り、`Response`を返すという流れが見えやすくなります。また、Workersでは`fetch`、`Request`、`Response`といったWeb標準の感覚がそのまま重要になります。

一方で、HonoはCloudflare Workers専用のフレームワークではありません。Node.js、Bun、Denoなど、複数のJavaScriptランタイムで動かせます。本書では、まずWorkersで考え方を身につけ、後半でマルチランタイムの考え方にも触れます。

:::message
本書ではCloudflare Workersを主な実行環境として使いますが、Honoの基本は特定の環境に閉じません。環境固有の話と、Honoそのものの話を分けながら説明します。
:::

## 学習用コードと実務用コード

本書では、学習のためにあえて小さく書く場面があります。たとえば、最初のうちは配列にタスクを保存します。これは、本番でそのまま使うためではありません。Honoのルーティング、リクエストの読み取り、レスポンスの返し方を先に理解するためです。

その後、章が進むにつれて構成を変えていきます。

- インメモリの配列からD1へ移す
- Handlerに寄っていた処理をServiceやRepositoryへ分ける
- 手書きの入力チェックをZodによるバリデーションへ移す
- その場しのぎのエラーを共通のエラーレスポンスへそろえる
- 動作確認用の手作業を自動テストへ置き換える

この流れを追うことで、「最初から完成形だけを見る」よりも、なぜその設計が必要になるのかを理解しやすくなります。

実務では、最初からすべての抽象化を入れる必要はありません。けれども、どこで抽象化が必要になるのかを知らないまま進めると、コードの重さに気づくのが遅れます。本書では、コードが少し窮屈になってきたところで、次の設計に進みます。

## コード例の読み方

本書のコード例では、必要に応じてファイル名を付けます。

```ts:src/index.ts
import { Hono } from 'hono';

const app = new Hono();

app.get('/health', (c) => {
  return c.json({ ok: true });
});

export default app;
```

コードブロックの先頭に`ts:src/index.ts`のような表記がある場合は、`src/index.ts`に書くTypeScriptコードという意味です。

一部のコードは、説明のために短くしています。実際の完成形では、エラー処理、型定義、バリデーション、テストなどを加えます。短いコードを見たときは、「この時点で学ぶための形」と考えてください。

また、章が進むにつれて、前の章で書いたコードを書き換えることがあります。これは失敗ではありません。API開発では、理解が進むほど構成も変わります。本書では、その変化も学習の一部として扱います。

## 公式ドキュメントとの付き合い方

本書は、公式ドキュメントの代わりではありません。Honoの全APIを網羅するリファレンスではなく、APIを作りながら判断の流れを学ぶための本です。

細かいメソッドやオプションを確認したいときは、公式ドキュメントもあわせて参照してください。特に、次の3種類の情報は公式ドキュメントを見る習慣をつけるとよいです。

- HonoのAPI仕様
- Cloudflare WorkersやD1の環境固有の仕様
- 使用するライブラリの最新のインストール手順やオプション

技術書では、読みやすさのために説明の順番を組み替えることがあります。一方、公式ドキュメントは最新の仕様や詳細な選択肢を確認する場所です。両方を行き来できるようになると、学習の速度が上がります。
